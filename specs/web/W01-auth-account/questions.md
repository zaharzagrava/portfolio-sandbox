# Open Decisions for W01 (answered unattended)

Format: `[TAG] question → default taken → why`. BREAKING first, then CONTRACT, then LOCAL. The human reviews BREAKING and CONTRACT lines first. Decision policy: most production-grade option the Interview-Prep notes and the constitution support; a `[BREAKING]` line tells the implementation to update existing tests and callers.

## BREAKING (changes behaviour or a UI/API contract that exists today)

- [BREAKING] Browser session = access token in JS memory plus a refresh cookie on the core API (`lib/api/client.ts:13-81`, `hooks/use-auth.tsx:41-59`) → the S48 token handler: opaque HttpOnly `__Host-bff-session` + readable `__Host-bff-csrf`, `GET /api/bff/session` as the only session source; `setAccessToken`, `getAccessToken`, the axios refresh interceptor and the refresh-on-mount effect are deleted → notes 05/02 §3 (BFF is the recommended store), constitution VI.2, S48 FR-040.
- [BREAKING] `register()` signs the visitor in and goes home (`use-auth.tsx:98-102`, `register/page.tsx:54-57`) → registration ends at `/login?notice=registered`; no automatic sign-in → S01 answers `202` identically for new and existing addresses; an automatic sign-in attempt would succeed only for new ones and defeat that (constitution V.4). `tests/helpers.ts register()` becomes register + sign in through the UI (same return value), so other journeys keep working.
- [BREAKING] Register form has "Full name" (not accepted by the API, unknown fields are `400`), password minimum 8 → remove the name field; password 12–128 characters; keep Confirm password and Terms as interface-only checks → S01 AS-04/AS-05 and FR-005; the name was silently dropped today.
- [BREAKING] Login form has a dead "Remember me" checkbox and a dead GitHub button; the Google button does nothing → remove "Remember me" and GitHub; Google renders only when the providers list offers it and C-OIDC holds → controls that do nothing mislead (lifetimes are fixed by S48; the backend has no GitHub provider).
- [BREAKING] Query parameter `returnUrl` and validator `safeReturnUrl` (`lib/safe-return-url.ts`, used by login, MFA, checkout, chat) → `returnTo` with the S02 FR-045 rules (one leading `/`, ≤ 512 chars, no control characters or backslash, checked before and after one round of percent-decoding, repeated parameter ignored) → S02's callback redirects use `returnTo`; the old validator accepts `/%2F%2Fevil.example`. Callers: `app/checkout/page.tsx:41`, `app/chat/chat-view.tsx:47`, `tests/helpers.ts:29`; `components/dashboard/dashboard-shell.tsx:35-39` redirects to `/login` without any return path today.
- [BREAKING] MFA step lives at `/mfa?token=<mfaToken>&returnUrl=…` with six one-digit inputs, auto-submit on the sixth digit and a dead "Use recovery code instead" button (`mfa-form.tsx`) → `/login/mfa?returnTo=…`, challenge held by the BFF (HttpOnly cookie), one "Authentication code" field, working recovery-code mode, no auto-submit → a challenge in a URL leaks through history and `Referer` (S02 gaps C2); auto-submit burns a counted attempt on every typo (S02 AS-16, AS-17); six inputs break paste, autofill and screen readers.
- [BREAKING] Forgot-password posts to `/api/auth/forgot-password`, swallows every error (including no network) and always shows "Check your email" (`forgot-password/page.tsx:36-45`), and there is no reset page → posts to `/api/auth/password-reset/request`; the confirmation appears only after `202`; errors are shown; new `/reset-password` page → S01 FR-080..FR-084; showing "sent" when nothing was sent is wrong.
- [BREAKING] Errors are toasts that print server `detail` text (`apiErrorMessage`, `login-form.tsx:60`, `mfa-form.tsx:39`) → inline `role="alert"` alerts built only from the problem `code`/`status` through a fixed copy catalogue, `Retry-After` wait text and `requestId` reference for 5xx; server `detail`/`title` are never rendered → constitution V.3 (stable codes), a11y (toasts vanish and are not focus-managed), no leakage of upstream text.
- [BREAKING] Navbar: account button's accessible name is its initials (`tests/auth.spec.ts:8` finds it by "UI"), no Log in / Sign up on mobile (`navbar.tsx:164` is `hidden md:flex`, the sheet has no auth entries), menu has no account page → accessible name "Account menu", Log in / Sign up reachable at every width, new entry "Account & security"; `auth.spec.ts` locator changes → WCAG 2.5.3/4.1.2 and a mobile visitor could not sign in at all.
- [BREAKING] Sign-out ignores failure and always clears local state, then goes to `/login` (`use-auth.tsx:84-96`) → sign-out through `POST /api/bff/session/logout` with CSRF; on failure the member stays signed in with a retry toast; success goes to `/login?notice=signed_out` → showing "signed out" while the server session lives is a security lie.
- [BREAKING] `useAuth()` exposes `login`, `register`, `verifyMfa`, `logout`, `refreshSession` and a mutable `user` of type `any`-fed `User` (`use-auth.tsx:19-30`) → `useAuth()` is read-only `{user, status, isAuthenticated, isLoading}`; actions move to `useLogin`, `useVerifyMfa`, `useLogout`, `useRefreshSession`; roles include `MODERATOR` → server data (the session) belongs to TanStack Query (VI.4), not a hand-rolled context with `useState`. Callers: `navbar.tsx`, `dashboard-shell.tsx`, `app/dashboard/seller/view.tsx:18,30`.
- [BREAKING] `queryKeys.auth.user` → `queryKeys.auth.session()` plus `mfaStatus()`, `sessions()`, `identities()`, `oidcProviders()` → one key per kind of server data (VI.4); `auth.user` has no users.
- [BREAKING] `register` and `forgot-password` pages are `'use client'` pages (`register/page.tsx:1`, `forgot-password/page.tsx:1`); the whole auth layout depends on client hooks → pages and layouts are Server Components; forms are client leaves (`register-form.tsx`, `forgot-password-form.tsx`, `reset-password-form.tsx`) → constitution VI.1, P0903.
- [BREAKING] The shared client uses `NEXT_PUBLIC_API_URL || 'http://localhost:3000'` as an absolute base URL, reads `__Host-csrf` and calls `/api/auth/refresh` (`client.ts:3,26-34,70-81`) → relative same-origin URLs only; CSRF from `__Host-bff-csrf` into `X-CSRF-Token`; no browser refresh → S48 FR-043, constitution VI.2 (`__Host-` cookies are valid only on one origin).
- [BREAKING] GraphQL client and SSE reader send `Authorization: Bearer <memory token>` (`lib/api/graphql.ts:20-23`, `lib/api/sse-reader.ts:51-59`) → cookie session plus `X-CSRF-Token` on `POST` → S48 questions (BREAKING, W01 follow-up), VI.2.
- [BREAKING] Notices after auth events are toasts ("Successfully logged in!", "Registration successful!") → one persistent banner chosen by `?notice=` on the destination page, and a polite status announcement during submission; the success toast is dropped → toasts are not reliably announced and disappear before being read.
- [BREAKING] `/mfa` route removed (no redirect) → no external clients; the new route is `/login/mfa`.

## CONTRACT (something another capability must provide or consume)

- [CONTRACT] C-FWD: S48 — how do browser REST calls get an identity once no token is in JS (cart merge, checkout, orders, `/api/auth/sessions`, `/api/auth/mfa/*`, chat, assistant)? → S48 forwards every same-origin `/api/*` request of a BFF session with `Authorization: Bearer` attached server-side, `Cookie` stripped, CSRF + origin on non-`GET`, responses passed through; `next.config.ts` rewrites route `/api/*` through the BFF → S48's spec covers only the page, GraphQL and session endpoints; without forwarding, removing the memory token breaks every authenticated call. X.8.3 allows "session and token handling, plus propagation of the auth context" and forbids anything beyond forwarding unchanged to one owning endpoint.
- [CONTRACT] C-REFRESH: S48 — how does the UI see a role change (opening a shop makes the user a seller; today `refreshSession()` re-mints the token, `seller/view.tsx:30`)? → new `POST /api/bff/session/refresh` (CSRF) returning `{user, expiresAt}` after a forced identity refresh → S01 AS-28 says a role takes effect at the next refresh; the BFF owns refresh (single flight) so the browser cannot ask S01 directly.
- [CONTRACT] C-OIDC: S02 + S48 — S02's callback sets `__Host-access`/`__Host-refresh`, but the web session is the BFF session; a Google user would be signed in at the API and anonymous in the UI → default: S48 `GET /api/bff/session` (and C-FWD) also accept an S02 cookie session by resolving it server-side, or S02's callback creates the BFF session; the federated second step is completed by `POST /api/bff/session/mfa`; the Google UI is built but gated by `AUTH_OIDC_ENABLED` until then → S48 questions already flagged this for W01; shipping a Google button that "works" but leaves the navbar signed out is worse than none.
- [CONTRACT] D1: S01 — S01's assumption "the web client logs in automatically after registration" → W01 does not (see BREAKING above); S01's spec text should drop the assumption → automatic sign-in reveals membership.
- [CONTRACT] D2: S28 — reset link `<front>/reset-password?token=<resetToken>` (S28 catalogue row `security.password_reset`, S28 AS-09) → `<front>/reset-password#token=<resetToken>`; the page removes the fragment on load → a query token reaches access logs, CDN logs and `Referer`; a fragment is never sent to a server.
- [CONTRACT] D3: S02 — link-flow failures redirect to `/login?error=<code>` (S02 FR-048) even though the user is signed in → W01 redirects a signed-in visitor on `/login?error=<code>` to `/account/security?tab=methods&error=<code>`; S02 may later redirect there directly → no change needed in S02 today.
- [CONTRACT] Problem body shape for `validation_failed`: S01 FR-009 says "per-field errors", V.3 lists no field list → assumed `errors: {field: string, message: string}[]` on the problem body (`problemSchema` in `packages/contracts`); when absent the form shows "Check the highlighted fields." as the form-level message → W01 needs a stable shape to place messages under fields.
- [CONTRACT] `packages/contracts` has no `src/` today (`packages/contracts` holds `moon.yml` and `package.json` only) → backend capabilities (S01, S02, S48, S54) create the schemas listed under Requires; W01 imports them and hand-writes no duplicate types → constitution V.2; until then W01's `lib/api` modules define zod schemas locally with the same names so the swap is an import change.
- [CONTRACT] W07: the navbar frame embeds `<AccountSlot/>` inside Suspense and `<MobileAccountEntries/>` in the hamburger sheet; W07 adds `Referrer-Policy: no-referrer` for `/reset-password` and the `/account` → `/account/security` redirect in `next.config.ts` → W07 owns the frame and the shared headers file.
- [CONTRACT] W03, W04, W05, W06: switch to `returnTo`, read-only `useAuth()`, `loginHref()` and `requireServerSession()`; seller view calls `useRefreshSession()` → their pages are the callers of the BREAKING changes above; the admin layout has no guard at all (`app/admin/layout.tsx`) and is W06's to fix (API already refuses non-admins).
- [CONTRACT] W03/S10: W01 triggers `mergeGuestCart()` once after each sign-in and ignores its failure → merge ownership stays with S10/W03 (idempotent, race-safe per S10 AS-06).
- [CONTRACT] S28/ops test tooling: UI journeys need to read the reset link sent to a test address → the development stack's e-mail provider keeps sent messages readable over HTTP (a local mail catcher or the S28 fake provider), and `tests/helpers.ts getResetLink(email)` polls it → without it the reset journey cannot run (VII.7 forbids stubbing the backend in journeys).
