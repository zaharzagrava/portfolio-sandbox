- [BREAKING] What does "Place order" send and how is the key kept? → body `{expectedTotalMinor}`, one key per attempt kept in the tab's session storage (24 h, deleted on success/final outcome/sign-out), rotated per AS-19; today body `{}` and a key fixed per page mount (`app/checkout/page.tsx:36,47`) → S10 FR-012/FR-014/AS-20: after an `out_of_stock` the same key replays the same failure, and a reload today loses the key and can double-order; this is P0414 at the browser.
- [BREAKING] Who calls `POST /checkout`? → a server-side order function (server action) that attaches the session and, when the schema has it, the `__Host-ref` code, returning a typed result; today the browser calls it through the shared axios client (`app/checkout/page.tsx:47`) → W02's contract says W03 reads `getRefCode()` on the server (the cookie is HttpOnly); one server hop also keeps problem bodies typed instead of thrown.
- [BREAKING] Is there a pay step? → yes: `/checkout/pay/{orderId}` with hosted card fields, 3-D Secure and live payment status; today "Place Order" ends at a `RESERVED` order and the success page says "Order Confirmed!" with no payment at all (`app/checkout/success/page.tsx:25`) → S10 says only the provider signal marks an order paid and S13 names the pay step as W03's; without it no order can be paid from the UI.

- [BREAKING] Where does order history live? → `/orders` and `/orders/{orderId}` outside the dashboard, `/dashboard/orders` permanently redirects; history is a keyset page `{items, nextCursor}` with `cursor` in the URL; today it is a bare-array list inside the seller dashboard shell (`app/dashboard/orders/view.tsx`, `lib/api/orders.ts:33-35`) → S28's notification links point at `/orders/<id>` (S28 AS-01), S10 AS-59 returns pages, VI.4 puts the cursor in the URL; W04 owns the dashboard and loses the buyer's table (`[CONTRACT]` below).
- [BREAKING] Cancel rules and confirmation → only `RESERVED` orders show **Cancel**, behind a confirmation dialog; today `PENDING` is also cancellable and the click cancels at once (`lib/api/orders.ts:19`, `components/dashboard/orders-table.tsx:38-52`) → S10 FR-045 allows only `RESERVED` (a `PENDING` cancel would be a `409`), and cancelling releases stock, so it is confirmed.
- [BREAKING] Quantity controls → **−** is disabled at 1 and removal is the explicit **Remove** with an **Undo** toast; **+** is bounded by 20 only; today **−** at 1 removes the line and **+** is disabled by the product's exact `quantity` (`app/cart/page.tsx:90`) → exact stock must not be exposed (W02's public product shape has no `quantity`), an accidental removal must be reversible, and checkout is the stock authority (S10 AS-32).
- [BREAKING] Cart query ownership → `useCart` loses its `user?.id ??
