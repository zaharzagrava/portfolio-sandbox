# Test Plan: W06 — Admin feature-flag console (`packages/web`)

Constitution VII.8 table: one row per acceptance scenario in [`spec.md`](spec.md) (66 scenarios, AS-01 to AS-66), each proven at the lowest layer that can prove it. A dash means the layer does not test that scenario. Where a row names more than one layer, the cell states what that layer proves; no part is proven twice. "Proven by backend spec" names the S38 scenario that owns the rule; the UI never re-tests it (VII.7).

## Layers and conventions

- **UI journey (Playwright, happy path only)**: `packages/web/tests/*.spec.ts` against the real local dev stack (`moon run dev-monolith`, web on 3000), seeded admin (`SEED.admin`), a unique flag key per test (`e2e-flag-<random>`), web-first assertions, no fixed sleeps, roles and labels instead of test ids. A journey never forces a failure and never asserts a backend rule. Two files, each with a top-level `describe` naming its feature: `admin-flags.spec.ts` (`Admin feature flags`) and `admin-access.spec.ts` (`Admin console access`). Existing `admin-flags.spec.ts` is rewritten (`questions.md`).
- **UI unit (Vitest + React Testing Library)**: `*.test.tsx` / `*.test.ts` next to the code. Queries by role and label, `@testing-library/user-event`, MSW at the network boundary with problem+json fixtures parsed by the `packages/contracts` schemas, `jsdom`, fake timers for countdowns, a stub for `navigator.clipboard`. They cover UI-only logic, states, copy, focus and accessibility. No markup snapshots. Async Server Components are not rendered in Vitest: their decision logic is a pure function (`adminAccess`, `parseListParams`, …) tested directly, and the real page is covered by a journey.
- **Visual (Playwright screenshot)**: `packages/web/tests/visual/admin-*.spec.ts`, projects `chromium` (1280 × 800) and `mobile` (390 × 844). The backend is stubbed with `page.route` (layout only), animations disabled, an axe scan (serious or critical = 0) runs on each state, screenshots are compared to committed baselines.
- **Static gates** (VII.1): `tsc --noEmit`, ESLint, `next build` (Cache Components validation, no `instant = false`), and the architecture test `lib/architecture.test.ts` shared with W03/W04 (reads the source: no `fetch`/`axios`/`EventSource` in components or hooks, query keys only from `lib/query-keys.ts`, no new Context or store, no `use cache` around per-user data, no token or credential storage, no `dangerouslySetInnerHTML`, no `console.*` of flag bodies, no array index as `key`).
- **Fallback and degradation paths (VII.9)** each have a forcing test: list failure and failed background refetch (AS-07), lost save response (AS-27), conflict (AS-28), killed-while-editing (AS-35), rate limit countdown (AS-50), offline (AS-52).
- **Edge cases** (spec "Edge Cases") are each a scenario below: concurrent save (AS-28), kill racing a save (AS-35), replayed save (AS-27), repeated kill (AS-38), editor under a changing flag (AS-28 unit: draft keeps its basis version), 20 variants and 50 rules (AS-61 visual), referenced variant removed (AS-19), unknown rule feature (AS-21 unit), expired-but-evaluating copy (AS-45), long text (AS-60 visual), non-admin mid-session (AS-48).
- Helpers: `createFlag(page, key, options?)`, `flagPath(key, tab?)`, `adminLogin(page)` in `tests/helpers.ts`; `login()` moves to `returnTo` (W01). Everything else is in `gaps.md`.
