# QA report: discover
Tried: doctor-live at start and end (healthy); API probes of search (typos, empty/blank/101-char/special-character queries, limit/minRating/sort/cursor errors, sorts, paging 8/8/5, filters, mismatched cursor), suggest, trending, recommendations; DB comparison (21 ACTIVE products = 21 search results); browser at 1280x800 and 390x844 (home, /search variants, junk URL params, semantic, category, inverted price, unknown/invalid product, typing in the search box, empty and 300-char submit, sort, back/forward/reload, price filter, opening a result, phone filter sheet); outbox, all 20 DLQs, /health/ready.
## Defects
DEFECT D1 CONFIRMED high: Result click record is always rejected with 400 (searchId is "unknown_property")
- oracle: browser console error (failed request) and W02.R-15
- steps:
  1. Open http://localhost:3000/search?q=desk
  2. Click the first result card
  3. Watch the network call `POST /api/search/clicks`
- expected: one click record `{searchId, productId, position}` accepted (S32: answers 202)
- actual: the storefront sends `{"searchId":"v1.…","productId":"…","position":0}`, answered `400 validation_failed` with errors `[{field:"searchId",code:"unknown_property"},{field:"query",code:"maxLength"},{field:"query",code:"isString"}]`. The API wants `query` instead of `searchId`. A body `{query:"desk",productId,position}` gets 202 on both :8000 and :3000. So no click ever reaches the click log, and click-through / MRR reports can never fill.
- evidence: scripts/ui-click2.js (prints `CLICK 400 …`), scripts/click-api.js (400 for searchId body, 202 for query body, on API and storefront proxy); browser console "Failed to load resource … 400 … /api/search/clicks"

DEFECT D2 CONFIRMED high: every search page request calls the API with `facets=true`, which the API rejects with 422 (no facet panel is ever shown)
- oracle: browser console error; W02.R-10 / B-08 (facet counts) cannot happen
- steps:
  1. Open http://localhost:3000/search (also /search?q=desk, and after changing sort or applying a price filter)
  2. Watch the console / network: `GET /api/products/search?facets=true&limit=24`
- expected: 200 with facet counts, and a facets section in the filter panel
- actual: `422 unsupported_combination` (parameters: ["facets"]) on every search view (the page still lists products, so the server render seems to degrade quietly). The filter panel has only Price, Rating and "In stock only"; no category or brand counts. Directly: `GET /api/products/search?facets=true` gives 422.
- evidence: console lines "Failed to load resource: 422 … /api/products/search?q=desk&sort=price-desc&facets=true&limit=24" (scripts/ui-interact.js); scripts/api-probe2.js section --filters (`facets=true 422`, `semantic=true 422`). Note: facets are in S32 Known gaps (untested), but the storefront asks for them and gets an error on every page, which is a wiring fault and not a missing feature.

DEFECT D3 SUSPICIOUS low: anonymous visitors get a 401 console error on every page
- oracle: SUSPICIOUS (judgment). A browser console error appears on each page for a signed-out visitor.
- steps: open http://localhost:3000/ or /search signed out; console shows "Failed to load resource: 401 … /api/bff/session"
- expected: a signed-out check answers quietly (for example 200 with no user)
- actual: `GET /api/bff/session` answers 401 `unauthenticated` on every page view; it may be intended, but it fills the console of every visitor
- evidence: scripts/ui-click.js output (`RESP 401 GET /api/bff/session`)
