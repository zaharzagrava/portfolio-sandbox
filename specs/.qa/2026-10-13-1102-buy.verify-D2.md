- The answer was `400` problem+json: `code: validation_failed`, `errors: [{field:searchId, code:unknown_property}, {field:query, code:maxLength}, {field:query, code:isString}]`. The requestIds were 01a13488-5883-... (run 1) and 01a13488-6a0f-... (run 2).

- The navigation to the product page still worked (URL /products/01a1...), so the user sees nothing, but the click event is lost.

## Not noise
- The request is a real production-path call from the app, not the Next.js dev overlay, hot reload or the dev double effect. It happens once per click and fails every time.
- Unrelated console noise also appears, and I did not count it toward this defect: many CSP `style-src` inline-style violations, and a 401 on page load for an anonymous visitor.
- Not a documented gap: no spec page says click recording is unbuilt or that this 400 is expected.
- The contract mismatch is clear from the API's own answer. The web sends `searchId` and the API rejects it as an unknown property. The API wants a string `query`, and it reports both `isString` and `maxLength` for it, so the field is missing.
