# Open Decisions for S08 (answered unattended)

Format: `[TAG] question → default taken → why`. BREAKING first, then CONTRACT, then LOCAL. The human reviews BREAKING and CONTRACT lines first. Decision policy: most production-grade option the Interview-Prep notes and the constitution support; no external clients to keep compatible, so correctness, security, observability and clean domain boundaries win over preserving today's behaviour.

## BREAKING (changes behaviour or an API/UI contract that exists today)

- [BREAKING] Product writes (today raw `INSERT`/`UPDATE "Product"` and a raw `{productId}` outbox row on `products.events`, `integration-sync.service.ts:126-141`, `:186`) → only `upsertFromExternal(shopId, items, 'shopify'|'woocommerce')` and `applyStockDelta`; this domain writes no product row and no product event → IX.4, IX.7 R1, S05 FR-030/FR-032, domain-map ("never writes `Product` directly").
- [BREAKING] Stock sync (today inbound sets `quantity = :stock` absolutely and outbound compares one combined hash; a sale between pull and apply is overwritten) → three-way merge on a recorded common base (`syncedStock`): inbound as a delta via `applyStockDelta` with a deterministic `operationId`, outbound as a conditional absolute write, negative or out-of-range merges go to a conflict queue → note 06/02 §3.2–3.3 (compare before update, field-level merge, manual queue for what cannot be merged), P0612 "conflict queue" which the code lacks.
- [BREAKING] Outbound push trigger (today the projector reads `{productId}` from `products.events` and joins the product table, `integration-sync.service.ts:152-160`) → consumes S05's versioned `catalog.product_*` events and reads the quantity from the event copy; version-guarded, coalesced, sandbox and unlinked events ignored → IX.7 R3/IX.8, IV.5.
- [BREAKING] Money (today `Math.round(Number(price) * 100)`, `shopify.provider.ts:63`) → decimal-string parser with the platform currency's exponent, no floats; `12.999`, exponent notation, negatives are rejected → III.8; the old code mis-rounds `1.005` style values and accepts `1e3`.
- [BREAKING] Variants (today only `variants[0]` is mapped, stock of other variants is silently ignored, `shopify.provider.ts:58`) → one variant = one product, `externalId = <productId>:<variantId>`, stock per variant → stock is a per-variant quantity at the provider; the old mapping oversells every non-first variant. - [BREAKING] Connect (today `POST /shops/:shopId/integrations {provider, externalShop, credentials}` accepts raw tokens and a seller-chosen webhook secret, permission `shop.manage`, provider `fake` allowed outside production) → Shopify through OAuth install + callback, WooCommerce through verified keys with a platform-generated webhook secret, permission `integrations.manage` (S03 FR-020), `fake` removed from DTO, migration check and production wiring → note 05/02 §9, SD-36 ("OAuth tokens with refresh in … encrypted column"); sellers should not paste admin tokens, and a test-only provider in the public contract is an attack surface.

- [BREAKING] Quarantine (today one new row on **every** re-read of a bad item, i.e. every 5 minutes forever; no way to review, retry or dismiss; reasons are free text) → one open row per item with `occurrences`, reason codes, auto-resolve when fixed, list/retry/dismiss routes, 90-day expiry; a run halts after 1,000 quarantined items → "quarantine + alert, not crash" (SD-36) needs a bounded, reviewable table; without dedupe it is a storage leak.
- [BREAKING] Reconciliation (today inline in one scheduled job for all integrations, deletes inferred from a listing that may be partial, local stock zeroed with a raw `UPDATE "Product"`, the "report" is a quarantine row) → one `reconcile` message per integration on the backfill queue, deletion confirmed by a direct read, mass-deletion guard (≥10 links and >20%), classified immutable reports, drift fixed only when one side differs from the base → note 06/02 §3.5, §5 ("auto-correct only when rules are clear", period close: never mutate a closed period).

## LOCAL (affects only this capability's internals)

- [LOCAL] One `externalSku` per variant `<provider>:<integrationId>:<externalId>` (≤ 128) → never collides with CSV SKUs or a second store; matching an existing CSV product by the seller's own SKU is a later feature.
- [LOCAL] Untracked-inventory variants are quarantined (`inventory_not_tracked`) rather than imported with fake stock → the marketplace cannot sell "unlimited" safely.
- [LOCAL] Draft and archived provider products are not imported; linked ones lose stock (zeroed) but are not archived locally → archiving needs an actor and is the seller's call.
- [LOCAL] Deleted-at-provider = zero stock + link state; no archive/delete of the marketplace product.
- [LOCAL] Local edits of provider-owned fields are overwritten at the provider's next change; no conflict is raised → single system of record per field (note 06/02 §3.3 "usually the best answer").
- [LOCAL] Conflict resolution = seller changes stock through the normal route and dismisses; no resolve-with-value route → avoids a second stock writer and a cross-domain saga.
- [LOCAL] Outbound write is a conditional absolute set (Shopify `changeFromQuantity` / compare quantity; WooCommerce read-then-write in a short window) → the SD note says "set, not adjust"; the precondition prevents overwriting a concurrent provider sale.
- [LOCAL] Webhook stale rule only where the provider sends a timestamp (Shopify `X-Shopify-Triggered-At`); WooCommerce relies on delivery-ID dedupe → V.8 needs a timestamp that WooCommerce does not send. Risk: Shopify may disable subscriptions after repeated non-2xx; the scheduled pull makes a 401 on a stale replay harmless, and Shopify retries keep the original timestamp.
- [LOCAL] `PAUSED` and `NEEDS_REAUTH` integrations acknowledge webhooks without recording them; resume enqueues an incremental pull plus a reconcile → the merge makes the catch-up exact.
- [LOCAL] Raw payload kept per link, capped at 256 KiB (else quarantined `payload_too_large`) → "unknown fields go into raw jsonb" (06/02 §4) without unbounded rows.
- [LOCAL] Run budget 4 min incremental, 12 min backfill, or 40 pages; visibility timeouts 300/900 s stay → a run must end before its message becomes visible again.
- [LOCAL] Circuit breaker state lives on the integration row (counter + `breakerOpenUntil`), not in Redis → it must survive a Redis flush and be visible in the status route.
- [LOCAL] Per-integration lease on the cursor row (holder, expiry, fence), 5 min renewed each 60 s → same mechanism as S07's job lease; advisory locks would not carry a fence.
- [LOCAL] Webhook receipts, runs, reports and resolved items have the retention of AS-76; open items older than 90 days are closed, not deleted → "never delete unseen".
- [LOCAL] Validation failures are `400 validation_failed` (S03, S05, S06 use 400; S07 uses 422) → one status per class across the platform is S54's concern; this spec follows the majority.
- [LOCAL] Provider API version is pinned in configuration and validated at startup; upgrading is a config change plus adapter contract tests → quarterly Shopify deprecations.
- [LOCAL] Shopify stock location = the primary location at connect time; changing it needs a reconnect → keeps one stock number per variant.
- [LOCAL] `Idempotency-Key` is not required on any route of this capability (V.6 covers order/payment/booking/bid/ledger creation only).
- [LOCAL] Install state stores a digest, not the state, TTL 10 min, consumed by a conditional update → single use under concurrency.
- [LOCAL] On-demand `reconcile` and backfill `sync` are rate-limited per integration (1 per hour) → protect the provider budget.
