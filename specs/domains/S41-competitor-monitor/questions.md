# Questions and chosen defaults: S41 — Competitor price monitor

Unattended run: nothing was asked; each default below was chosen by the decision policy (most production-grade option the notes and the constitution support). Sorted by impact: `[BREAKING]` first (changes behaviour or an API/UI contract that exists today), then `[CONTRACT]` (another capability must provide or consume it), then `[LOCAL]`. Scenario and requirement IDs refer to [`spec.md`](spec.md).

## BREAKING

- [BREAKING] Registration response and status → `201 {id, productId, url, host, status, lastPriceMinor, currency, lastCheckedAt, lastStatus, nextCheckAt, createdAt}` for a new watch, `200` with the same body for a replay (today an untyped `{targetId, url}` with the default `201` every time, `crawler.module.ts:30`) → a watch has its own identity (needed for list, delete, history, alert aggregate id) and a replay must be distinguishable (VII.3 idempotency) → FR-001, AS-01/02.
- [BREAKING] Refusal of a URL by the SSRF/policy guard → `422 url_not_allowed` (generic detail) and `422 url_unresolvable`; syntax stays `400 validation_failed` (today every failure is `400` with the guard's message, `crawler.service.ts:59-63`) → the message of the guard names the reason ("only https URLs are allowed", resolved ranges) and leaks resolver behaviour; a stable code is testable → AS-04/05, V.1.
- [BREAKING] `https` and port 443 only in every environment, and the fixture allowlist moves to its own config key that makes startup fail in production (today `http` is allowed for allowlisted hosts and the crawler reuses `webhooks_allow_private_hosts`; in production the allowlist is silently ignored, `crawler.service.ts:50-54`) → the notes' guard is "https only, block private ranges"; a webhook key controlling the crawler is a coupling and a silent no-op in production hides a misconfiguration (IV.6/VIII.5) → FR-012, AS-56. The e2e spec's config spy changes.
- [BREAKING] New routes: `GET /shops/:shopId/competitors`, `DELETE …/:watchId`, `GET …/:watchId/prices` (today only `POST`) → the notes' UI journey is "add competitor URL → price chart"; a monitor with no list, no removal and no history cannot be operated → FR-005–FR-007.
- [BREAKING] Price parsing: exact decimal, currency exponent per ISO 4217, currency mandatory, ambiguous formats rejected (today `Math.round(n * 100)` after stripping every non-digit, currency defaults to `USD`, `extract-price.ts:6-9,38`) → `"1.299,00"` currently becomes `1.299` (a price of 1 cent), JPY is ×100 wrong, a missing currency becomes dollars and can create a false alert; wrong price is worse than no price → FR-021, AS-33.
- [BREAKING] "Your price" and its currency come from the catalog's `getProductsByIds` (R1) and the alert is compared only within one currency (today SQL on `Product.price` and the string `'usd'` hard-coded for the seller's price, `crawler.service.ts:155,164`) → IX.4 and correct money display; mismatched currencies produce `currency_mismatch`, not an alert → FR-025, FR-028, AS-46.
- [BREAKING] The alert is the outbox event `seller_insights.competitor_price_dropped` v1, one per owner (today a direct `NotificationRouter.dispatch` with `formatMoney`, `crawler.service.ts:9,159-166`) → already decided by S28 (IV.3, domains do not know notifications exist); the barrel and tests stop using `NotificationRouter`, `formatMoney`; `crawler.e2e-spec.ts` spies the outbox instead → FR-026, AS-43.
- [BREAKING] Alert rule: per-watch evaluated price, evaluated on every observation **and** at registration; fires when `competitor < yours` (same currency) and the price is lower than the watch's previous evaluated price (today: a single comparison against the target's previous price, so a second shop that registers an already-observed URL never gets an alert, and the first observation always alerts if it undercuts, `crawler.service.ts:147`) → alerts must be correct per shop, not per target → FR-025, FR-027, AS-45/47/49.
- [BREAKING] Observation history rows only when the price or currency changes (today a row on every extraction that is not "unchanged", so a changed page with the same price inserts a duplicate point, `crawler.service.ts:140-145`) → smaller history, "lowest in 30 days" unaffected; the counter is the aggregate version of the alert → FR-023, AS-37.
- [BREAKING] robots.txt handling: unreachable (network error, timeout) or 5xx → the page is not fetched, retried in 1 h; `4xx` → everything allowed; the product token is matched exactly (today a network failure means "allowed with a 10 s delay", `crawler.service.ts:193`, and the group match is a substring test `token.includes(a)`, `robots.ts:33`) → RFC 9309 and politeness: a robots file we could not read is not permission; a rule for `bot` must not bind us → FR-016, AS-19/20.
- [BREAKING] Redirects: same host only, `https` only, at most 3 hops; a cross-host redirect ends with `redirected_host` (today any host is followed after the SSRF check, `pinned-get.ts:49-52`) → the lease, the delay and the robots rules belong to the registered host; following another host would bypass all three → FR-013, AS-27.
- [BREAKING] Fetch limits: 10 s overall deadline per request, 30 s per crawl, HTML content types only, a `truncated` flag (today only an idle-socket timeout, so a one-byte-per-second page holds a fetch loop and a host lease for ever; any content type is read, `pinned-get.ts:29,46`) → timeouts and bulkheads (06/03); a slow-drip competitor must not starve the fleet → FR-014, AS-28.
- [BREAKING] A failed crawl (SSRF refusal, timeout, DNS failure, thrown error) records a status and backs off (today `crawl()` throws, `crawlNext` only logs, the target keeps its old `nextCheckAt` and is queued again every minute, `crawler.service.ts:96-108`) → hammering a failing site every minute breaks politeness → FR-019, AS-29.
- [BREAKING] Registration no longer pulls `nextCheckAt` forward on every call; only when the last check is older than 1 h (today `LEAST(nextCheckAt, now())` on every `POST`, `crawler.service.ts:67`) → anyone could force a recrawl each minute by re-posting; politeness must not depend on a seller's clicks → FR-004, AS-11.
- [BREAKING] `CompetitorWatch` loses its foreign keys to `Shop` and `Product` (and the cascade) and product deletion arrives as `catalog.product_deleted` (today `REFERENCES "Shop"`, `"Product" ON DELETE CASCADE`, migration `20261002140000`) → IX.4 forbids FKs across owners; extractability test IX.9 → FR-030, AS-52/57. A new migration (with `lock_timeout`, III.11) drops the constraints.
- [BREAKING] Tracking-parameter list becomes explicit and `tag` is no longer stripped (today the regex also drops `tag`, `ref`, `spm` and every `mc_*`, `domain/url.ts:1`) → `?tag=blue` can be a product selector; two products must not merge into one target. Existing `CrawlTarget.url` values must be re-normalised by a migration that merges duplicates (re-pointing watches) → FR-017, AS-40.
- [BREAKING] Plan limits: a watch needs the entitlement `maxCompetitorWatches` and is capped at 5 per product (today unlimited, no entitlement check) → "Pro shops register" in the notes and unbounded crawl load otherwise → FR-003, AS-08.
- [BREAKING] Write route is rate limited (30/min per shop, fail closed) and the module is split: `CompetitorController` leaves `crawler.module.ts` for `api/` with DTOs from `packages/contracts` (today inline `WatchDto`, no limit) → D-6, VII.6 → FR-009.

## CONTRACT

- [CONTRACT] S28 consumes `seller_insights.competitor_price_dropped` v1 `{watchId, shopId, productId, productTitle, host, competitorPriceMinor, yourPriceMinor, currency, ownerId}`, `aggregateId = watchId` → honoured exactly, plus the additive field `priceVersion` (the observation counter, S28's "version") and one event **per owner** with a deterministic `eventId` → S28's payload has a single `ownerId`; owners of one observation share `(aggregateId, priceVersion)`, so S28 must dedupe on `eventId`, never on (aggregate, version) → S28 to confirm; topic name `seller-insights.events` is chosen here (S28 did not name one).
- [CONTRACT] S18 → a new numeric entitlement key `maxCompetitorWatches` in the plan table and the free tier (`starter` and free tier 0 in the spirit of "Pro shops register"; values are S18's) read with `checkLimit('SHOP', shopId, 'maxCompetitorWatches', current)` → entitlements derive from the live subscription, never plan names (S18 note); S18's DS-1 has no such key today.
- [CONTRACT] S54 → `safeGet` (SSRF-safe GET) with injectable resolver, overall request deadline, `sameHostRedirectsOnly`, `allowedPorts`, content-type filter and typed failure classes, replacing `infrastructure/net/pinned-get.ts` → S02, S08 and S43 asked for the same guard (their `questions.md`); this capability is the proof point (P0507) and states the exact shape it needs (spec Requires).
- [CONTRACT] S03 → `ShopScoped('products.write'|'products.read')`; R1 `getMembersByShopIds(ids, ['OWNER'])`; events `shop_created`, `shop_plan_changed`, `shop_status_changed`, `shop_deleted` (the last has no `shopVersion`) → replaces `ShopMembership` SQL (`crawler.service.ts:155`) and gives the shop read model (R3); `shop_deleted` is applied unconditionally.
- [CONTRACT] S05 → R1 `getProductsByIds(ids, {shopId})` for ownership, status, price and currency, and `catalog.product_deleted`; the worker app must be able to load the exported provider → replaces `SELECT 1 FROM "Product"` (`crawler.service.ts:70`) and the `JOIN "Product"` (`:155`); S05's list of consumers already names S41.
- [CONTRACT] S53 → outbox append inside the evaluation transaction and the consumer framework for the two read-model consumers → IX.6, IV.5.
- [CONTRACT] S50, S49 → policy `seller-insights.competitor-write.shop`; jobs `crawler.schedule-due` (exists as a raw `upsertSchedule`) and `crawler.purge-targets` → VIII.6.
- [CONTRACT] Web → no web capability owns the competitor screen yet; the routes above are its contract and "your price" on the chart is composed by the BFF (R2) from catalog's own API → this spec adds no cross-domain read to the capability's API.

## LOCAL

- [LOCAL] Seen-set (Bloom filter) is a negative filter only, backed by the target table → pattern map P1103 binds it; the notes' "a false positive would skip a fetch" cannot happen (FR-010).
- [LOCAL] Priority = max shop plan among watchers, then earliest due; plan read from the shop read model → notes: "priority by shop plan & change frequency"; change frequency is the adaptive interval.
- [LOCAL] Interval ladder 6 → 12 → 24 → 48 h for unchanged, 12 → 48 h for `gone`, 1 → 24 h for errors, ±10 % jitter, floor 1 h → avoids synchronised herds.
- [LOCAL] Several Product nodes on one page: first with a price in document order → simple and deterministic; documented limitation.
- [LOCAL] Out-of-stock offers are not prices → an out-of-stock page is not a competitor undercutting.
- [LOCAL] Archive is best-effort; history is not (state advances only after the history row is written, deduplicated on target id + counter) → a lost archive loses evidence, a lost row loses the price.
- [LOCAL] `Crawl-delay` capped at 300 s, minimum gap 1 s, host lease 60 s, crawl budget 30 s (< lease), queue mark 15 min.
- [LOCAL] Targets with no watcher are retired at once and deleted after 30 days; history stays until its 2-year retention.
- [LOCAL] Logs carry host and target id, never the URL or query (query strings can hold tokens).
- [LOCAL] Evaluation batches of 500 watches per transaction (the catalog and tenancy batch limits).
- [LOCAL] Raw-HTML archive key `crawl/<date>/<host>/<targetId>-<timestamp>.html` kept; 7-day lifecycle rule asserted on the bucket configuration.
- [LOCAL] No user pause/resume, no on-demand recrawl, no per-host block list → not in the notes; the shop-status pause exists.
