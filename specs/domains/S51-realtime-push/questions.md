# Questions and defaults: S51 — Realtime push hub

Every open choice was resolved by the decision policy (most production-grade option the notes and constitution support). Tags: `[BREAKING]` changes behaviour or an API/UI contract that exists today; `[CONTRACT]` decides something another capability provides or consumes; `[LOCAL]` affects only this capability's internals. BREAKING first, then CONTRACT, then LOCAL.

## BREAKING

- [BREAKING] Refusal codes: anonymous viewer on a topic whose rule refuses it → `401` (today `403`, `topic-stream.e2e-spec.ts:86`); authenticated viewer refused → `403` with one generic `detail` that does not name the topic (today `not allowed: <topic>`, `topic-stream.controller.ts:129`) → V.4 (401 = unauthenticated) and no oracle for "exists but not yours" vs "does not exist"; the existing e2e assertion changes.
- [BREAKING] A presented but invalid or expired credential → `401` even on public topics (today `Firewall({ anonymous: true })` behaviour decides) → `EventSource` cannot refresh silently; a stale cookie treated as "anonymous" hides expiry until a private topic is asked for.
- [BREAKING] Topic rules are **one per route** (prefix + suffix) and are never OR-combined; a duplicate route fails the boot (today `define` appends policies and OR-combines, `topic-registry.ts:34-35`; `topic-registry.spec.ts:49-53` asserts it) → the OR existed for the shared `job:` prefix that S07/S12 remove; an "any rule grants" combination is a security footgun.
- [BREAKING] Suffixes belong to their prefix: a suffix is valid only on the prefix that listed it, and a prefix with listed suffixes no longer accepts the bare `<prefix>:<id>` (today one global suffix set, so `shop:x:seatmap` is accepted, `topic-registry.ts:30,42`; `shop:<id>` bare is accepted) → needed so tenancy (`live`) and assets (`assets`) can both own routes under `shop`; parity test `topic-registry.spec.ts:7-28` is rewritten.
- [BREAKING] Prefix grammar `^[a-z][a-z-]{0,31}$` (today `[a-z]+`, `topic-registry.ts:23`) → S12 requires `order-export`; hyphen needed.
- [BREAKING] `publish` resolves `{ published, id }` and never throws for store faults, with a 1 s timeout and one attempt (today resolves the id string, throws on any Redis error, no timeout, `realtime-publisher.service.ts:19-35`) and rejects invalid topic, event type and oversize payload with typed errors (today nothing validated) → S13 and S31 specify best effort; a publish failure after commit must not fail the caller's flow; callers in orders, auctions, chat, fulfilment, launch-events, catalog-sync, notifications and seller-insights are re-checked for use of the returned id.
- [BREAKING] Live-only events (`replay: false`) carry no `id:` and never touch the cursor (today they get id `'0-0'`, and `topic-stream.controller.ts:148` drops any live-only event once a replayable one was delivered on that topic, then writes `0-0` into the cursor, `:149`) → a real bug for S24 (`read` replayable, `presence` live-only on the same topic) and S40.
- [BREAKING] Replay is paged to the end of the buffer (today one `XRANGE … COUNT 500`, silently cutting longer gaps, `topic-stream.controller.ts:96,177`) and an uncoverable gap sends `event: resync` instead of a hole → silent loss is the worst failure of a resume feature; web clients (W03, W04, W05, `useEventStream`) must handle `resync` by refetching.
- [BREAKING] A first connection receives a baseline `id:` frame so a topic with no event yet still resumes gap-free (today no cursor entry means no replay, so events published between a first disconnect and the reconnect are lost for topics that had not yet delivered) → closes a real gap.
- [BREAKING] The stream engine (`SubscriptionHub`, `TopicStreamController`, `TopicStreamModule`) moves from `apps/sse-gateway/src/topic-stream/` into `libs/infrastructure/realtime`, hosted by the gateway app (today app code, which domains cannot import) → I.5/X.1 (no logic in apps) and S23's ask; imports in `live-batcher.service.ts:64` and the e2e spec change.
- [BREAKING] Per-user (20) and per-anonymous-address (10) connection caps, instance capacity (`503`), and a new S50 policy `realtime.connect` (today `skipThrottle: true`, no cap of any kind, `topic-stream.controller.ts:114`) → an unbounded long-lived endpoint is a resource-exhaustion door; the cap and the policy are the notes' "backpressure" at the edge of the server.
- [BREAKING] Connections have a maximum lifetime (30 min) and end at credential expiry when the principal supplies it (today unlimited) → bounds how long a stale authorization or a missed revocation can last; `EventSource` reconnects with its cursor, so clients see nothing.
- [BREAKING] `retry:` is jittered 2000–5000 ms per connection (today fixed `3000`, `topic-stream.controller.ts:139`) → a deploy that drops 50k connections otherwise reconnects them in one instant.
- [BREAKING] Any query parameter other than `topics` → `400` (today ignored) → keeps tokens out of URLs and logs (notes: "a token in the URL … leaks into logs").
- [BREAKING] Event types are validated (`^[a-z][a-z0-9_.-]{0,63}$`; `open`, `error`, `resync`, `revoked` reserved) (today any string is written into `event:`, `topic-stream.controller.ts:150`: a newline in a type injects frames) → security fix; every existing type (`price`, `closed`, `notification`, `order.status`, `payment.status`) passes.
- [BREAKING] The replay buffer expires with the idle topic and drops events older than one hour (today count-capped only, no expiry: one stream per topic ever used, forever, `topics.ts:8`) → III.9 (every key has a TTL).
- [BREAKING] The publish and the live announcement become one atomic step (today two round trips, `realtime-publisher.service.ts:21-34`, while the comment at `:9-11` claims one `MULTI`) → a crash between them leaves a replay entry no live viewer saw, and the ordering claim of the notes depends on it.
- [BREAKING] A rule that throws or times out gives `503 realtime_policy_unavailable` (today an unhandled error, effectively `500`, and no timeout) → outage is not a verdict; avoids both a leaking "allow" and a misleading `403`.
- [BREAKING] Slow-consumer drop is joined by a stall timeout (30 s) and a bound on messages buffered during replay (today the replay buffer is an unbounded array, `topic-stream.controller.ts:144`) → P0105; a replay that never ends must not grow memory.
- [BREAKING] Open connections gap-fill from the replay buffer after a backplane reconnect (today clients are assumed to reconnect, `subscription-hub.service.ts:29`, but a healthy client connection never does) → silent loss otherwise.
- [BREAKING] The raw `libs/infrastructure/redis-pubsub` (publish-only, used by chat) and the gateway-local `redis-pubsub`, `payment-stream`, `realtime-notifier` are removed once their callers have moved (S24 to the hub; S13 deletes the payment SSE endpoint) → one fan-out path, one key namespace (I.4); the per-viewer unsubscribe bug of `payment-stream` (Q18 in the notes) disappears with it.

## LOCAL

- [LOCAL] Credentials in URL (a ticket as in the WebSocket lesson) → not added; cookie or bearer only → notes call URL tokens the worse option; ticket only for clients that can send neither.
- [LOCAL] Retention 1,000–1,200 events and 1 h → as stated → bounded memory, reconnect windows; approximate trimming means the upper bound is 1,200.
- [LOCAL] Gap detection (trimmed or expired) → resync event, not partial replay → exactness over best effort.
- [LOCAL] Replay page size 500 → configurable, loop to the end.
- [LOCAL] Payload cap 32 KiB, type grammar → stated; notifications and deltas only.
- [LOCAL] Policy timeout 2 s; publish timeout 1 s; no publish retry → IV.6; retry belongs to the caller if it ever wants one.
- [LOCAL] Replay-buffer overflow → discard buffered live messages and continue the replay (not close) → replayable events are in the buffer anyway; live-only ones in that window are lost, documented.
- [LOCAL] Revocation transport → backplane control channel; best effort plus lifetime bound → IV.3 (pub/sub never carries what must be delivered).
- [LOCAL] Discovery transport → the backplane's own list of channels with subscribers (ref-counting makes "has a channel" equal "has a listener") → no extra shared state to keep fresh.
- [LOCAL] Connection caps are per instance, not fleet-wide → approximate is enough for an abuse cap; exactness would cost a store round trip per connect.
- [LOCAL] Drain window 10 s, jittered per connection → avoids a stampede on deploy.
- [LOCAL] `owner` string on `define` → diagnostics for boot errors only.
- [LOCAL] Metric label sets are closed lists; no topic, user or cursor label → cardinality.
- [LOCAL] UI journeys: none for S51; the web hook's journeys belong to W03, W04, W05 → this capability has no screen.
- [LOCAL] `pnpm check:table-ownership` could not be run in this unattended session → by inspection the lib has no model or SQL; expected 0 findings (`gaps.md`).
