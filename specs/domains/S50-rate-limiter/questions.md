- [BREAKING] The central `RATE_LIMIT_POLICIES` table in `rate-limit.types.ts` is removed; each capability declares its own policies through `RateLimitModule.forFeature(definePolicies(...))`; S50 keeps only `default.read` and `default.write` → the table names checkout, auctions, chat, LLM, notifications: domain names inside infrastructure break X.3, and 40 specs would all edit one file → names and numbers stay exactly as each spec states them. (Also tagged CONTRACT below.)
- [BREAKING] The global fixed-window throttler (`@nestjs/throttler`, `ThrottlerGuard` in `core.module.ts:68-172` and `sse-gateway.module.ts:55-121`, `RedisThrottlerStorage`, config keys `throttle_api_limit` / `throttle_api_ttl`, `Firewall({ throttle, skipThrottle })`, `@SkipThrottle` on the Stripe webhook) is deleted → a platform default interceptor (`default.read` 300/min, `default.write` 60/min, user-or-address, fail open) plus `@RateLimitExempt(reason)` → two engines with two algorithms (a fixed window with the 2× boundary burst the notes warn about), two header formats and two fail models is the opposite of one provider; `skipThrottle` on ~25 anonymous routes means no limit at all (S25 asks for the default).
- [BREAKING] `RateLimiterService.acquire` returns `{ acquired, release, decision }` (today a release function or `null`) → a denial must carry `retryAfterMs` and a reason, and the interceptor hard-codes `Retry-After: 5` (`rate-limit.interceptor.ts:53-54`) → callers: `catalog-import.service.ts:100` (S07 drops this slot anyway), `statements.controller.ts:35` (decorator, unaffected).
- [BREAKING] `RateLimitDecision` gains `policy`, `reason`, `retryAfterMs: number | null`; `source` values become `store | local-lease | fallback` (today `redis | local-lease | fallback | fail-closed`); metric label values change accordingly → needed to tell "over the limit" from "limiter down" and "never fits"; callers `answer.service.ts:78`, `assistant-quota.service.ts:54`, `integration-sync.service.ts:225`, `notification-workers.service.ts:69`.
- [BREAKING] The sliding window takes its window index and elapsed time from the store's clock inside the atomic step, not from `Date.now()` of the calling instance (`rate-limiter.service.ts:131`) and reports a precise `retryAfterMs` (today the time to the end of the window) → instances with skewed clocks disagree on the window, and the notes say all instances share one clock.
- [BREAKING] A request denied by a later policy returns the units taken from earlier policies (today a request denied by `auth.login.account` has already consumed `auth.login.ip`) → a refused request must not cost budget; the multi-policy login in S01 depends on it.
- [BREAKING] Fail-open fallback charges `cost` and covers sliding-window policies and concurrency policies (today `bucket.take(key)` ignores cost at `rate-limiter.service.ts:93`; concurrency fail-open is unlimited at `:46`) → `llm.provider.tpm` and `public-api.default` are cost-weighted; unlimited fail-open concurrency defeats the policy during an outage.
- [BREAKING] The client address comes only from the platform's trusted-proxy resolution; the interceptor no longer reads `cf-connecting-ip` directly (`rate-limit.interceptor.ts:84`) → today any client can set that header to get a fresh bucket per request (S01 AS-15).
- [BREAKING] Subject for `shop` policies is typed `shop:<id>` (today the raw id, `rate-limit.interceptor.ts:95`) → no collision between subject kinds; changes stored keys (state resets once on deploy).
- [BREAKING] An unknown policy name fails application startup (decorators) and type checking (code), and a policy table is validated at startup (today a bad entry is found at the first request, or never) → VIII.5.
- [BREAKING] Cost above a policy's limit is a permanent denial (`reason: 'cost-exceeds-limit'`, `retryAfterMs: null`), `422` over HTTP (today the Lua returns a retry time that never comes true) → clients must not be told to wait for something that cannot happen.
- [BREAKING] Each store call has a timeout (default 200 ms) and a store failure is not retried inside the decision (today no timeout: a hung store hangs the request until the driver's own timeout) → IV.6.
- [BREAKING] Throttling runs before the idempotency check, so replays consume budget (`@RateLimit` stays an interceptor registered before the idempotency interceptor) → otherwise replays are a free bypass of any limit.
- [BREAKING] Edge worker `429` becomes problem+json with `Retry-After` and `RateLimit-*` (today a bare `{"error":"Rate limit exceeded"}` with no headers, `packages/edge-be/src/index.ts:336,401`) → clients and the web app handle one shape.
- [BREAKING] Failure-only counting is a new mode and `auth.login.account` switches to it (S01); concurrency denial `Retry-After` is derived from the earliest lease expiry, clamped 1–5 s (today fixed `5`) → required by S01/S02; more truthful hint.

## LOCAL

- [LOCAL] Leaky bucket → not built → the token bucket's average rate covers every use here.
- [LOCAL] Concurrency lease renewal → not offered → long jobs use their own fenced lease (S07, S49).
- [LOCAL] Default limits → `default.read` 300/min and `default.write` 60/min, user-or-address, fail open, no lease → a floor, not a tuning knob.
- [LOCAL] Fallback fleet-size estimate → configuration `rate_limit_fallback_instances`, default 4 (was a constant) → tunable per deployment.
- [LOCAL] Lease fraction ceiling → 0.5 → above that one instance can drain the key.
- [LOCAL] Denial memo for lease-enabled keys → up to 1 s of local denials → protects the store under attack; costs at most one lease lifetime of under-admission.
- [LOCAL] Problem body omits the policy name; headers carry it → names are not secret, but the body is read by humans and logs.
- [LOCAL] Denial log sampling → one line per policy per second → a flood must not become a log flood.
- [LOCAL] Edge limits stay two constants of the worker (120/min per subject, 500 ms timeout) → the edge cannot import the backend registry.
- [LOCAL] Time in tests → injectable store-time source plus fake application clock → no sleeps.
- [LOCAL] Cost resolvers run before validation and are pure → they must tolerate hostile input; failure follows the fail mode.
- [LOCAL] Pause is a store-side marker on the bucket, set empty on penalty → no burst after the pause.
