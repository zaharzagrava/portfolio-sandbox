## BREAKING

- [BREAKING] Event identity is `event_id` alone and the first received copy wins → the store collapses duplicates across name, day and receive time and every read counts one copy → today the store key is `(name, day, event_id)` with `ReplacingMergeTree(received_at)`, so a replay whose `ts` was re-clamped lands in another key and counts twice, and a later copy overwrites the first → `clickhouse/070_analytics.sql`, `analytics.service.ts:75-86`.
- [BREAKING] Experiments get explicit lifecycle endpoints (`PUT` for the draft definition with `expectedVersion`, `POST …/start`, `POST …/stop`), `stopped` is terminal, and variants, weights, layer, range, unit and metric are immutable once running → restarting or reweighting mid-run corrupts the analysis, and today `PUT` accepts any status in any order (a stopped test restarts, `stoppedAt` is nulled) and silently ignores definition changes while answering `204` → `analytics.service.ts:112-123`, `analytics.controller.ts:41-46`.
- [BREAKING] `PUT /api/admin/experiments/:key` answers `201` with `Location` or `200` with an `experimentSchema` body, uses optimistic concurrency (`expectedVersion`, `409 version_conflict`, equal save is a no-op), and splits shape errors (`400`) from semantic errors (`422 experiment_definition_invalid` with all `{path, code}`) → V.1, V.4 and two-admin safety, same pattern as S38 → today `204`, last writer wins, a raw database error on bad input.
- [BREAKING] Variant weights are integers in basis points that sum to 10,000, at most 10 variants, no floating-point scaling → exact, testable bucket boundaries → today any positive weights, scaled with `total / 10_000` as a float (`experiments.ts:22-23`).
- [BREAKING] An experiment declares `unit` (`user` | `visitor`), `owner` and a `metric` from a closed list; `purchase` needs unit `user` → a purchase carries only a user id, so counting it for an anonymous unit silently yields zero conversions; assigning by "user id else anonymous id" makes a visitor change variant at sign-in → today `unit` does not exist and results key by `if(user_id != '', user_id, anonymous_id)`, which splits one person into two units. Migration backfills `unit: "user"`, `owner: "unknown"`.
- [BREAKING] `GET /api/experiments/assignments` answers `{assignments: {key: {variant}}, degraded}` with `Cache-Control: private, no-store`, `Vary`, a 120/min limit, validated `X-Anonymous-Id`, the principal (not a header) selecting the user unit, and an empty degraded answer when stores are down → per-visitor data must not be shared-cached, and a store outage must mean control, not a 500 → today `{key: variant}`, no cache headers, unvalidated header, no limit (`analytics.controller.ts:34-39`).
- [BREAKING] Results count exposed and converted **units**, apply the window `[startedAt, stoppedAt]`, exclude crossover units, withhold comparisons when SRM mismatches, crossover exceeds 1% or an arm has fewer than 100 units, report a 95% interval, `alpha` with Bonferroni for more than two variants, `analysis: "fixed_horizon"`, `asOf`, and answer `503` when the store fails → a "winner" computed on broken data is worse than none (10/02 Ex2: SRM means the data is broken) → today the window has no end, a unit exposed to two variants counts under the first, comparisons are always shown, only SRM sets `trustworthy`, and a store failure is a `500` (`analytics.service.ts:71-107`).
- [BREAKING] Ingest validation is tightened and its answer changes: `anonymous_id` only `[A-Za-z0-9_-]`, `ts` a non-negative integer, flat props with key charset `[A-Za-z0-9_.-]`, `user_id`/`received_at`/`country`/`platform` in the body are rejected `forbidden_field`, exposures must have a valid shape, `rejected` is `[{index, code}]` with a closed code list (today `{index, error: <zod message>}`), duplicates inside a batch are `duplicate_in_batch`, body over 128 KiB `413`, wrong content type `415`, a produce failure `503 ingest_unavailable` with `Retry-After` (today an unhandled `500`) → a collector facing the internet must say precisely why, never trust identity fields, and tell the client when to retry → `event-schema.ts:12-23`, `analytics.service.ts:26-40`.
- [BREAKING] Ingest uses its own rate-limit policy `analytics.ingest` (120/min, per user or IP, fail open) instead of borrowing `search.query`, drops `skipThrottle: true`, and the edge worker gets the same limit → analytics spam must not eat search quota, and the public endpoint was effectively unlimited at the edge → `analytics.controller.ts:17-18`, `edge-be/src/index.ts:273-310`.
- [BREAKING] `country` is recorded only with the edge credential (S38's check), and `platform` is limited to `web | ios | android` (`server` is reserved) → any client can send `CF-IPCountry` or `X-Client-Platform` straight to the fallback → `analytics.controller.ts:30`.
- [BREAKING] The edge worker validates exactly as the backend does, from one shared table of vectors (it currently stringifies nested props to `"[object Object]"`, truncates values and cuts props silently instead of rejecting, and never rejects bad `anonymous_id` characters), retries produce 3 times and counts final failures → one contract, two runtimes → `edge-be/src/index.ts:257-310`.
- [BREAKING] Purchase events from `order.paid` use an invalid-payload dead-letter instead of a silent filter, and take `received_at` from the injected clock → VII.4 requires a rejected or dead-lettered invalid payload → `purchase-events.projector.ts:24-43`.
- [BREAKING] `AnalyticsService.logExposure` is removed; server-rendered variants log exposures through the same ingestion with the visitor's identity → one validated path, no privileged writer of events (it has no caller today).
- [BREAKING] Experiment writes append an immutable history row (`ExperimentAudit`, actor not null, request id, before/after) in the same transaction and admin endpoints list experiments and history by keyset → III.7 requires a history row with every state transition; today none exists → new migration, new table in `db/ownership.ts`.

## CONTRACT

- [CONTRACT] `bucketOf(salt, unit)` is called with salts `"layer:<layer>"` and `"exp:<key>"` (S38's spec says "the experiment id as salt") → a flag and an experiment that share a key would otherwise get identical buckets and correlated assignment; the namespaced salt keeps today's hash values and still goes through S38's single function → S38 must keep exporting `bucketOf(salt, unit)` unchanged; if it prefers the bare key, say so and S39 changes the two prefixes.
- [CONTRACT] The closed event-name set gains `video_view` (with `props.video_id`) → S30 says view counts come from player beacons into S39 but no name exists for them → S30's emitter uses it; S35 ignores names it does not count, so its contract is unaffected.
- [CONTRACT] `storedAnalyticsEventSchema` is published in `packages/contracts`, `anonymous_id` is `""` for server events (8–64 characters for client events), `ts`/`received_at` are `YYYY-MM-DD HH:mm:ss.SSS` UTC, topic `analytics.events` keyed by `anonymous_id` → S35's spec requires exactly this; the empty id only appears on `purchase`, which S35 does not count.
- [CONTRACT] Exposure event shapes are `{experiment, variant}` and S38's `{flag_key, variant, flag_version}` → S38 asked for exactly its shape; flag exposures are stored and ignored by experiment results.
- [CONTRACT] Rate-limit policies `analytics.ingest`, `experiments.assignments`, `experiments.admin.write`, `experiments.results` are added to S50's registry with the numbers in the spec → S50 owns the registry (S35 does the same for `discovery.trending`).
- [CONTRACT] The BFF/Next.js server reaches assignments by R2: forwards the session and `X-Anonymous-Id`, never caches the answer in a shared cache; server-rendered exposures go through `POST /api/events` with the visitor's own identity → composition may not import domains (X.8.2), and per-visitor data must not be shared-cached → S48, W02, W03 follow this.
- [CONTRACT] W02/W03 own the emitters and the anonymous-id cookie, reuse one `event_id` per event across retries, log one exposure per render and flush with `sendBeacon` on `visibilitychange` → the notes' test list (08/04 §8) puts "exposure emitted exactly when the user sees the variant, still delivered on unload" on the client; S39 can only prove it is accepted and counted once. - [CONTRACT] The purchase signal is consumed from `order.paid` v1 as an R3 projection through the exported `OrderPaid` event contract; S53 supplies the dead-letter queue and replay; S10 keeps emitting `order.paid` with `userId`, `total`, optional `currency` → domain-map: experimentation depends on orders for conversion.
- [CONTRACT] S25 lists S39 as a consumer of `discussion.post_created`, and S37 says S39 "may subscribe" to `link.clicked` → S39 consumes neither: no requirement in this capability needs them, and domain-map lists only orders as a dependency; either would add a domain edge. - [CONTRACT] J05 reads results through `GET /api/admin/experiments/:key/results` with a user-unit experiment; a visitor-unit experiment cannot count `purchase` → J05 creates a `unit: "user"`, metric `purchase` experiment and polls results for up to 60 s after the purchase (FR-044).
- [CONTRACT] No experiment lifecycle events (`experiment_started`, `experiment_stopped`) are published → nobody consumes them; the history table and logs cover audit.
- [CONTRACT] Shared event vectors live in `packages/contracts` (fixture next to the schemas) and both the backend and `packages/edge-be` tests read them → the two runtimes cannot import each other's code, so one data file keeps them equal.

## LOCAL

- [LOCAL] Crossover threshold 1%, minimum arm size 100, SRM threshold `p < 0.001`, Bonferroni for more than two variants → conventional values; one constant each.
- [LOCAL] At most 200 experiments, 10 variants; assignment evaluates every running experiment per request → keeps the 5 ms budget without an index.
- [LOCAL] Assignment degraded mode returns an empty map, not an error → fail to control, as the notes' kill switch does.
- [LOCAL] Running set cached with write invalidation and a 10 s per-instance memory layer → at most 15 s staleness after a stop.
- [LOCAL] Results are computed on request, no result cache → admin-only and rate limited; revisit if used by dashboards.
- [LOCAL] Refunds and cancellations do not reverse a purchase conversion → out of scope; `order.paid` happened.
- [LOCAL] Event retention 400 days, dead letters 14 days (unchanged).
- [LOCAL] Raw props values and user ids are never logged; anonymous id logged as a 4-character prefix.
- [LOCAL] Erasure of a person's events on request and consent handling are out of scope; no IP or user agent is stored.
- [LOCAL] Existing `analytics.e2e-spec.ts` is replaced by the six files in `test-plan.md`; it calls services directly and bypasses HTTP and the stream.
- [LOCAL] Experiment `description` ≤ 500 characters, `owner` 1–100 characters (same limits as S38 flags).
