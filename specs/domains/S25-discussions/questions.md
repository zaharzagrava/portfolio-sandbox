# Questions and decisions — S25 Product discussions

Taken unattended under the decision policy (most production-grade option the notes and constitution support). Sorted by impact: BREAKING first, then CONTRACT, then LOCAL. Review BREAKING and CONTRACT lines first.

## BREAKING

- [BREAKING] Board identity (today any string ≤ 64 chars: `product-<uuid>`, `brand:apple`, or garbage, no product check) → board ID is the product UUID; writes check the product through catalog R1 (`404 board_not_found`, `409 board_closed` for ARCHIVED); brand boards and free-form boards are removed; route is `/boards/:productId/…` as in SD-11 → any string could spawn a spam board; no domain owns brands; the web's `product-<id>` prefix goes (W02 change).
- [BREAKING] Creating posts and comments → `Idempotency-Key` required (V.6 semantics: replay returns stored status and body, in-flight `409`, different body `422`, missing `422`) → a double click or a retry after a timeout otherwise duplicates content; today no protection (`discussion.service.ts:58,120`).
- [BREAKING] Vote request/response → body is `{value}` only (client-sent `targetType` removed; server resolves it), response always `{targetId, targetType, ups, downs, score, myVote}` (today a replay returns `{ups, downs}` without `myVote`, `vote.service.ts:38`), `422 self_vote_not_allowed`, `409 target_deleted`, `404 target_not_found` → trusting a client-supplied type lets a comment ID be voted as a post; self-votes are a basic manipulation vector.
- [BREAKING] List envelopes and cursors → `{items, nextCursor}` replaces `{posts, next}`; cursors are opaque keyset cursors (today the hot/top cursor is a numeric ZSET offset, `discussion.service.ts:93`, and the `new` cursor is a readable `bucket:pagingState`); invalid `sort`/`window`/`limit`/`cursor` → `400` instead of silently falling back to `hot` (`discussions.controller.ts:29`) → III.10 forbids offset pagination; offsets skip and repeat items while votes reorder the list; silent fallbacks hide client bugs.
- [BREAKING] Comment reads → one model: top-level comments paged (`sort=best|new|old`), each with its first 5 replies and `hasMoreReplies`, plus `GET /comments/:id/replies` for "load more per branch"; the flat `thread()` (chronological, hard `LIMIT 200`, no cursor) and `bestThread()` (no cursor, N+1 reads) are removed; `path` is no longer exposed → SD-11 and notes §11 ask for "first N top-level + a few replies, then load more per branch"; today a 50k thread cannot be paged at all.
- [BREAKING] Safe markdown → keep raw markdown, store the rendition with a policy version, re-render on read when the version is old, and require clients to sanitise `bodyHtml` again (W02) → notes 05/01 §1: "sanitise at render time … re-sanitising at output protects old stored data too"; today HTML is sanitised once at write and rendered by the web with `dangerouslySetInnerHTML` and no client sanitiser (`product-discussions.tsx:108`, VI.7).
- [BREAKING] Deleted comment output → tombstone returns `authorId: null`, empty body, `deleted: true`, `deletedBy`; raw markdown erased in storage (today `authorId` stays visible, `body_md` blanked only) → notes §9 "deletes … must be filtered at hydration"; an author's identity on removed content is needless exposure.
- [BREAKING] Deleting posts → new `DELETE /posts/:postId` (author or moderator); posts have a `deleted` column but no way to delete (today only comments) → users and moderators need removal; the feed must be able to hide deleted posts.
- [BREAKING] Ranking inputs → ranking (hot, top, best) uses weighted votes (weight 0 for accounts younger than 24 h, shadow-banned voters, unresolved accounts); displayed counts stay raw → SD-11/notes §11 name "new-account vote weight" and shadow-ban as the abuse controls; today every vote counts the same.
- [BREAKING] Derived state in the cache → Redis hashes/ZSETs (`score:*`, `post-meta:*`, `board:{…}:top`, `post:{…}:best`) all get a TTL and are rebuilt from the vote/comment stores on a miss; the vote store is the source of truth; hot and top both capped at 1,000 per board (today only `hot` is capped; `top` and the score hashes grow forever; a Redis restart loses `comments` counts and rankings) → III.9 (cache never source of truth, every key has a TTL).
- [BREAKING] Feed link → `DiscussionService` stops calling `FeedPublisher` in-process (it is `@Optional` and not provided in `DiscussionsModule`, so it never ran, and it swallows errors, `discussion.service.ts:86`); post creation records `discussion.post_created` durably and S26 consumes it → IV.4 forbids a direct dual write; a swallowed publish is a lost event.
- [BREAKING] Reaching old posts → `new` listing reaches every post (today it stops after 24 empty-or-full month hops, `discussion.service.ts:101`, so boards older than two years lose their history) → correctness over the cheapest scan.
- [BREAKING] Top ranking → gains `window=day|week|month|year|all` (default `all`); notes §11 "plain score within a time window" (today all-time only) → additive but the default order is now capped and windowed.
- [BREAKING] Validation status → validation failures are `400 validation_failed` (aligned with S24), body complexity limit of 20 nested quote/list levels, titles reject control and bidi-override characters; unknown request fields are rejected (today `ValidationPipe` rules are inconsistent per route) → V.4/II.2 and notes 05/01 §1 (logs, bidi spoofing).
- [BREAKING] Rate-limit profiles `discussion.write` and `discussion.vote` are used by this capability only → today `media.controller.ts:28` and `share-links.controller.ts:21` borrow `discussion.write`, so a user's photo uploads eat their post budget → one profile, one owner.
- [BREAKING] Anonymous reads no longer `skipThrottle` → they use the platform's default read limit (S50) instead of no limit at all → public unauthenticated endpoints with no limit are a free scraping and DoS surface.
- [BREAKING] Vote concurrency outcome → same-user concurrent votes return `200` or `409 vote_in_progress` with `Retry-After` (today a `409 Vote in progress` only from a 3 s Redis lock; if the lock expires mid-write, a delta applies twice) → the store, not the lock, guarantees one record; counts reconcile from the records.

## CONTRACT

- [CONTRACT] Author display → API exposes `authorId` only, no display name or e-mail → S01's `UserSummaryDto` has `email`, `role`, `createdAt` and no public handle; S24 made the same choice; BFF (S48) may compose a handle later (R2).
- [CONTRACT] Account age and moderation target lookup → S25 calls S01 `UserDirectoryService.getUsersByIds` (R1) and uses only `id` and `createdAt`; lookup failure or unknown user → weight 0 → fail safe for ranking; S01 spec AS-79 shape.
- [CONTRACT] Board validation → S25 calls S05 `ProductQueryService.getProductsByIds` (R1) on writes only; reads never consult the catalog → keeps hot reads independent of catalog latency; S05 AS-48 shape (`status: ACTIVE | ARCHIVED`).
- [CONTRACT] Events S25 provides → `discussion.post_created`, `discussion.post_deleted`, `discussion.comment_created`, `discussion.comment_deleted`, `discussion.vote_anomaly_detected` v1 on topic `discussion.events` keyed by `postId`; payloads in `spec.md`; none for votes, none for shadow content → S26 (feed items and their removal) and S28 (reply notifications) are the consumers; S26 and S28 must read this section.
- [CONTRACT] Durable event recording → community records events in its own store with the write and relays them (at least once, stable `eventId`); the infrastructure outbox is a PostgreSQL table and community owns none (decision D5), so using it would be a dual write → S53 must expose the envelope and producer (`defineEvent`, keyed Kafka send) without requiring a SQL transaction.
- [CONTRACT] `DiscussionQueryService.getPostsByIds` (R1, ≤ 100 ids, visible posts only) → S26 hydrates feed `post` items with it so deleted and shadow posts vanish from timelines (notes §9) → same domain, still an exported service so the contract is explicit.
- [CONTRACT] Rate limiting → S50 provides profiles `discussion.write` (10/min/user, fail closed) and `discussion.vote` (60/min/user, fail open + local lease) with `429` + `Retry-After`; S25 does not implement limiting itself.
- [CONTRACT] Idempotency → S25 needs the V.6 idempotency-record service (user + route + key, 24 h TTL, stored status and body) from infrastructure (first specified in S13); if it is not usable from a store-less path, S25 holds its own records in its store.
- [CONTRACT] W02 must send `Idempotency-Key` on post and comment creation, use the product UUID as board ID, read `{items, nextCursor}`, send `{value}` only on votes, re-sanitise `bodyHtml` before insertion, de-duplicate by `postId`, render titles as text → W02 spec must read this section.
- [CONTRACT] Product-page "top discussions" section → S48 may call `GET /boards/:productId/posts?sort=hot&limit=3` over HTTP (R2); S25 offers no other composition endpoint.
- [CONTRACT] Photos in posts → out of scope (S29); `media-events.ts` and the media upload comment ("discussion posts") promise a link that this capability does not provide; markdown images are not rendered.
- [CONTRACT] Shop-level moderation → not offered; only `ADMIN` and `MODERATOR` roles moderate. A later capability could take `ShopAccessService.assertMember` (S03) → keeps S25 free of a tenancy dependency; recorded so S03 does not assume it.
- [CONTRACT] Contracts package → S25 adds zod schemas `PostView`, `CommentView`, `CommentNode`, `PostPage`, `CommentPage`, `VoteResult`, `CreatePostRequest`, `CreateCommentRequest`, `VoteRequest` (V.2).

## LOCAL

- [LOCAL] Comment depth limit → 8 (top = 0), reply beyond it `422 max_depth_exceeded` → bounded path length; Reddit flattens instead, refusing is simpler to test.
- [LOCAL] Embedded replies → first 5 descendants per top-level comment, thread order → matches SD-11 "first few replies".
- [LOCAL] Replies ordering → oldest-first in every sort; only top-level re-ordered → notes only rank top-level comments.
- [LOCAL] Best-score ties → older comment first; hot/top ties → newer `postId` first → deterministic keyset order.
- [LOCAL] Reply to a deleted comment → `409 parent_deleted` → a tombstone keeps the tree shape but takes no new children.
- [LOCAL] Vote on archived product's content → allowed → only creation is closed.
- [LOCAL] Shadow ban → prospective (flags content at write time); events skipped for shadow content → deterministic, no mass rewrite of old rows.
- [LOCAL] Anomaly signal → 10 zero-weight votes in 10 min per target, one event per target per hour → IP clusters need network data the domain does not have.
- [LOCAL] Account-age weight → fixed at cast time, not re-evaluated → recount from the vote store stays deterministic.
- [LOCAL] Degraded mode when the cache is down → hot/top/best from the 200 most recent posts or top-level comments with `degraded: true`; votes `503` → counting without the serialising lock risks double deltas.
- [LOCAL] First-page cache → viewer-independent, 5 s, invalidated on every write to the thread; votes may lag ≤ 5 s → SD-11 "hot thread first page cached 5 s".
- [LOCAL] Counter durability → durable aggregate counters lag ≤ 5 s; reconciliation every 5 minutes for targets voted in the last 24 h, repairs within 15 min → the vote store is the truth.
- [LOCAL] Page size → default 25, max 50, on every list.
- [LOCAL] Partition size for top-level comments 5,000 and the ranking cap 1,000 are configuration; tests set them to 5 and 3.
- [LOCAL] Out of scope → editing, locking/pinning, report queues, search, attachments.
