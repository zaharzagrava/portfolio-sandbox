# Research: S25 — Product discussions

No `NEEDS CLARIFICATION` remains: `questions.md` defaults are accepted. The items below are the design decisions the spec leaves to the plan, each checked against the code read for this plan (`libs/domains/community`, `libs/infrastructure/{idempotency,events,cassandra,cache,jobs,rate-limit}`, `packages/contracts/src/community/discussions.ts`).

## R-1 Where the truth of a vote lives

- **Decision**: one Scylla table, `votes_by_target ((target_id), user_id)`, is the truth. Each row carries `value`, `weight`, `cast_at`, `version`. A vote is a lightweight transaction (`UPDATE … SET value, weight, cast_at, version = v+1 IF version = v`, or `INSERT … IF NOT EXISTS`). The statement's `[applied]` result is the serialisation point (FR-020, FR-023, III.6). The Redis lock, the read-previous-then-write and `votes_by_user` leave the write path.
- **Why**: today (C3) a lock that expires lets two requests apply the same delta; (C8) `votes_by_user` is an unbounded partition. A conditional write cannot double-apply. The loser of the compare-and-set re-reads once and retries once; a second loss answers `409 vote_in_progress` + `Retry-After: 1`.
- **`myVote` for a page**: `SELECT … FROM votes_by_target WHERE target_id IN (…≤50) AND user_id = ?` (partition-key IN with a clustering equality; bounded by page size).
- **Old table**: `votes_by_user` stays untouched this release (expand/contract, III.11); a later contract step drops it. Old `votes_by_target` rows have null `weight`/`version`: read as weight 1, version 0 (the first CAS uses `IF version = null`-safe path: `IF value = ?` fallback documented in `data-model.md`).
- **Alternatives**: Redis Lua as truth (breaks III.9); keep the lock and add a version (still two stores); counters only (no per-user record, cannot enforce one vote).

## R-2 Displayed counts and ranking inputs are derived state with a durable counterpart

- **Decision**: `ups`/`downs` (raw) and `wups`/`wdowns` (weighted) are four counters. Live copy: Redis hash `dsc:cnt:{targetId}` with a 1 h TTL, updated by one Lua script `COUNT_APPLY` right after the CAS commits (only when the hash exists; a miss is rebuilt, not incremented). Durable copy: Scylla counter table `vote_counts` fed by the existing `WriteBehindCounter` (drain ≤ 5 s). Rebuild on a miss: page `votes_by_target` for the target and sum (single flight, `CacheModule`/S52 helper). Reconciliation (R-9) repairs drift for targets voted in the last 24 h.
- **Why**: fixes C4/C5 (no TTL, crash between multi and buffer). The delta is computed from the CAS result `(previous, new)`, so it is derived from the committed record, not from a read taken before it.
- **Crash window**: a crash between CAS commit and the Lua apply loses a delta from the live hash only; the target is in `recent_targets` (written before the CAS, idempotent insert), so the reconciliation job recounts it. The window is bounded by 5 minutes + the 15-minute repair target (FR-024).
- **Alternatives**: counters computed on read from the vote partition (a hot post with 100k voters, 50k rps: no); batch the CAS and counter in one statement (Scylla cannot mix counter and LWT).

## R-3 Atomic creation and durable events: logged batch, not an outbox table

- **Decision**: `community` owns no PostgreSQL table (D5), so the infrastructure outbox (a SQL table written in a SQL transaction) is not usable without a dual write. A post is created with one **logged batch** over: `posts`, `posts_by_board`, `board_months`, `recorded_events` (the event row), `recent_activity`. A comment: `comments_by_post`, `comment_locator`, `recorded_events`, `recent_activity`. A logged batch is all-or-nothing (the batch log replays it), which is what FR-060 asks ("if the post exists, the event will be published"). The batch spans partitions on purpose; the unlogged `batchSamePartition` helper is not used for it. `client.batch(..., {logged: true})` is called from the community adapter on `CassandraService.client`; the shared service is not edited.
- **Relay**: `pending_events ((hour_shard), event_id)` holds the payload until published. A scheduled job (`discussions.relay-events`, every 2 s, S49) reads the current and previous hour for each of 8 shards, publishes with `EventPublisher.publishMany` (S53: validates the envelope, keyed by `aggregateId`, idempotent producer), then deletes the pending row. The pending partitions are TTL'd (48 h) and use `gc_grace_seconds = 3600` and TWCS, so the deletes do not accumulate tombstones. Delivery is at least once; `eventId` is fixed at write time (`recorded_events` holds the immutable copy; the pending row is the work queue).
- **Invalid recorded event**: a row that fails its zod schema is copied to `dead_events` with the reason and deleted from `pending_events`; it never blocks the shard (IV.5, VII.4).
- **Alternatives**: infrastructure outbox in PostgreSQL (dual write, rejected in `questions.md`); publish after the write in-process (the swallowed publish of A4); Scylla CDC (not available on Keyspaces).

## R-4 Idempotency: infrastructure record for the HTTP semantics, a creation claim for the crash window

- **Decision**: `@Idempotent({required: true, ttlSeconds: 86400})` from `infrastructure/idempotency` gives replay, in-flight `409`, different body `422`, missing key `422` and the user+route scope (FR-004). It lives in PostgreSQL and is infrastructure-owned (IX allows it: it is a shared platform service, not a community table). It cannot cover a crash between the Scylla commit and the stored response, nor AS-52 (store timeout where the write actually landed). So creation also takes a **claim**: `create_claims ((user_id, key_hash))` with `INSERT … IF NOT EXISTS` carrying the pre-allocated `entity_id` and `created_at` (TTL 25 h). The first attempt allocates the time-based ID from the clock and inserts the claim; any retry (after a 503 the interceptor released) finds the claim and re-issues the same batch with the same ID and `createdAt`. The batch is an upsert on the same primary keys, so a repeat is a no-op.
- **Why**: AS-52 asks for exactly one post "whichever attempt actually stored it". The key hash is `sha256(route + key)`; the claim stores the request fingerprint, so a reused key with a different body is refused even if the PG record was purged.
- **Alternatives**: deterministic ID from `hash(user, key)` (timeuuid needs the clock time; an ID that is not time-ordered breaks FR-003); own Scylla idempotency records for the whole V.6 semantics (duplicates the platform service).

## R-5 Time-based IDs without the driver clock

- **Decision**: `domain/ids.ts` builds a version-1 UUID from `(nowMs, sequence, node)`: 60-bit timestamp from the injected `Clock`; 14-bit clock sequence = a per-process monotonic counter that resets when the millisecond changes (and carries into the 100-ns field up to 9,999 values per ms), 48-bit node = random per process. `compareTimeUuid(a, b)` orders by `(timestamp, clockSeq, node)`; the Scylla `timeuuid` type orders the same way. A `sortableId(uuid)` (32 hex, timestamp first) is the Redis member, so lexicographic member order equals time order (fixes D2). `node:crypto` randomness enters through a `RandomSource` argument, so `domain/` imports no `node:crypto` (fixes B7, I.3).
- **Frozen clock (AS-19)**: 50 concurrent comments at the same instant get distinct IDs (sequence + node), identical `createdAt`, and a deterministic order (the comparator).

## R-6 Comment layout and bucket allocation

- **Decision**: keep `comments_by_post ((post_id, bucket), path)` and `comment_locator`. Top-level comments are assigned a bucket by an LWT slot allocator `post_buckets (post_id) → (bucket, filled)`: `UPDATE … SET filled = filled + 1 IF bucket = ? AND filled < cap`; when full, `SET bucket = bucket + 1, filled = 1 IF bucket = ?`. The Redis `INCR` (no TTL, B2) and the `comment_buckets` read-then-write on `posts` are removed (the `posts.comment_buckets` column is kept, no longer written). The allocator row is claimed before the batch; a crash after the claim wastes one slot, never loses a comment. Replies take the **root's** bucket from the parent's locator row (a reply never lands in another root's partition, AS-18).
- **Thread order**: `(bucket, path)` where `path` is the time-based segment from the injected clock plus the ID's sortable suffix (so the order is a pure function of the stored IDs). `sort=new` reads buckets descending with `ORDER BY path DESC`.
- **Rows per page (AS-18, SC-005)**: a partition mixes roots and replies, and CQL cannot filter "no dot in `path`" without reading the replies. So roots also live in `top_comments_by_post ((post_id, bucket), path)` (written in the same logged batch): a page reads at most `limit + 1` rows from it, anchored on the cursor. Per root, one range read on `comments_by_post` (`path > p AND path < p/`, `LIMIT 5`). Total ≤ `limit × 6` rows. The edge wrapper in the test counts rows.
- **Deleted/shadow rows**: tombstones are returned (position kept); shadow rows are skipped after the read with one bounded top-up read per page (≤ 2), so a page can hold fewer than `limit` items but never loops.
- **Alternatives**: bucket from `count / cap` (needs an exact count: the problem); time-based buckets (unbounded for a viral hour).

## R-7 Rankings in Redis: members, keyset, windows, cap, TTL

- **Decision**: per board one ZSET per ranking: `dsc:rank:{boardId}:hot` and `…:top:{day|week|month|year|all}`; per post `dsc:rank:{postId}:best` for top-level comments. Member = `sortableId`, score = the ranking value (hot rounded to 7 decimals; top = weighted net; best = Wilson, 9 decimals). Equal scores in Redis order by member, descending on `ZREV*`, which is time order, so the FR-032 tie-break (newer first) is native. Keyset page = Lua `RANK_PAGE(key, scoreCursor, memberCursor, limit)`: ranges from the cursor score inclusive, skips entries with the same score whose member is ≥ the cursor member, returns `limit + 1`. The cursor is `base64url(HMAC(sort, boardId, window, score, member))`; a tampered or foreign cursor is `400 invalid_cursor`. No offset (III.10).
- **Cap and TTL**: every ZSET is trimmed to the configured cap (default 1,000) on insert (`ZREMRANGEBYRANK`), and has a 6 h TTL refreshed on write. Hot ages out because the hot score includes age; top windows drop entries older than the window at read time (Lua filters by the time embedded in the member) and at rebuild. Post meta (`createdAt`, title hash) is not duplicated in Redis: pages hydrate posts from Scylla by ID (one `IN` query) and counts from the count hashes (one pipelined `HMGET` batch), fixing D7.
- **Rebuild on a miss**: read `board_months` (non-empty months, newest first, fixes D5) and `posts_by_board`, newest first, up to `rebuildScanCap` posts (default 20,000), join weighted counters, write the ZSETs with the cap. Single flight per board. A board larger than the scan cap ranks its newest 20,000 posts after a cache loss: documented limit, tests use a small cap.
- **`new`**: durable only. Keyset `(bucket, post_id)` over `posts_by_board` walking `board_months` downward: no 24-month horizon. A shadow row is returned only to its author.
- **Degraded** (FR/AS-51): Redis errors on a rank read → `ranking = degraded`: compute from the newest 200 posts (or 200 newest top-level comments) in memory with the same pure functions; response `degraded: true`; its cursor is a `new`-style cursor tagged `degraded` (so a cursor from one mode is refused in the other: `invalid_cursor`).

## R-8 Vote weight, shadow bans, anomaly signal

- **Weight** (`domain/vote-weight.ts`): `weight(accountCreatedAt, now, shadowVoter) → 0 | 1`: 0 if shadow, unresolved (`undefined`), or `now − createdAt < 24 h`; else 1. Account age comes from one `UserDirectoryService.getUsersByIds([voterId])` per **first** vote of a (user, target) and per change; failure → weight 0 + warning (AS-45) via a domain port `AccountDirectory` (ACL, IV.8) with a 300 ms timeout. Shadow-ban lookup: `shadow_bans ((user_id))` cached in a 60 s local map (a ban is prospective; 60 s lag accepted and documented).
- **Anomaly**: pure `domain/anomaly.ts` over a Redis sorted set `dsc:anom:{targetId}` (timestamps of zero-weight votes, 10-minute window, TTL 15 min) and a `SET NX EX 3600` key for the once-per-hour dedupe; the event is recorded in the same way as any other (R-3). This is derived state: after a Redis loss the signal can fire a second time within an hour (documented, harmless).

## R-9 Reconciliation and schedules

- Jobs (S49 `upsertSchedule` from `DiscussionsWorkerModule`, one owner module so `VoteService` is no longer provided twice, G7): `discussions.flush-votes` (5 s, exists), `discussions.relay-events` (2 s), `discussions.reconcile` (5 min: for each target in `recent_targets` of the last 24 h, recount votes and comments from the durable store, compare with the live hash and durable counters, repair, log one warning with the drift, recompute rank entries; a second run changes nothing), `discussions.purge` (hourly: nothing to purge in Scylla, TTLs do it; kept out of scope). `discussions.recount` (exists) stays as the per-target worker the reconcile job enqueues. `recent_targets ((day), target_id)` and `recent_posts ((day), post_id)` have a 48 h TTL.

## R-10 Safe markdown

- **Decision**: keep `marked` + `sanitize-html` in `domain/content.ts` (pure, no framework import). Policy constant `RENDER_POLICY_VERSION = 2` (bumped from the implicit 1). Heading mapping: levels 1–2 → `h4`, 3–4 kept, 5–6 → `h4`, text kept (E2). Complexity gate before `marked.parse`: a linear scan counting nesting of `>` and list-indent levels per line and the count of unclosed `[`/`(`; > 20 levels or a single line that makes the scan exceed a budget → `markdown_too_complex` (→ `400 validation_failed`, field `body`). Storage: `body_md` raw, `body_html`, `html_version`. Read path: `html_version < current` or null → `renderMarkdown(body_md)` in memory; a lazy `UPDATE … SET body_html, html_version IF html_version < ?` in the background (best-effort, never blocks, never fails the read). Defence in depth: the output of **any** read also passes the cheap `assertSafeHtml` check (tag/attribute allow-list scan) only in tests; production relies on the version check.
- **Title**: verbatim; validated (trim, 3–300 code points, no control or bidi) in the DTO pipe through a shared pure `normalizeTitle` in `domain/`.

## R-11 Validation, errors, timeouts

- Global `ValidationPipe({whitelist, forbidNonWhitelisted, transform})` is already production config; DTOs get `@Transform(trim)` and code-point length validators; a `DomainError(code, status)` family in `domain/discussion-errors.ts` carries the stable `code`; the global filter (S54) renders problem+json and maps `code`. Unknown `sort`, `window`, `limit`, `cursor` → `400 validation_failed` through query DTOs (`@IsIn`, `@IsInt @Min(1) @Max(50)`), `cursor` failures → `400 invalid_cursor`.
- Timeouts: every Scylla call through `ScyllaStore.run(query, params, {timeoutMs, idempotent})` (adapter wrapper: `readTimeout` + `Promise.race`, 800 ms reads, 1,500 ms writes inside the 2 s write budget tracked by an `AbortBudget` value passed down); every Redis call through `RankingCache` with 150 ms. A timeout or driver error → `ServiceUnavailable` (`503 service_unavailable`, generic detail). Retries: only inside the CAS loop (exactly one layer, ≤ 2 attempts, idempotent by construction); no automatic retry elsewhere (clients retry with the same key).
