## D. Suggested order of work

1. Pure domain first (AS-53, AS-54, tests first): `resolveBid`, the state machine with `assertNever`, the bidding window, the extension function, the alias function, the runner-up selector; ports for the repository, cache, stock, order command, role lookup and clock in `domain/`.
2. Data (expand/contract, `lock_timeout`): new status values and `statusReason`, `currency`, `winnerOrderId`, hold marker, history table, partial unique constraint on live auctions per product, drop the FK to `Shop`, ownership registry entries (`AuctionHistory`), `packages/contracts` schemas and event schemas, rename the money columns' API names (`…Minor`) at the DTO boundary.
3. Scheduling and lifecycle: create (with idempotency), list, read, cancel, hold job, open job, due-auction sweeper (AS-01–AS-09, AS-35).
4. Bidding: the serialized durable bid step, idempotency, rate-limit and fail-closed behaviour, shill guard through R1, `my-bid`, anti-sniping, outbox events per bid, post-commit realtime (AS-10–AS-26, AS-40, AS-41). Delete the Lua scripts, the stream, the relay, the `auction:active` set and the Redis state.
5. Close and settlement: conditional close with history, events, winner-order request job through S10's command (coordinate the S10 amendment in the same change), the `orders.events` consumer with inbox and DLQ, second chance, stock return job (AS-27–AS-39, AS-42).
6. Public reads: cached view, batch route, bid history with cursor and aliases, realtime messages with `version` (AS-43–AS-48).
7. Operations: metrics and alerts, partition job, domain barrel cleanup, delete the old e2e spec and write the seven new ones plus the two unit specs, update the notifications test for `priceMinor` (AS-49–AS-52); run `check:boundaries` and `check:table-ownership --strict`.
