## BREAKING (changes behaviour or an API/UI contract that exists today)

- [BREAKING] The live state is a Redis hash mutated by a Lua script, with a Redis stream drained into Postgres by a write-behind relay (`infra/place-bid.lua.ts`, `infra/bid-relay.service.ts`); the stream is trimmed with `MAXLEN ~ 1000000` and a Redis failover can lose acknowledged bids → the durable store decides every bid: one atomic, per-auction-serialized step that records the bid, updates price/leader/version and writes the outbox row; Redis keeps only the cache, the limiter and realtime fan-out; the Lua scripts, the stream, the relay and the `auction:active` set are removed → note §22 (conditional update in one transaction, "row-level locking is fine at hundreds of bids/s"), III.6 (invariants in one strongly consistent store), III.9 (caches never source of truth); an acknowledged bid must never be lost.
- [BREAKING] `POST /auctions/:id/bids` has no `Idempotency-Key` → required (8–128 chars), replay returns stored answer, in-flight `409`, different body `422`; creating an auction requires it too → V.6 (bids are named explicitly), a double-clicked create would take two units.
- [BREAKING] Bid refusals answer `200` with `outcome: 'too_low'` / `'ignored'`, a closed auction answers `422` (`auction.service.ts:107-114`) → `422 bid_too_low {minimumMaxAmountMinor}`, `422 bid_not_increasing`, `409 auction_closed {status}`, `409 auction_not_started`; stable `code`s in problem+json → V.3/V.4 (a state conflict is `409`, semantic failures `422`), clients need a minimum to show.
- [BREAKING] Money fields `startingPrice`, `minIncrement`, `reservePrice`, `maxAmount`, `price` (and event field `price`) → `…Minor` names, responses through `packages/contracts` schemas, ORM row never returned (`auctions.controller.ts:23-27` returns the created model) → III.8, V.1, V.2 and the S10/S11 naming.
- [BREAKING] The view and bid response expose `leaderId` (a user ID) publicly (`auction.service.ts:110,122-124`) → `leaderAlias` (stable per auction, not reversible); a bidder's own maximum only through authenticated `GET /auctions/:id/my-bid` → V.1 ("internal IDs not meant for clients"), bidder privacy; the public history never shows IDs.
- [BREAKING] Reserve is compared with the *visible price* at close (`auction.jobs.ts:58`), so a leader whose maximum exceeds the reserve can lose the auction as "unmet" → when the leader's maximum ≥ reserve the price rises to at least the reserve, `reserveMet ⇔ price ≥ reserve`; the reserve amount is never public, only `hasReserve`/`reserveMet` → the usual auction-site rule (a maximum that covers the reserve meets it); fairness to the bidder, and the seller never sells below the reserve.
- [BREAKING] A bid with maximum ≤ own current maximum answers `200 ignored` (`place-bid.lua.ts:25-27`) → `422 bid_not_increasing` → a silently ignored bid hides a client bug.
- [BREAKING] `startsAt` is stored but never enforced; an auction is `OPEN` the moment it is created (`auction.service.ts:60-76`) → status `SCHEDULED` until `startsAt`, bids before it are `409 auction_not_started`, minimum lead 1 min, duration 10 min–30 days; statuses `SCHEDULED, OPEN, CLOSED, SECOND_CHANCE, SOLD, UNSOLD, CANCELLED` replace `OPEN, CLOSED, UNSOLD, CANCELLED` (check constraint by expand/contract, `CLOSED` rows of today keep meaning "awarded") → the schema promises a start; III.7 (discriminated union state machine).
- [BREAKING] The unit leaves and returns by raw `UPDATE "Product" SET quantity = quantity ± 1` (`auction.service.ts:54-57`, `auction.jobs.ts:70,99`) → only `applyStockDelta` with `auctions:<id>:hold` / `:return`, driven by durable intent (job written in the transition's transaction), and the auction opens only once the unit is held; a stuck hold cancels the auction after 5 min → IX.4 (D-12), S05's guarantees, no network I/O in a transaction (III.3), exactly-once return.
- [BREAKING] The winner's order is built by the auction inside its own transaction: inserts into `BisOrder`, `BisOrderItem`, `ShopOrder`, plus `orders.transition` (`auction.jobs.ts:60-76,106-121`) → after the close commits, one idempotent command to S10 (`createFixedPriceOrder`, key `auction:<id>:winner`) with retries ≤ 8 and a dead-letter state → IX.4 (one transaction writing two domains is banned), IV.3 (saga with an idempotent command), and today a crash or retry between the two writes cannot be recovered.
- [BREAKING] Second chance is a job at `reservedUntil + 60 s` that reads `BisOrder` and picks the runner-up with raw SQL (`auction.jobs.ts:85-104,119`), takes the winner window (48 h) for the offer too, ignores the reserve and the shill guard, and returns the unit when none → event-driven on S10's `order.cancelled` (and permanent order rejection), runner-up must meet the reserve and not be a shop member, offer at their maximum, 24 h window, at most one offer; `auctions.second-chance` job removed → no cross-domain read (D-7/D-12), no polling, no extra delay when the winner cancels at once, and the reserve means the seller never sells below it.
- [BREAKING] `GET /auctions/:id/bids` runs raw SQL in the controller, returns at most 50 rows, no cursor (`auctions.controller.ts:45-54`) → application service, keyset pagination `limit ≤ 100`, default 20, opaque cursor, aliases, only price-changing bids → II.1, III.10, V.1.
- [BREAKING] `skipThrottle: true` on the public view (`auctions.controller.ts:31`) → cached view (1 s, single-flight) plus policy `auctions.read.ip` 600/min fail open; `Cache-Control: public, s-maxage=1` → an uncached public read of a hot auction is a DoS lever; III.9.
- [BREAKING] `leader_changed` is emitted by the relay once per batch and misses intermediate changes (`bid-relay.service.ts:117-123`); no `bid_placed`, `created`, `opened`, `second_chance_offered`, `sold`, `unsold`, `cancelled` events although the domain map lists `auction.bid_placed` → every state change writes its event in the same transaction, `leader_changed` for every real change, all payloads carry `auctionVersion`; `AuctionLeaderChanged.price` → `priceMinor`; `AuctionClosed` gains `status`, `currency`, `reason` → IV.4, P0607; the notification test (`notifications.e2e-spec.ts:120`) updates its payload.
- [BREAKING] The close job freezes the auction in Redis first, then commits to Postgres, and uses `Date.now()` (`auction.jobs.ts:47,107`); the post-close `setTimeout` to `srem` is lost on restart (`:81`) → the close is one conditional update in Postgres with the injected clock, serialized with bids; no in-process timers → exactly-once close (P0311), VII.2 (frozen time).
- [BREAKING] No seller cancel route; no seller list/read routes → added (`POST …/cancel`, `GET /shops/:shopId/auctions[/:id]`) → illegal-transition and IDOR coverage (VII.3), and a seller needs to see their auctions.
- [BREAKING] Only a plain `@Firewall()` and a `RateLimit('auction.bid')` guard a bid, and a limiter outage is unspecified → keep policy `auction.bid` (fail closed): limiter down → `503 bid_unavailable` + `Retry-After: 2`; reads keep working → fail-closed policy already declared; documented behaviour and a forced-fault test (VII.9).
- [BREAKING] `Auction.shopId REFERENCES "Shop"("id")` in the migration (`migrations/20261001180000-auctions.js:16`) → foreign key dropped (plain ID) by expand/contract → IX.4 (no FK across owners).
- [BREAKING] One live auction per product is not enforced → partial unique constraint on `(productId)` for non-terminal statuses → III.6; double-selling the same unit.
- [BREAKING] The domain barrel exports `AuctionModel` and `AuctionsWorkerModule` provides `OrderService`, `FlashStockService` and `ORDER_MODELS` itself (`index.ts:7`, `auctions-worker.module.ts:12`) → barrel exports modules and event contracts only; the worker module imports nothing from orders but the R1 command service → X.4, D-7, D-8.
- [BREAKING] `auctions.e2e-spec.ts` calls `AuctionService`/`AuctionJobs`/`BidRelay.flush` directly, injects `ShopModel`, `ShopMembershipModel`, `UserModel`, `BisOrderModel`, and stops the relay by hand → rewritten through HTTP (`supertest`), seeding by shared fixtures and exported services, jobs invoked through their handlers → VII.2, VII.8, D-7.

## CONTRACT (decides something another capability must provide or consume)

- [CONTRACT] S10 said "S21 will state what it needs" for the winner's checkout → S21 needs `OrderCommandService.createFixedPriceOrder({idempotencyKey, buyerId, shopId, productId, quantity: 1, unitPriceMinor, currency, titleSnapshot, reservedUntil, origin: {kind: 'AUCTION', ref, step}, stockHandling: 'EXTERNALLY_HELD'}) → {orderId, status: 'RESERVED', reservedUntil, replayed}` (R1, exported by `orders`; idempotent ≥ 90 days; permanent rejection `OrderCommandRejectedError {code}`); S10 to add it by amendment → the unit is already out of regular stock, so S10 must not move stock on create, cancel or expiry; fixed price, no discounts; the winner then pays through the normal S13 path.
- [CONTRACT] S21 consumes `order.paid` and `order.cancelled` from `orders.events` (key `orderId`, S10's shapes incl. `orderVersion` and `reason`) and matches them to its stored `winnerOrderId` → S10 must keep these two events and fields stable and must emit `order.cancelled` for an `EXTERNALLY_HELD` order on expiry/cancel without a stock event → second chance and sold are driven by them; no polling of S10's tables.
- [CONTRACT] S05 operation IDs `auctions:<auctionId>:hold` (`auction.hold`, −1) and `auctions:<auctionId>:return` (`auction.return`, +1); idempotency retention ≥ 3 days (S05 gives 30) → exactly-once unit hold and return; hold failures `insufficient_stock` cancel the auction.
- [CONTRACT] S03 `ShopAccessService.getRole(shopId, userId)` (R1) replaces `MembershipService.role`; any non-null role is "member"; must answer within 200 ms; the call is per bid (no N+1), tenancy may cache → shill guard on the bid path must be cheap and fail closed.
- [CONTRACT] S18 route guard `RequiresShopEntitlement('auctions')` on create only (existing behaviour); bidding and closing never re-check the plan → a downgrade must not strand live auctions.
- [CONTRACT] Event `auction.leader_changed` field `price` → `priceMinor` (plus `currency`, `auctionVersion`, `shopId`, `productId`); new `auction.closed`, `auction.second_chance_offered`, `auction.sold`, `auction.unsold`, `auction.cancelled`, `auction.opened`, `auction.created`, `auction.bid_placed` on topic `auctions.events` (key `auctionId`) → S28 (outbid, won, second chance, sold notifications) and community (`auction_started` feed item, today a kind with no producer) consume them; S28's spec must read the payloads in `spec.md`.
- [CONTRACT] `GET /auctions?productIds=` (≤ 100 ids, anonymous) is the BFF's R2 target; the BFF (S48) composes the product page with it → one call for N products; no per-row calls.
- [CONTRACT] The web capability for auction pages must: anchor the countdown on `serverTime`, ignore realtime messages whose `version` is not above its own, show the problem codes (`bid_too_low` with `minimumMaxAmountMinor`, `auction_closed`, `shill_bid_forbidden`, `rate_limited`, `bid_unavailable`), send an `Idempotency-Key` per bid attempt and reuse it on network retry → exactly-once bids need the client's key.
- [CONTRACT] Realtime topic `auction:<id>` stays public (existing policy `() => true`) and carries only `price` and `closed` messages with `version` → S51's registry.
- [CONTRACT] Rate-limit registry: keep `auction.bid` (10 per 10 s, token bucket, per user, fail closed); add `auctions.read.ip` 600/min fail open → S50's registry file today only has `auction.bid` (`rate-limit.types.ts:48`).
- [CONTRACT] J03 (launch day journey) expects "an auction closing with the winner's checkout and the notifications each triggers" → satisfied by `auction.closed` + the winner's `RESERVED` order + S28; no extra contract.

## LOCAL (affects only this capability's internals)

- [LOCAL] Anti-snipe window 2 min, extension 2 min, cap 60 min after the original end (today's constants) → kept; only price-changing bids extend, own-max raises do not → a leader must not extend at will.
- [LOCAL] Tie on equal maximums → the earlier bid keeps the lead, price `leaderMax` → standard rule, deterministic by sequence.
- [LOCAL] Minimum increment fixed per auction; no tiered increments → simplicity.
- [LOCAL] Winner payment window 48 h, offer window 24 h, both configuration → today 48 h for both.
- [LOCAL] Second-chance price = runner-up's own maximum → today's rule and the usual one.
- [LOCAL] Bidder alias = non-reversible keyed hash of `(auctionId, userId)` truncated, shown as e.g. `Bidder 7K2Q` → stateless, stable per auction, unlinkable across auctions.
- [LOCAL] Bid sequence = auction `version` of accepted bids (gapless); rejected bids consume none → ordering proof for P0607.
- [LOCAL] Leader re-check at close and at offer time (shill guard) uses the same R1 lookup, done before the close's transaction → no network call inside a transaction.
- [LOCAL] Hold deadline 5 min after creation; hold and return are retried by the due-auction sweeper → keeps jobs simple.
- [LOCAL] `Bid` stays range-partitioned by month; a daily single-run job creates the current month and 3 ahead (today only the migration calls `bid_ensure_partitions`, so after about 4 months every bid lands in `Bid_default`) → P0318; default partition kept as the catch-all with a gauge.
- [LOCAL] The unique index `(auctionId, version, createdAt)` cannot enforce uniqueness across partitions; uniqueness of `(auctionId, sequence)` comes from the serialized per-auction version bump → noted, tested by AS-19.
- [LOCAL] Sellers see no bidder identity (only alias, then the order's buyer through S10) → privacy.
- [LOCAL] Retention of bids/auctions ≥ 24 months, no archival job in this capability → disputes; out of scope.
- [LOCAL] Max amount 1,000,000,000,000 minor units, below the JS safe-integer range → money stays exact.
- [LOCAL] `Idempotency-Key` retention follows the platform default (24 h) → S54.
- [LOCAL] Public list `GET /auctions` supports only `productIds`; browse/search of auctions is a discovery concern (R3, later) → scope.
