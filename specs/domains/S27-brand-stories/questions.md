# Questions and decisions — S27 Brand stories CMS

Taken unattended under the decision policy (most production-grade option the notes and constitution support). Sorted by impact: BREAKING first, then CONTRACT, then LOCAL. Review BREAKING and CONTRACT lines first. Line references are to `packages/backend/libs/domains/content/` as of writing.

## BREAKING

- [BREAKING] Public read route and cache key (today `GET /stories/:shopSlug/:slug?locale=` with `Vary: Accept-Language` and `max-age=60`, `api/stories.controller.ts:67,72,75`) → `GET|HEAD /stories/:shopSlug/:slug/:locale`, no `Vary`, `Cache-Control: public, s-maxage=300, stale-while-revalidate=86400` exactly as the notes → notes §5 says locale in the path for cacheability; `Vary: Accept-Language` fragments the CDN while the server ignores that header; `max-age` cannot be purged from browsers and defeats "live within a minute".
- [BREAKING] Public story body → adds `canonical`, `alternates` with `x-default`, `preview:false`; 404 becomes `s-maxage=10` problem+json → hreflang data in the API is a notes requirement; `x-default` and canonical are what a fallback response needs for SEO.
- [BREAKING] Status model (today `SCHEDULED` is a status, `application/stories.service.ts:68`; a scheduled republish of a live story sets it to `SCHEDULED` and the public read, which filters `status='PUBLISHED'`, returns 404, `:115`) → status `DRAFT|PUBLISHED|ARCHIVED` plus a separate `scheduledAt`; migration drops `SCHEDULED` from the check (expand/contract) → the old model takes a live story offline when a republish is scheduled.
- [BREAKING] Write contracts (today no concurrency or replay protection: `PUT drafts` overwrites, `publish` takes `at?` only) → drafts require `expectedRevision`, publish and schedule require `expectedVersion` and an `Idempotency-Key`; wrong values answer `409`/`422` → two editors and client retries are normal for a team CMS; a replayed publish today creates a duplicate version with identical content; III.6/III.7, V.6 spirit.
- [BREAKING] Scheduling in the past (today silently publishes now, `:67`) → `422 schedule_in_past`; more than 365 days → `422 schedule_too_far` → a wrong clock or timezone on the client should fail loudly, not publish a reveal early.
- [BREAKING] Scheduled-run safety (today only a delayed job; a lost job means the reveal never happens, no failure state) → a one-minute due-schedule sweep as safety net, permanent failure recorded as `scheduleFailure` plus `story.schedule_failed` → launch reveals are time-critical; VIII.6 single-run idempotent job.
- [BREAKING] Preview token (today a JWT signed with the global session `jwt_secret`, no audience, no pinned algorithm, in a query string, `:145,151`; response is raw draft columns; mintable with `products.read`, `api/stories.controller.ts:54`) → dedicated signing key, pinned algorithm, audience `story-preview`, header `X-Preview-Token`, response in the public story shape with `preview:true`, `noindex`, `no-referrer`, mint requires `products.write`, locale in the body → a shared key lets a preview token be confused with session tokens; query strings leak into logs and referrers; viewers could read drafts; VIII.7.
- [BREAKING] Sitemap paging and capacity (today `OFFSET page*50000` to find a start id and `count(*)`, `:163,187`, with 50,000 stories per file and one `<url>` per locale, so a file can hold 1,000,000 URLs) → a never-changing position allocated at first publish, 2,500 stories per file (50,000 URLs at the 20-locale cap), keyset batches, no count; abnormal termination on mid-stream failure → the sitemap protocol caps a file at 50,000 URLs; offset pagination on an unbounded table is forbidden (III.10); a clean `</urlset>` after an error silently truncates the crawl.
- [BREAKING] Revalidation webhook signature (today HMAC over the body only with `x-revalidate-signature`, body `{tags, at}`, `infra/cache-invalidation.ts:73-80`; skipped silently without a secret) → headers `X-Revalidate-Timestamp` and `X-Revalidate-Signature` over `"<timestamp>.<raw body>"`, body `{tags, eventId}`; production refuses to start without secrets → V.8 and a body-only signature is replayable forever.
- [BREAKING] Event payloads and consumer (today `story.published {storyId, shopId, slug, version, locales}`, no archive event, consumer purges without an inbox, no failure policy, `infra/cache-invalidation.ts:61-82`) → adds `shopSlug`; new `story.archived` and `story.schedule_failed`; consumer clears the origin entry first, de-duplicates by `eventId`, retries with a bounded policy and dead-letters → IV.4/IV.5; purging the CDN before the origin entry lets the CDN re-cache the stale version for 5 minutes.
- [BREAKING] Shop data (today `SELECT slug FROM "Shop"` and `JOIN "Shop"` at `application/stories.service.ts:100,115,175`; a foreign key `Story.shopId → Shop.id` in `migrations/20261001350000-stories.js:13`; the e2e spec imports `ShopModel`) → R3 copy `ShopRef` fed by tenancy events (public read, sitemap), R1 `getShopsByIds` for the single write-path lookup; FK dropped; new table `StoryShop` owned by `content` in `db/ownership.ts` → IX.4 and IX.7; this is the line `check:table-ownership` reports for `content`.
- [BREAKING] Errors (today `BadRequestException('Nothing to publish')`, `:92`, `BadRequestException` for blocks `:54`, a unique violation on duplicate slug surfaces as 500, `:43`) → problem+json codes: `invalid_blocks` 422, `no_drafts` 422, `slug_taken` 409, `revision_conflict`/`version_conflict` 409 → V.3, V.4; a duplicate slug must not be a 5xx.
- [BREAKING] Origin cache (today TTL 3600 s, miss path not single-flight, store failure fails the read, `:111-121`) → TTL 60 s, single flight per story, cache failure falls back to the durable store → III.9 (caches never the source of truth) and the "within a minute" goal when an invalidation is lost.
- [BREAKING] Controller content (today the controller writes headers, builds XML and loops the stream, `api/stories.controller.ts:66-122`; services issue raw SQL through `@InjectConnection`, `application/stories.service.ts:2`) → thin controllers (II.1), repositories behind domain ports in `infra/` (I.2, III.1), sitemap and header logic in application/domain code; every query carries `shopId` (today `own()` then queries by `storyId` alone, `:192`) → constitution I, II.1, III.1, III.4.
- [BREAKING] Barrel (today exports `StoriesWorkerModule`, `StoryCacheInvalidator`, `StoryCacheModule`, and `StoriesService` is exported by the module, `index.ts:7`, `stories.module.ts:12`) → barrel exports only Nest modules for the apps; no R1 service; no consumer or purger class → X.4 and debt D-8.

## CONTRACT

- [CONTRACT] Who owns the story pages `/<locale>/brands/<shopSlug>/stories/<slug>`, the revalidation route `/api/revalidate`, and the staff editor UI? → no web capability does today; this spec defines only the backend contract (public API, revalidation call, tags) and asks W-capability planning to assign them (suggest W02 for the reader pages and route, W04 for the editor) → without an owner the backend half has no UI journey; recorded as a gap, not invented here.
- [CONTRACT] Revalidation receiver rules → the web side must verify `HMAC-SHA256("<timestamp>.<raw body>")`, reject timestamps older than 5 minutes, and treat the call as idempotent → V.8; S27 cannot enforce it.
- [CONTRACT] S03 shop events as the R3 source → consume `tenancy.shop_created`, `shop_updated`, `shop_status_changed`, `shop_deleted` exactly as S03 lists them (`shopVersion` as version guard); slug assumed immutable while the shop exists → S03 forbids slug changes in `PATCH` (AS-08) and lists content among "shop-owning domains" that read shop name and slug from events.
- [CONTRACT] S03 export of other domains' data → not provided: S03 defines the shop export shape without per-domain contributions, so S27 only purges on `shop_deleted` → nothing to conform to yet; add a contribution when S03 defines one.
- [CONTRACT] Permission names → reuse `products.read`/`products.write` (S03 FR-020 fixed set) instead of new `stories.*` permissions → a new permission is an S03 amendment with no benefit here.
- [CONTRACT] S05 batch query → `getProductsByIds(ids, {shopId})` with presence only; archived products accepted; no revalidation on product events → S05 AS-48/AS-50 provide it; product data is composed at render (R2), not cached by S27.
- [CONTRACT] S49 permanent-failure signal and single-run sweep → S27 needs a non-retryable failure outcome for handlers and a cron facility with leader or lock → AS-47, AS-46; S49's spec is not written yet.
- [CONTRACT] S50 policy `content.write.shop` (120 per minute per shop, fail closed) → declared here, to be added to S50's registry → S50's spec is not written yet.
- [CONTRACT] S52 conditional GET and single flight → S27 supplies a strong ETag; the cache toolkit answers `304` (list, weak, `*`) and provides single-flight cache-aside → pattern P0410 lists S52 as co-owner.
- [CONTRACT] Platform idempotency-key facility owner → assumed S54 with the V.6 contract of S10 FR-012 (header `Idempotency-Replayed`, 24 h) → S10 and S27 both need it; the owner capability is not written yet.
- [CONTRACT] Event topic and envelope → `stories.events`, key `storyId`, S53 envelope; S28 may consume `story.schedule_failed` → not required for S27.
- [CONTRACT] No R1 export from `content` → no other domain needs story data synchronously; the BFF/front end reads the public HTTP API → keeps `content` a leaf in the domain graph (IV.2).

## LOCAL

- [LOCAL] Archive instead of delete → no delete endpoint; `ARCHIVED` is the take-down; versions kept until the shop is deleted → deleting published content breaks inbound links and history.
- [LOCAL] Limits → 5,000 stories per shop, 20 locales, 200 blocks, 256 KiB per draft, 1 MiB body, 365-day schedule horizon, 30-minute preview, all configurable.
- [LOCAL] Slug and default locale immutable → URLs and the fallback chain depend on them.
- [LOCAL] Publish requires a default-locale draft and rejects "nothing changed" → avoids a live story that cannot fall back and no-op versions.
- [LOCAL] Product references checked only at publish (S05 R1, 2-second timeout, fail closed with 503) → drafts may reference anything while being written.
- [LOCAL] Restore replaces all drafts with the version's locales → predictable; revisions advance.
- [LOCAL] `DELETING` shops cannot publish (S03 gate) but their live stories stay public until `shop_deleted` → S03 allows reads in `DELETING`.
- [LOCAL] Both tags (`story`, `shop`) purged on every publish and archive → brand index pages refresh; over-purge cost is negligible at ~1k changes per day.
- [LOCAL] Video hosts stay `www.youtube.com`, `player.vimeo.com`, `stream.marketplace.dev`, matched on the parsed host; images only need `https` → host allowlist for images is not in the notes.
- [LOCAL] Sitemap `s-maxage=3600` → crawlers poll slowly; an archived story may stay listed up to an hour.
- [LOCAL] Consumer dead-letters after 8 deliveries; CDN calls ≤ 30 tags, 5-second timeout, ≤ 3 in-call retries.
- [LOCAL] Staff reads added (list, detail, versions) → the draft editor cannot work without them; additive.
- [LOCAL] No unit-tested glue → unit specs only for blocks, locale chain, state table, ETag matching, sitemap positions and XML escaping, signature scheme.
