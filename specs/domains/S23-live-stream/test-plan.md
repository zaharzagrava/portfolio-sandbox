# Test Plan: S23 — Live Launch Stream (domain `launch-events`)

Constitution VII.8 table: one row per acceptance scenario in [`spec.md`](spec.md) (54 rows), each proven at the lowest layer that can prove it. A dash means the layer does not test that scenario.

- API e2e files live in `packages/backend/libs/domains/launch-events/`. Each file's top-level `describe` names its feature (VII.8). They boot the real `LiveModule`, `LiveWorkerModule` (publisher and reconcile job are invoked through `tick()` / the job handler with the injected clock), `LiveProjectorModule`, `LiveGatewayModule` and `LiveTopicsModule` with the production prefix, `ValidationPipe`, problem+json filter and interceptors, against real Postgres (real migrations), Redis, Kafka stand-in and DynamoDB Local from `docker-compose.test.yaml`. SSE assertions open real event connections over HTTP (`supertest` with a streaming parser) on the booted gateway module.
  - `live-streams.e2e-spec.ts` — describe "Live stream: lifecycle, authorization and pinned commerce"
  - `live-comments.e2e-spec.ts` — describe "Live stream: comment ingest, moderation and mutes"
  - `live-reactions.e2e-spec.ts` — describe "Live stream: reactions, statistics and viewer counts"
  - `live-delivery.e2e-spec.ts` — describe "Live stream: sampling, batching, snapshots and event connections"
  - `live-history.e2e-spec.ts` — describe "Live stream: history, async moderation and consumers" (includes the VII.4 duplicate-delivery and invalid-payload tests of both consumers)
  - `live-operations.e2e-spec.ts` — describe "Live stream: degradation, configuration, observability and domain isolation"
- Shops, memberships, products and users are seeded only through the shared fixture helpers, the identity fixture (`SessionIssuer` / `issueTokensFor` replacement), tenancy's and catalog's exported services; no spec injects `ShopModel`, `ShopMembershipModel`, `ProductModel` or `UserModel` (D-7). Streams are created through the staff route.
- Only system edges are faked: identity token verification, the toxicity classifier port (scores and timeouts forced), the realtime transport and the history store where a fault is forced, and the clock. Faults (fast store wiped, event stream refusing writes, outbox refused, history store throttling) are injected through the test module's switchable store wrappers at the system edge, never by stubbing a repository.
- Unit specs sit beside the code under `domain/`, are table-driven (`it.each`) and exist only for pure logic (VII.5): `reservoir.spec.ts`, `moderation.spec.ts`, `comment-text.spec.ts`, `live-state.spec.ts`, `window-composer.spec.ts`, `author-handle.spec.ts`, and the client reducer in `packages/contracts/src/live/live-reducer.spec.ts` (`fast-check` for order and duplicate insensitivity). Controllers, repositories, services, consumers, gateway and adapters get no unit tests.
- UI journey (Playwright): none. No web capability in `scripts/sdd/capabilities.tsv` covers live-stream pages and `packages/web` has no live screen, so VII.7 has no client flow yet. The cross-domain happy path (booking, flash sale, live comments, auction) belongs to J03 (`packages/backend/test/journeys`). When a web capability adds the stream page, it adds one journey `packages/web/e2e/live-stream.spec.ts` (open a stream, see the snapshot, post a comment, see the pin, see counts) and re-tests none of the edge cases here.
- Static gates (VII.1): `tsc --noEmit` and ESLint for `packages/backend` and `packages/contracts`; `pnpm check:boundaries`; `pnpm --dir packages/backend check:table-ownership --strict` (AS-54); `pnpm check:module-graph`; `pnpm check:model-registry`.
- Gate 9 (VII.9) fallback/degradation tests that force the fault: AS-10 (slow viewer), AS-11 (viewer cap), AS-20 (limiter down), AS-23 (event stream down, feed write failing), AS-24 (cold cache, unknown IDs), AS-30 (limiter down), AS-31 (publisher takeover), AS-43 (history throttling), AS-47 (classifier timeout), AS-49 (fast store wiped), AS-51 (store outages).
- Concurrency tests use `Promise.all` and assert that exactly the allowed number succeed and the invariant holds (VII.3): AS-07, AS-22, AS-24, AS-27, AS-34, AS-38, AS-39. Each is repeated at least 20 times in the same test.
- Async consumers (VII.4): the history writer and the async-moderation consumer each get a duplicate-delivery test and an invalid-payload test (AS-44, AS-45, AS-47); the reconcile job has the duplicate/concurrent-run test (AS-50).
- The k6 SSE fan-out `scripts/load-tests/live-stream.test.js` (`pnpm loadtest:live-stream`: 5,000 connections plus a comment flood) proves SC-003 and SC-014; it is an ops artifact, not part of this table.
