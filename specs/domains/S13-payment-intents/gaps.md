## E. Migrations (expand/contract, III.11)

1. Expand: add `Payment.version`, `Payment.currency`, `Payment.orderId` (copy of `bisOrderId`), `Payment.chargeAttemptedAt`, `Payment.requiresAction`, `Payment.failureCode`, `Payment.clientSecret` (nullable, cleared on final status), `Payment.paymentMethodToken` (nullable, cleared when final), a unique index on `orderId`, new enum values `REFUND_PENDING` (and use of `CANCELLED`), new tables `PaymentHistory` and `PayableOrder` (order copy), each with its entry in `db/ownership.ts` under `domain:payments`, each migration with a `lock_timeout`.
2. Backfill `orderId`, `currency` (`'USD'` for old rows) and `amount` meaning (already minor units); backfill history with one synthetic row per existing payment.
3. Switch code to the new columns; contract later: drop the foreign key and association to orders, drop `bisOrderId` and the unique `idempotencyKey`.
4. Retire topics `payments.requests`, `payments.responses` and `payments.dlq` after consumers move to `payments.events` (keep a Sunset period only if a deployed consumer still needs it).

## F. Suggested order of work

1. Boundaries first: run `check:table-ownership`, add the order copy and its consumer (A5, A17, C3), drop the association and the barrel exports (D-7, D-11, D-17), remove the stock SQL (A6, C1, C2).
2. Domain core: state machine with versions and history (A14), money and classification rules, backoff, provider port with answer validation (A13, A24), clock (A26).
3. Provider adapter: per-operation breakers, call limits, no SDK retries, correct "not sent" versus "sent" (A9, A12, A23, A30).
4. HTTP accept path with idempotency (A1–A3, A27 with S54), rate limits (A21), response contracts.
5. Processor: charge command, attempts, crash recovery, retries (A4, A8); resolver and sweep (A10, A11).
6. Events and outbox with envelopes and no secrets (A16); ledger link through S14 (A15).
7. Saga: order-event compensation, refund consumer and refund execution (A17); status service with refresh (A18).
8. Reads and push; remove the old routes, the SSE stream and the gateway route (A19, A20); web types.
9. Observability, config validation, graceful shutdown (A22, A30, A31).
10. Replace `payment.e2e-spec.ts` by the specs of the test plan (A29); finish with the static gates.
