# Questions and decisions: S47 — "Ask this product" and shop help center

Decisions taken unattended under the decision policy (production-grade, notes and constitution first). BREAKING first, then CONTRACT, then LOCAL. Format: `question → default → why`. Notes: `docs/showcase/sections/SD-43-rag-help-center.md` and `interview-prep/10-system-design/10-ai-applications.md` §43. Code references are to `packages/backend/libs/domains/assistant/`.

## BREAKING

- [BREAKING] A product of another shop in a document create answers `403` (`application/knowledge.service.ts:242-248`) → `404 not_found`, same body as an unknown product; ownership is part of the catalog lookup (`getProductsByIds(ids, {shopId})`) → V.4 (hide existence across tenants), III.4 (principal in the lookup).
- [BREAKING] Product ownership and the product's shop come from raw SQL on catalog's `Product` (`knowledge.service.ts:246`, `api/knowledge.controller.ts:81`) → S05's `getProductsByIds` (R1) → IX.4 (D-12).
- [BREAKING] `KnowledgeDocument` has foreign keys to `Shop` and `Product` (`ON DELETE CASCADE`, migration `20261002160000-knowledge-base.js`) → drop both; documents are removed by consuming `catalog.product_deleted` and `tenancy.shop_deleted` (R3) → IX.4 forbids foreign keys across owners; deletion becomes asynchronous (≤ 60 s) instead of a cascade.
- [BREAKING] Document responses are raw rows: `storageKey`, `contentHash`, `indexedHash`, `embeddingModel`, `createdBy`, raw `error` text (`knowledge.service.ts:65-125`, the controller returns rows at `api/knowledge.controller.ts:44-59`) → explicit `knowledgeDocumentSchema` `{id, title, visibility, productId, format, status, failureCode, chunkCount, createdAt, updatedAt}` → V.1; internal paths and parser messages must not reach clients.
- [BREAKING] `failure` is a free-text message cut to 500 chars (`knowledge.service.ts:151-152,181,190,196`) → stable `failureCode` (`not_a_pdf`, `unparseable`, `no_text`, `too_many_pages`, `too_many_chunks`, `size_mismatch`, `embedding_unavailable`) → sellers can act on it; no parser internals in responses.
- [BREAKING] `GET …/documents` returns an array capped at 200 with no cursor (`knowledge.service.ts:111-113`) → `{items, nextCursor}`, `limit` ≤ 100, default 20, keyset `(createdAt DESC, id DESC)`, `status` filter → III.10; `GET …/documents/:documentId` added for status polling.
- [BREAKING] Create answers `201` also when the document is a duplicate → `201` new, `200` with `deduplicated: true` for a repeat → honest status codes; replay is not a creation.
- [BREAKING] `…/uploaded` on a document that is not `AWAITING_UPLOAD` silently returns it, a missing upload is `400` (`knowledge.service.ts:102-107`) → replays on `QUEUED/PROCESSING/READY` are `200` with no second task, `FAILED` → `409 invalid_transition`, missing bytes → `409 upload_missing` → III.7 and VII.3 (illegal transitions are `409`, replays idempotent).
- [BREAKING] Delete reads the document then updates unconditionally (`knowledge.service.ts:128-134`) → single conditional update `WHERE status <> 'DELETED'` inside the transaction; of two concurrent deletes exactly one is `204` → III.6/III.7.
- [BREAKING] A `FAILED` document is retried only by an incidental redelivery (`ingest` accepts `FAILED`) → explicit `POST …/retry` (`202`, only from `FAILED`), and ingestion no longer claims `FAILED` rows → the only way out of `FAILED` is a decision by the seller or a re-index.
- [BREAKING] Several ingest workers can run the same document at once (claim sets `PROCESSING` again for `PROCESSING` rows, `knowledge.service.ts:138-141`) → a 5-minute lease; a second delivery is acknowledged without effect; an expired lease is taken over → one paid embedding pass per document; III.6.
- [BREAKING] Transient provider errors leave the row `FAILED` and rethrow (`knowledge.service.ts:178-186`) → back to `QUEUED` on a transient error; `FAILED(embedding_unavailable)` only when the queue dead-letters after 5 receives; previous passages untouched → a `FAILED` flag on a document that is still serving is a lie, and a retry must not make a good index worse.
- [BREAKING] `VoyageEmbedder` retries 5 times with backoff inside the call (`infra/embedder.ts:43-48`) while the queue also redelivers → embedder has no internal retry; question path degrades to keyword-only; ingestion retries by redelivery only → IV.6 (retry at exactly one layer, ≤ 3 in synchronous paths).
- [BREAKING] Retrieval scope is applied in the candidate queries but the hydration query loads by id with `JOIN KnowledgeDocument` and checks status afterwards (`infra/retriever.ts:98-106`) → hydration repeats the scope predicate and `status = 'READY'`; candidates also filter on document status in the same query → III.4 ("never post-filter"), defense in depth.
- [BREAKING] Voyage failure on the question makes the whole ask fail → after 3 s the retrieval degrades to keyword-only (`sources.mode: "keyword"`) → notes: "FTS catches exact terms"; availability over completeness; VII.9 forced path.
- [BREAKING] Help-center ask meters with `subjectId = shopId` (`api/knowledge.controller.ts:89`) → the member's user id as `subjectId`, shop as `scopeId` → usage belongs to a person; a shop id in a user field corrupts S18 keys.
- [BREAKING] Ask rejections `BUSY` arrive as an in-stream `error` after `sources` (`application/answer.service.ts:78-82`) → `429 assistant_busy` problem+json before the stream; in-stream errors only `PROVIDER_UNAVAILABLE`, `TIMEOUT`, `INTERNAL` → a rejected request must leave no half-sent stream; web already branches on status for `429`.
- [BREAKING] The in-stream `done` has `{citations}` only → `{citations, grounded}`, `sources` event becomes `{mode, items}` instead of a bare array → additive field but the array becomes an object; W02's `AskProduct` must read `items`. `grounded` lets the UI warn when the model cited nothing.
- [BREAKING] The model call is metered by `LlmMeter` (direct billing call, `UsageService` re-provided in `knowledge.module.ts:39`) → S46's `LlmCallRecorder` (outbox `llm.call_completed`), purpose `rag`, metric `llm.rag.tokens`; failed, refused and aborted calls are recorded too → D-14; S46 questions already decide the recorder.
- [BREAKING] No moderation of the question or of the output (module has none) → input moderation (sensitive data, categories; fail closed, 200 ms) and per-chunk output moderation via S46's port → the notes require moderation of input and output; seller documents are untrusted, so output moderation matters here.
- [BREAKING] Inline markdown limit is 20 MiB although the request body is far smaller in practice (`knowledge.service.ts:13,67`) → 1 MiB inline; larger files go through the PDF upload path or are split → an unbounded JSON body is a memory and abuse risk; `400 validation_failed`.
- [BREAKING] Visibility rule `SHOP_PRIVATE` + `productId` is `400` (`knowledge.service.ts:243-245`) → `422 product_document_must_be_public` → V.4 (semantic validation is `422`).
- [BREAKING] Missing keyless `VOYAGE_API_KEY` silently selects the hashing embedder in every environment (`knowledge.module.ts:22-25`), the scripted provider likewise (S46) → startup fails in production for either; the test embedder remains for tests and local dev → a production index built from hash vectors is silently wrong forever.
- [BREAKING] Anonymous product ask is served with `skipThrottle: true` and only the `rag.ask` bucket (`knowledge.controller.ts:78`) → kept anonymous, but the product must be `ACTIVE` in an `ACTIVE` shop (404 otherwise) and the question is moderated → an archived or suspended shop's documents must not be served to the public.
- [BREAKING] The domain barrel exports `Retriever`, `LlmMeter`, `ScriptedLlmProvider` and the knowledge modules (`index.ts:8-16`) → exports `KnowledgeModule`, `KnowledgeWorkerModule`, `KnowledgeProjectorModule`, DTO types and `KnowledgeSearchService` (renamed from `Retriever`) → X.4, D-8; the eval harness imports the service from the entry point.

## CONTRACT

- [CONTRACT] S05 → R1 `getProductsByIds(ids, {shopId})` is used at create time and `getProductsByIds([productId])` at ask time; `ProductDto.status` and `shopId` assumed; S05's gaps already name S47 → matches S05's contract line 339; no new ask.
- [CONTRACT] S05/S03 events → S47 consumes `catalog.product_deleted` v1 `{productId, shopId, productVersion}` (topic `products.events`) and `tenancy.shop_deleted` v1 `{shopId}`; S47 does **not** consume archived/restored/suspended events (it checks status at ask time through R1) → fewer subscriptions, no read model; S03 FR-062 says shop-owning domains purge on `shop_deleted`.
- [CONTRACT] S03 `ShopQueryService.getShopsByIds` must carry `status` (`ACTIVE`/`SUSPENDED`/`DELETING`/`DELETED`) → used to refuse product asks for non-active shops; S03's `ShopSummaryDto` already has `status`.
- [CONTRACT] S18 must accept `llm.call_completed` with `metric: "llm.rag.tokens"` and `subjectId: "anonymous"` and treat it as platform cost with no per-user allowance → rag is rate limited by `rag.ask`, not by the monthly assistant allowance (S46 owns `llm.assistant.tokens`); otherwise anonymous asks cannot be recorded.
- [CONTRACT] S46 exports (from `@app/infrastructure/llm`) the moderation port `moderate(text, {signal}) → {flagged, category?}` with a 200 ms input deadline and the breaker primitive → S47 must not build its own; S46's spec names the port but not its location; if it stays inside `assistant` it must be exported from the entry point instead.
- [CONTRACT] S50 registry gains `rag.ingest` (30/min per shop, fail closed); `rag.ask` is unchanged (10/min per user or address, fail closed, today `rate-limit.types.ts:60`); `llm.provider.tpm` is S46's → one registry, no ad-hoc limiter calls.
- [CONTRACT] W02 must read `sources.items`, handle `grounded: false`, status `404` (product not askable), `422 input_rejected`, `429 assistant_busy | rate_limited`, `503 assistant_unavailable`, and in-stream `error {code}` → `components/product/ask-product.tsx` today branches on 429 only and treats `refusal` as an error.
- [CONTRACT] W04 (seller dashboard) owns the document-management screens; they use `POST …/documents`, the presigned upload, `…/uploaded`, polling `GET …/documents/:id` and `…/retry` → W04's source list does not name S47 yet; the journey test row stays pending until it does.
- [CONTRACT] Shared contracts live in `packages/contracts` (`knowledge*`, `ragAskRequestSchema`, `ragStreamEventSchema`); the web must import them instead of hand-written types → V.2.

## LOCAL

- [LOCAL] Reranker → not built; fused order is final → the notes list it as optional; recall gate measures the effect of any later addition.
- [LOCAL] Update-in-place of a document's content → not offered; a new upload is a new document, the seller deletes the old → hash identity keeps idempotency simple; re-index covers model changes.
- [LOCAL] Query rewriting with chat history → out of scope (single question) → the notes mark it optional.
- [LOCAL] Delete keeps a tombstone row for 30 days (no text, no bytes) → needed so replayed events and the sweep see consistent state; purged by the sweep.
- [LOCAL] Embedding model stored per passage (not only per document) → the vector candidate query must filter on it without a join.
- [LOCAL] Passage count cap 2,000 per document, 500 pages, 20 MiB → protects the embedding bill; each limit has its own `failureCode`.
- [LOCAL] Candidates 40 per list, top-k 6, RRF constant 60, similarity floor 0.3 → today's values; all configurable.
- [LOCAL] Query embedding timeout 3 s, retrieval deadline 2 s, first token 30 s, answer 60 s → shorter than S46's turn (answers are short).
- [LOCAL] Ask reads from the primary → deletes visible at once; replicas later with a stated staleness.
- [LOCAL] No answer resume buffer → answers are short; re-ask is cheap.
- [LOCAL] Statuses stay as today (`AWAITING_UPLOAD`, `QUEUED`, `PROCESSING`, `READY`, `FAILED`, `DELETED`); no new states.
- [LOCAL] Document lifecycle publishes no events → no consumer; add when a capability needs one.
- [LOCAL] Platform documents use the same markdown and PDF forms as shop documents → one pipeline.
- [LOCAL] Ingestion concurrency 4 workers per instance, 128-text embedding batches → today's values; documented as the provider-rate knob.
- [LOCAL] Moderating output per chunk uses the same context window as S46 → no second policy.
