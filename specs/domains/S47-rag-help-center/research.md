## R-4 Document lifecycle, state machine and conditional updates
**Decision** (`domain/document-state.ts`, single table of legal moves, FR-003): `AWAITING_UPLOAD→QUEUED`, `QUEUED→PROCESSING`, `PROCESSING→READY|FAILED|QUEUED` (transient), `FAILED→QUEUED` (retry), `READY→QUEUED` (re-index), any→`DELETED` (final). Each move is one `UPDATE … WHERE id = :id AND scope-predicate AND status = :from [AND leaseToken = :t] RETURNING …`; zero rows → re-read in the same scope: absent/`DELETED` → `404`, otherwise `409 invalid_transition` (or an idempotent `200` where the spec says so: `uploaded` on `QUEUED|PROCESSING|READY`).
**Serving predicate** (refines G25/FR-021, see Complexity Tracking): a passage is eligible iff its document has `status <> 'DELETED'` **and** `chunkCount > 0`, evaluated in the ranking query through the intra-domain join `KnowledgeChunk c JOIN KnowledgeDocument d`. `chunkCount` becomes non-zero only in the commit transaction that inserts the passages and returns to zero when the document is deleted (same transaction that removes the passages). A first-time `FAILED`, `QUEUED` or `PROCESSING` document has `chunkCount = 0` and is invisible; a document being re-indexed or whose re-index failed keeps its old passages visible (AS-25, AS-41). The wording "READY" in AS-35/AS-45 holds because a document with serving passages and no re-index in flight is `READY`.
**Alternatives**: `status = 'READY'` literal filter (hides documents during re-index, breaks AS-41); a separate `servable` flag (two sources of truth for one fact).

## R-5 Schema: expand / backfill / contract
**Decision**: three migrations, each `SET LOCAL lock_timeout = '5s'`, idempotent (`IF NOT EXISTS`), no table rewrite:
1. *expand* (`…-knowledge-s47-expand.js`): `KnowledgeDocument` add `failureCode TEXT NULL` (check on the closed set), `contentSize BIGINT NULL`, `leaseToken UUID NULL`, `leaseUntil TIMESTAMPTZ NULL`, `queuedAt TIMESTAMPTZ NULL`, `deletedAt TIMESTAMPTZ NULL`, `bytesRemovedAt TIMESTAMPTZ NULL`; `KnowledgeChunk` add `embeddingModel TEXT NULL`; list-order index `(shopId, createdAt DESC, id DESC) WHERE status <> 'DELETED'` and platform variant; partial index on `(status, queuedAt)` for the sweep; `CREATE INDEX CONCURRENTLY` is not allowed inside the migration transaction, so indexes on these small tables are created with `lock_timeout` (documents are low volume; chunks get no new index: the model filter is applied on rows the HNSW/GIN scans already return).
2. *backfill* (`…-knowledge-s47-backfill.js`): `UPDATE "KnowledgeChunk" c SET "embeddingModel" = d."embeddingModel" FROM "KnowledgeDocument" d WHERE c."documentId" = d.id AND c."embeddingModel" IS NULL` in batches of 5,000 by `id` ranges; map old `error` text to `failureCode = 'unparseable'` / `'embedding_unavailable'` for `FAILED` rows (unknown text → `unparseable`) and drop nothing yet.
3. *contract* (`…-knowledge-s47-contract.js`, applied only after the code of steps 2–4 of the work order is deployed): `DROP CONSTRAINT` the two foreign keys (`"shopId" REFERENCES "Shop"`, `"productId" REFERENCES "Product" ON DELETE CASCADE`) found by lookup in `pg_constraint` (names are generated), `ALTER … SET NOT NULL` on `KnowledgeChunk.embeddingModel`, drop `KnowledgeDocument.error`. `KnowledgeChunk.documentId → KnowledgeDocument` stays (intra-owner).
**Check**: constraint names (`SELECT conname FROM pg_constraint WHERE conrelid = '"KnowledgeDocument"'::regclass AND contype = 'f'`); that the test stack applies migrations from `packages/backend/migrations` in filename order.
**Down**: not provided for contract (the dropped FKs are the debt); documented in the file header, same convention as the sibling contract migrations.

## R-6 Ingestion: claim, commit, single retry layer, receive count
**Decision**: handler `ingest(documentId, receiveCount)` — (1) `claim`: `UPDATE … SET status='PROCESSING', leaseToken=:t, leaseUntil=now()+:lease WHERE id=:id AND (status='QUEUED' OR (status='PROCESSING' AND leaseUntil < now()))`; zero rows → ack (READY duplicate, DELETED, live lease elsewhere). (2) read bytes (storage timeout 10 s; size check against `contentSize`/20 MiB, SHA-256 against `contentHash` for PDFs → mismatch = `size_mismatch`), parse and chunk (pure), limits (pages 500, passages 2,000) → deterministic `FAILED(code)` via `fail(t)` conditional on the lease token, ack. (3) embed in 128-text batches with `AbortSignal` per call (30 s), **no internal retry**. (4) commit via `TransactionRunner.run`: `UPDATE doc SET status='READY', chunkCount=:n, indexedHash, embeddingModel, leaseToken=NULL, failureCode=NULL WHERE id AND leaseToken=:t AND status='PROCESSING'`; zero rows → rollback, discard, ack (delete won, AS-29); else `DELETE chunks WHERE documentId`, multi-row `INSERT` in chunks of 200, commit. Transient error (`EmbeddingUnavailableError`, timeout, storage 5xx): `release(t)` → `QUEUED` (conditional), then rethrow so the queue redelivers; when `receiveCount >= knowledge_max_receives` (5, equal to `maxReceiveCount` in `infra/docker/elasticmq/elasticmq.conf`, asserted by a test) instead `fail(t, 'embedding_unavailable')` and rethrow so the message reaches the DLQ; previous passages are untouched in both cases (R-4). Heartbeat: the consumer's `visibilityTimeoutSec` is 300 s and the queue extends it while the handler runs (port feature); the lease equals it.
**Why `receiveCount` in the handler instead of a DLQ consumer**: the handler sees the count (`TaskMessage.receiveCount`), no second consumer or queue is needed, and the sweep (R-7) repairs a message lost to the DLQ without the handler running (document stuck `QUEUED`/`PROCESSING` → no change; `FAILED` is set by the handler at the last receive). **Check**: `receiveCount` is 1-based and increments on each receive in `sqs-task-queue.ts` and in `in-memory-task-queue.ts` (tests), and `bodySchema` dead-letters with reason `SCHEMA_INVALID` (AS-27). **Concurrency/batch** become config: `knowledge_ingest_concurrency` (4), `knowledge_embed_batch` (128).

## R-7 Sweep job (S49)
**Decision**: job type `knowledge.sweep` (payload `z.object({}).strict()`), schedule registered with `upsertSchedule` (every 5 min) catching `InvalidScheduleError`; S49 guarantees one run per schedule tick. One run does, each step as a bounded conditional update/delete (500 rows per statement) so a second or concurrent run changes nothing: (a) `AWAITING_UPLOAD` older than 24 h (`createdAt`) → `DELETED` + `bytesRemovedAt` pending; (b) `QUEUED` with `queuedAt < now() - 5 min` → `queuedAt = now()` and enqueue (duplicate tasks are harmless: claim is conditional); (c) `PROCESSING` with `leaseUntil < now()` → `QUEUED`, `queuedAt = now()`, enqueue; (d) `DELETED` rows with `storageKey` present and `bytesRemovedAt IS NULL` → delete object, set `bytesRemovedAt` (G24; retried every sweep); (e) tombstones `DELETED` and `deletedAt < now() - 30 d` → delete row. Time uses the database clock in SQL (one source, edge case in spec); the ages are config. **Check**: `jobs.module` declaration style in `catalog/infra/product-maintenance.jobs.ts`; `ShareLinks` plan R-… uses the same pattern.

## R-8 Retrieval query, fallback, cache, deadline
**Decision**: `PassageRepository.candidates({scope, queryText, vector?, minSimilarity, model, limit, deadlineMs})` runs one statement (as today) with CTEs `vec` and `fts`, each joined to `KnowledgeDocument d` with predicate `P = scope ∧ d.status <> 'DELETED' ∧ d."chunkCount" > 0`, `vec` additionally `c."embeddingModel" = :model`; with no vector, only `fts` (mode `keyword`). Hydration reloads text by the fused ids with `P` repeated. `SET LOCAL statement_timeout = :ms` inside the single `TransactionRunner.run` read (replaces the audited site); a cancellation error maps to `RetrievalUnavailableError`. `KnowledgeSearchService.search` embeds the question with `Promise.race` against `rag_query_embed_timeout_ms` (3,000) and `AbortSignal`, never retries; cache `rag:qe:v1:{sha256(model + normalize(q))}` with 24 h TTL, every cache error swallowed (counted); normalize = `trim`, collapse whitespace, lowercase. Metrics `rag_retrieval_duration_seconds`, `rag_retrieval_degraded_total`. **Model for answers (G38)**: new key `rag_model` default `claude-sonnet-5-5` (S46's summary-tier default is the cheaper tier; `assistant_model` is no longer read here). **Check**: the existing vector query casts and orders with `<=>` on `halfvec`; keep the SQL, add the predicates.

## R-9 Admission pipeline and status codes
**Decision**: Nest pipeline = `Firewall({anonymous: true})` (product ask) → zod body pipe (`400`) → `@RateLimit('rag.ask')` interceptor (`429 rate_limited` + `RateLimit`/`RateLimit-Policy` + `Retry-After`; store down → `503 rate_limiter_unavailable`, S50's code) → controller calls `AskService.ask(principal, target, question)` which does, in order: product/shop lookup (`404`) → input moderation (`422`/`503`) → provider budget (`llm.provider.tpm` with cost = estimated tokens; denied → `429 assistant_busy`; `422 rate_limit_cost_exceeded` surfaces as `INTERNAL`-class problem only if the estimate exceeds the whole limit, which `rag_*` ceilings make impossible, asserted by a unit test) → retrieval (`503 assistant_unavailable` on `RetrievalUnavailableError`) → `not_found` or stream. The SSE headers are written by `assistant-stream.ts` only after retrieval succeeds, so every pre-stream rejection is a plain problem+json. A `401` for an invalid token is the Firewall's (before the pipe). **Spec delta**: AS-07 says limiter store down → `503 assistant_unavailable`; S50 defines `503 rate_limiter_unavailable` and the user input requires adopting it; the test asserts `rate_limiter_unavailable` (with `Retry-After`), and the delta is listed in `gaps.md` "Spec changes".

## R-10 Streaming, deadlines, citations, recording
**Decision**: `AskService` builds one request (fixed `RAG_INSTRUCTIONS` constant in `domain/prompt.ts`, byte-identical across calls, test compares bytes; passage blocks with citations enabled; the question the last block; no tools; effort low; `maxTokens` 1,500) and iterates the provider stream with an `AbortController` linked to `res.on('close')`, a first-token timer (`rag_first_token_timeout_ms`) and a whole-answer timer (`rag_answer_timeout_ms`), all driven by the injected clock/timers so tests use fake timers. Output moderation runs per text chunk with the previous 256 characters; a flag aborts the call and ends with `refusal`. `citationsOf` (pure) filters indexes to `0…items-1`, dedupes in order of first appearance, drops other kinds and empty text; `grounded` = at least one block with at least one valid index. Recording: exactly one `CallRecorder.record` per attempted model call in `finally`, outcome from the path, estimated tokens (`chars/4`) when the provider gave none; `not_found` records nothing. Circuit breaker: `breaker.run` from `@app/common/resilience` around the provider call (FR-036 reuses S46's primitive; **Check** its name in `libs/common/resilience`).

## R-11 Documents: identity, concurrency, PDF grant
**Decision**: content identity = SHA-256 of the markdown bytes (UTF-8) or the declared `pdfSha256`, in scope `(shopId|platform, productId|none, visibility)`; the existing unique partial index decides the race: `INSERT … ON CONFLICT DO NOTHING RETURNING`, zero rows → select the winner in the same scope → `200 deduplicated`. Enqueue happens after commit; a crash between insert and enqueue is repaired by sweep (b) (G19). Storage key `knowledge/{scope}/{documentId}` (no content in key). PDF grant: `ObjectStorage.presignPost` with `minBytes = maxBytes = pdfSize`, `contentTypes: ['application/pdf']`, `expiresInSec = knowledge_upload_ttl_s` (900); the hash is verified at ingestion (R-6), a document whose bytes do not match is `FAILED(size_mismatch)` (the closed failure-code list has no hash code; recorded in `gaps.md` "Spec changes"). **Cap**: count of non-deleted documents of the shop checked in the same statement as the insert (`INSERT … SELECT … WHERE (SELECT count(*) …) < :cap`), so concurrent creates cannot exceed it by more than the race window of one statement; duplicate bytes are resolved first and answer `200` at the cap. Shop-level lock not used. **Cursor**: `domain/document-cursor.ts`, base64url JSON `{c: createdAt, i: id}` with an HMAC tag keyed by a subkey derived from the shared signing key used by `marketing/domain/list-cursor.ts` (**Check** which key it uses; if none is shareable, add `knowledge_cursor_key` to the config, required, ≥ 32 bytes).
