# Open Decisions for S14 (answered unattended)

Format: `[TAG] question → default taken → why`. BREAKING first, then CONTRACT, then LOCAL. The human reviews BREAKING and CONTRACT lines first. Decision policy: most production-grade option the Interview-Prep notes and the constitution support; no external clients to keep compatible, so correctness, security, observability and clean boundaries beat today's behaviour.

## BREAKING (changes behaviour or an API/UI contract that exists today)

- [BREAKING] Balance by `SUM(amount)` over all entries (`ledger.service.ts:113-118`, `payout.jobs.ts:53-55`, `ledger-maintenance.jobs.ts:43`) → balance reads use the running balances (authoritative) or the read model (fast); no code path sums history for a balance → notes: "balance page never sums entries", 10/02 Ex1.

## LOCAL (this capability's internals)

- [LOCAL] Number of shards → 32 for the three hot classes, a validated setting 1–256; shop and other accounts are unsharded → matches SD-20 "32 sub-accounts"; shard = stable hash of the journal's reference mod N.
- [LOCAL] Sweep target → shard 0 of the same account, hourly, one journal per account per window, deterministic ID → keeps a single "consolidated" shard readers can use; no new account.
- [LOCAL] Non-negative rule → only for `PAYOUT` debits of seller accounts and for `PAYOUT_CLEARING`; seller accounts may go negative through `AD_CHARGE`, `ADJUSTMENT` and refund clawbacks (the seller owes the platform) → the existing ad-billing spec expects −1000.
- [LOCAL] Journal limits → 2–200 lines, amounts non-zero safe integers, one currency per journal → a settlement for 200 shops is far beyond real orders; zero lines are rejected (today they are silently dropped).
- [LOCAL] Currency → stored on every journal and account; one supported currency (`EUR`) in this showcase, same as S13's `currency_unsupported` rule; mixed-currency journals are refused → FX would be explicit transactions with a stored rate (10/02), out of scope.
- [LOCAL] Journal identity → one journal per (kind, reference), enforced by a unique constraint on a journal header; the ID is deterministic (UUIDv5 of kind and reference) → replay safety without an advisory lock.
- [LOCAL] Time → all journal lines of one journal share one `postedAt` from the injected clock; a posting never lands in two partitions.
- [LOCAL] Postings into a month with no partition → succeed into the default partition, raise an alert, and the next maintenance run relocates them → money movement must not fail because of a maintenance lag.
- [LOCAL] Lock wait → statement timeout 5 s, lock timeout 2 s on posting; a timeout is `ledger_busy` (retryable by the caller, nothing persisted).
- [LOCAL] Archive to cold storage after 13 months (SD-20 "Scale") → out of scope; partition detach is not specified; running balances make it safe later.
- [LOCAL] Provider processing fees (the provider's own fee on each charge) → not booked; the statement's net/fee fields are read and ignored → no expense accounts in this showcase.
- [LOCAL] Statement line types handled → `charge`, `refund`, `dispute`; `transfer`/`payout`/`payout_reversal` are S15's and are counted as skipped; other unknown types are counted and skipped, never issues.
- [LOCAL] Day-boundary matching → a ledger journal with no provider line in the window is looked up by reference at the provider before it becomes `MISSING_AT_PROVIDER`; a provider line is looked up in the ledger by reference regardless of its posting day.
- [LOCAL] Provider windows → UTC days `[00:00, 24:00)`; `day` must be before today (UTC) and within 90 days.
- [LOCAL] Issue states → `OPEN → RESOLVED` only; `resolution ∈ {explained, adjusted, auto_matched}`; the note is 1–500 characters; run states `RUNNING → COMPLETED | FAILED`, `FAILED → RUNNING`, `COMPLETED` final.
- [LOCAL] Read model staleness accepted → ≤ 5 s p99 from commit to visible; `asOf` shows the projection time; the hot store keys carry a 24 h TTL refreshed on write, the durable store has no TTL.
- [LOCAL] Reconciliation of payouts and of the provider's own balance → out of scope (S15); manual adjustment without an issue → out of scope (no free-form journal endpoint).
- [LOCAL] Legacy data → `LedgerEntry_legacy` and old `MERCHANT_<uuid>` lines are backfilled into journals and balances in batches (expand), verified by count and checksum, then the legacy table is dropped in a later deploy (contract).
