# Questions and defaults: S33 — Search Autocomplete

Each line is a choice made unattended, with the default taken and why. Sorted by impact: BREAKING first (changes behaviour or a contract that exists today, so existing tests and callers need updating), then CONTRACT (another capability must provide or consume it), then LOCAL.

- [BREAKING] Response `{queries: string[], products: string[], partial: boolean}` → `{prefix, suggestions: {text, source: 'query' | 'catalog' | 'typo'}[], degraded: string[]}` with the merge, de-duplication and cap done by the backend → merging and ranking are business rules (VI.9); a boolean `partial` cannot say which source failed; `suggestionsFrom` in `packages/web/lib/api/catalog.ts` and `SuggestResponse` there are deleted, the e2e in `autocomplete.e2e-spec.ts` is rewritten.
- [BREAKING] `q` missing, or longer than 100 characters → today an empty answer, or a silent truncation to 100 characters (`normalizeQuery`, `top-k-trie.ts:80`); default `400` problem+json `validation_failed`, plus `400` for unknown parameters and a bad `limit` → silent truncation answers a question the user did not ask (V.3, V.4, ValidationPipe with `forbidNonWhitelisted`, II.2).
- [BREAKING] Rate limit: the route is `skipThrottle: true` today (`autocomplete.controller.ts:16`) → policy `discovery.suggest` 600/minute per address, fail open, `429` problem+json → an unthrottled public endpoint that touches the engine is a cheap amplification target; the CDN absorbs popular prefixes so 600/minute is far above real typing (10 requests per second at most).
- [BREAKING] Cache headers: a static `public, max-age=60, s-maxage=60` on every answer today (`autocomplete.controller.ts:17`) → the header only when `degraded` is empty; `no-store` for degraded answers and for `400`/`429` → otherwise a one-off engine hiccup is pinned in the CDN for a minute for every user of that prefix.
- [BREAKING] Catalog completions: `ElasticsearchService.suggestTitles` called directly, ignores visibility (`autocomplete.service.ts:79`, `elasticsearch.service.ts:219-225`) → only S32's `ProductTitleSuggester` (visible products only) → archived, sandbox, deleted and suspended-shop products must never be suggested (S32 AS-79, domain boundary D-16).
- [BREAKING] Blocklist applied only to the build input (`autocomplete-builder.jobs.ts:20,53`) → applied to every suggestion of every source at serve time as well, and to the build → a catalog title or a typo completion can carry an offensive term too, and a list change must not wait up to an hour for the next build.
- [BREAKING] Eligibility: the build counts every row with `results > 0` → also excludes `surface: 'internal'` rows, `[redacted]` and personal-data-looking queries (re-checked at build, rows older than S32's redaction may hold them), non-normalised queries and queries under two characters → today an email typed into the box by 5 people becomes a public suggestion; the assistant's in-process searches are not typing.
- [BREAKING] Snapshot: a bare gzip of `Suggestion[]` (`autocomplete-builder.jobs.ts:56`) → a versioned envelope with a checksum, the build parameters and `{query, searchers}` pairs; the pointer moves only forward and only for non-empty, changed content; the latest five versions are kept → today a truncated download is parsed blindly and an empty ClickHouse result publishes an empty index that blanks every node; an overlapping older build can overwrite the pointer; old snapshots are unreadable by the new nodes, so the first deploy serves `query_index_unavailable` until the first new build.
- [BREAKING] `AutocompleteModule` is `@Global()` and exports `AutocompleteService` and `SearchQueryLogger` (`autocomplete.module.ts:11,15`); the barrel exports `SearchQueryLogger` (`index.ts:17`) → the module exports nothing; the logger and query projector are S32's, the service is internal → X.4, D-8, D-15 (catalog must not import the logger).
- [BREAKING] Typo tolerance: absent today (the notes ask for an ES fuzzy fallback when the trie has no match, 10/09 #37) → added: `source: 'typo'` entries when the query index and the catalog prefix both return nothing, prefix ≥ 3 characters.
- [BREAKING] Frontend: `fetchAutocomplete` enables suggestions at 2+ characters with a 300 ms debounce and no cancellation (`packages/web/app/search/page.tsx:54-91,145`) → debounce 150 ms, cancel superseded requests, drop stale answers, 60 s client cache, request from 1 character → the notes (10/05 #12) and FR-042; W02 owns the change.
- [CONTRACT] S32 must add `ProductTitleSuggester.suggestTitlesFuzzy(prefix, size ≤ 10, signal?)` → default requested as a second method on the same port (edit distance ≤ 2 for terms of 5+ characters, ≤ 1 shorter, first character fixed, visible only) → S32 only offers prefix titles today, and autocomplete must not reach the engine around the port.
- [CONTRACT] S32 must store `surface` (`'http' | 'internal'`) in the query log table and keep `query` normalised and redacted, with `event_id` collapsing duplicates and a 90-day expiry → S33 filters on `surface`; rows without the column read as `'http'`; S32's `search.performed` already carries `surface`.
- [CONTRACT] The log is read by the S33 build directly from the discovery analytics store → default: allowed, same domain, the store is discovery's (domain-map: query logs in ClickHouse); S32 keeps the table definition and the projector, S33 is a read-only consumer of columns `event_id, query, results, user_hash, surface, ts`; a column change by S32 is a contract change.
- [CONTRACT] S50 must declare `discovery.suggest` (600/minute per address, fail open) → the registry is S50's.
- [CONTRACT] S49 must run `search.build-autocomplete` hourly, once across replicas, lease 10 minutes → name and cron kept from today; the lease is the existing `600_000` ms.
- [CONTRACT] W02 must follow the consumer obligations of FR-042 (debounce 150 ms, abort, discard stale, 60 s cache, render as text) and read `suggestResponseSchema` from `packages/contracts` → W02 has no spec yet; this is the interface it must adopt.
- [CONTRACT] S35 (trending): a streaming top-K blend is not built here → deferred; if S35 wants it, it adds a `trending` value to `source` and a trending budget through an additive, announced change; clients validating strictly must accept unknown sources first (V.7).
- [CONTRACT] Edge cache: honours `Cache-Control` and keys on the full URL, never forwards credentials for `/suggest` → operations artifact, not an e2e row.
- [LOCAL] K = 10, depth 20, floor 5 distinct searchers, window 30 days, cap 200,000 queries → the notes' numbers (SD-12 scale section).
- [LOCAL] Catalog budget 40 ms, typo budget 40 ms, parallel start → the existing 40 ms; parallel so a trie miss costs one budget, not two.
- [LOCAL] Fuzzy runs speculatively in parallel with the catalog prefix call on a trie miss → bounded latency over saving one rare engine call.
- [LOCAL] Typo fallback minimum 3 characters, at most 5 entries → shorter prefixes are noise at edit distance 1–2.
- [LOCAL] Slot allocation `⌈0.6 × limit⌉` for queries, catalog cap 5, rest to the other → popular queries first as in the current client; no source starves the other.
- [LOCAL] Breaker: 5 consecutive failures, open 10 s, one probe → protects the engine and the latency budget when it is down at 50k RPS.
- [LOCAL] Per-prefix catalog cache: in process, 60 s, never caches failures → notes say "cached per prefix 60 s"; process memory is enough, no shared cache.
- [LOCAL] Poll interval 30 s, retry of a failing version at most once per poll → unchanged from today; keeps the pointer store and object store quiet.
- [LOCAL] Retention: five snapshots, unreferenced objects kept one hour → rollback room, no deletion of an in-flight build.
- [LOCAL] Empty-result guard only; no "shrank by more than X%" guard → a percentage guard blocks legitimate drops and is easy to add later; the integrity checksum and the empty guard cover the failure modes seen.
- [LOCAL] Blocklist words kept as today (`fake`, `counterfeit`, `stolen`, `hack`, `hacked`), whole-word, from configuration → hides e.g. "fake plant" from the drop-down only; the list is policy, not code.
- [LOCAL] Query suggestions are the stored normalised (lower-case) text → what people searched is what the search box will run.
- [LOCAL] Prefixes deeper than 20 characters are best-effort → memory bound from the notes.
- [LOCAL] `limit` 1–10, default 8 → one parameter instead of today's hard-coded 8 + 5.
- [LOCAL] Version string is a sortable UTC timestamp (as today) → lets the pointer rule be a plain comparison.
- [LOCAL] Metrics names use the `autocomplete_` prefix and no query text in labels or logs → privacy (VIII.1).
