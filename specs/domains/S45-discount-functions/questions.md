# Questions and defaults: S45 — Seller discount functions (domain `shop-functions`)

Decisions taken unattended, sorted by impact. Review `[BREAKING]` and `[CONTRACT]` lines first. Policy: the most production-grade option the Interview-Prep notes and the constitution support.

## [BREAKING]

- [BREAKING] Checkout hook (today `CheckoutDiscounts.unitPrices(lines) → number[]` is defined in `orders` and implemented by `ShopFunctionsService`, so shop-functions imports orders while the domain map says orders depends on shop-functions) → R1 export `DiscountEvaluationService.evaluateDiscounts(cart) → {shopDiscounts: [{shopId, discountMinor}]}`, never rejects; the orders port is deleted and shop-functions no longer imports orders → IX.7 R1, X.5 (no cycle); S10 AS-24 and FR-018 already require this shape.
- [BREAKING] Seller input and test-case shape (`unitPrice`, hard-coded `currency: 'usd'`; `service.ts:129`) → `unitPriceMinor`, currency taken from the cart (ISO three letters), strict validation of every field (today the nested `tests` array is unvalidated, `module.ts:14`); stored test cases and sources that read `unitPrice` must be migrated or resubmitted → money is integer minor units (III.8), V.1, P0112.
- [BREAKING] Output arithmetic (today `Math.floor(value)` on fixed discounts, out-of-range `lineIndex` silently skipped, `value ≤ 1,000,000` float; `contract.ts:28-35`) → `fixedPerUnit` must be an integer, a bad `lineIndex` or non-finite value makes the whole output invalid (the function counts as failed), percentages above 100 still clamp, percentages use integer basis points, the shop total is clamped to the shop gross → "never trust output" (P0112) and exact money (III.8); silent repair hides seller bugs the judge should catch.
- [BREAKING] Test cases belong to the function and are read live by the judge (`service.ts:86`), so editing them changes the suite under a running judge → each version freezes the suite at submission; new `GET/PUT …/tests` routes read and replace the current suite → a judge must be reproducible; the test-case table gains `version` (null = current suite).
- [BREAKING] Submission pre-check (a `/function\s+run\s*\(/` regex answers `400`, `service.ts:66`) and `BadRequestException` strings → any source ≤ 20,000 characters is accepted (`202`) and the judge returns `compile-error` or `entry-missing`; every error is problem+json with a code → a regex is not a parser, the sandbox is the authority; V.3.
- [BREAKING] Create and submit responses (today create returns `{functionId}`, submit `201 {version, status}`) → create answers `201 shopFunctionSchema` with `id`; submit answers `202 {functionId, version, status, createdAt}` → V.2 contract schemas; async work answers 202.
- [BREAKING] Judge hand-off (today insert then `queue.enqueue`, a dual write; a crash leaves a version `QUEUED` forever, `service.ts:74`) → version, frozen cases, history row and an outbox judge request in one transaction, relayed to the queue, plus a recovery job (2-minute threshold, 5 attempts, then `REJECTED judge_unavailable`) → IV.4, III.3.
- [BREAKING] Queue `function-test-runs` → task `shop-functions.judge-version`, same payload `{functionId, version}`, zod-validated, invalid payloads dead-lettered → S53 naming; IV.5.
- [BREAKING] Judge result application (today `ACTIVE` whenever all cases pass and the previous `ACTIVE` is demoted, so an older, slower version can overwrite a newer one; no conditional status checks; cache dropped outside the transaction; `service.ts:100-110`) → conditional transitions with history rows; a passing version older than the active one becomes `SUPERSEDED (stale)`; a partial unique index allows one `ACTIVE` per function; `activeVersion` can only name an `ACTIVE` version → III.6, III.7.
- [BREAKING] Sealed-runtime sharing (today one isolate per source hash is shared by every shop with identical source and **keeps its globals between runs**, `sandbox.ts:27,34`; `Date` and `Math.random` exist) → a fresh context per run, nothing shared between shops, no `Date` or `Math.random`, a timeout or memory failure destroys the instance → a cross-tenant side channel and a non-deterministic memo are production bugs; pure functions make judge and memo sound.
- [BREAKING] Foreign key `ShopFunction.shopId → "Shop"` (`migrations/20261002150000-shop-functions.js:9`) → dropped by an expand/contract migration; the cross-domain reference is a plain ID; one-`ACTIVE`-per-function partial unique index; `ShopFunctionVersionHistory` table added to the ownership registry → IX.4, III.7, III.11.
- [BREAKING] Permission on the routes (today `ShopScoped('shop.manage')` on both routes, so any manager role can change code that runs at checkout; `module.ts:26,32`) → `functions.manage` (OWNER, ADMIN) on every route, reads included → III.4, V.4; S03 adds it (CONTRACT below).
- [BREAKING] New limits: 3 functions per shop, 100 versions per function, 10 submissions per hour per shop, 256 KiB suite, unique function name per shop (today only `tests ≤ 50`, `name ≤ 60`, `source ≤ 20,000`) → seller code is expensive to run and judge; bounded resources are a production expectation.
- [BREAKING] Judge placement: seller code executes only in a hardened `function-runner` deployment (no network, read-only root FS, non-root, default seccomp, no data-store credentials), and the coordinator that touches the database is a separate process; today `FunctionJudgeModule` runs seller code in a process holding DB, Redis and queue credentials (`module.ts:57-75`) and the "second wall" is only prose → the notes name process isolation as the second wall; I.6 written reason is isolation.
- [BREAKING] Breaker (today 5 failures in 60 s → skipped 300 s with non-atomic `INCR` then `EXPIRE`, no half-open, no visibility; `service.ts:159-172`) → atomic counting, a single half-open trial, state visible in `GET …/functions/:id`, metrics and logs → P0620 "tested fallbacks".
- [BREAKING] Entitlement is checked nowhere today → write routes need `shopFunctions`; checkout reads it in one batch; a downgraded shop's functions stop applying and resume on upgrade → domain map: "Depends on: billing (R1 entitlement)".
- [BREAKING] Existing test `shop-functions.e2e-spec.ts` calls the service directly, spies on `TaskQueue.enqueue` (`:39`), imports tenancy's `ShopModel` (`:11`) and uses Redis `KEYS` (`:49`) → replaced by the four supertest e2e files and three unit specs in `test-plan.md`; the sandbox unit spec is kept and extended → VII.2, VII.3, III.9.

## [LOCAL]

- [LOCAL] Verdict names → `pass`, `wrong-output`, `timeout`, `memory`, `runtime`, `invalid-output`, `compile-error`, `entry-missing` (first five exist today).
- [LOCAL] Several functions per shop → largest discount per line wins, no stacking → matches today's `Math.min` on unit price; cannot exceed the gross.
- [LOCAL] Percentage precision → `(0, 100]` with 2 decimals as basis points → exact integer arithmetic.
- [LOCAL] Per-case equality → deep equality of the validated output, same discounts in the same order.
- [LOCAL] Budgets → judge 50 ms per case and 10 s per version; checkout 5 ms per function and 200 ms overall; 32 MB per runtime (from SD-40 and S10's 250 ms).
- [LOCAL] Compiled-instance cache size and pre-warm → plan decision (cap × size goes in `plan.md`); compile time is outside the 5 ms but inside the 200 ms.
- [LOCAL] Active-set cache and memo → 60 s TTL each, deleted on change, memo keyed by version hash plus canonical input hash (today keyed by source hash alone).
- [LOCAL] Rollback only to a `SUPERSEDED` version that passed → no re-judge; its frozen verdicts stand.
- [LOCAL] Verdict list ordering → by case name ascending (as today).
- [LOCAL] Delete → hard delete of function, versions, history and cases; no shop-deletion consumer in this release.
- [LOCAL] No `Idempotency-Key` on submission → a duplicate is a harmless draft; V.6 lists orders, payments, bookings, bids and ledger moves only.
- [LOCAL] No global kill-switch flag → per-function disable and the breaker are the controls; S38 can add a flag later.
- [LOCAL] No realtime push of verdicts → sellers poll.
- [LOCAL] Functions run without `Date` and `Math.random` → time-based discounts are out of scope.
