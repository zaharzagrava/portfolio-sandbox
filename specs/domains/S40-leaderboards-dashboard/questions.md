- [BREAKING] Stats shape: `revenueCents`, `avgOrderValueCents`, `refunds` (count), rolling `now − N days` window, sparse `daily`, no `from`/`to` (`api/seller-stats.dto.ts`, `seller-stats.service.ts:32`) → `…Minor` names (S10 convention), calendar window of `N` UTC days ending today, zero-filled `daily`, `refundsCount`/`refundedMinor`/`netRevenueMinor`, `currency`, product `title`, and `days` outside 1–365 is `400` → money naming is consistent with S10/S13; a rolling window gives a partial first day and a chart with holes.

## CONTRACT (decides something another capability must provide or consume)

- [CONTRACT] S10 lists only `order.paid` as S40's input (`S10 spec: Consumers … S40 (order.paid → sales and leaderboards)`) → S40 also consumes `order.reserved` (checkout count for conversion) and `order.refunded` (stats), no payload change; S10 must add S40 to those events' consumer lines → the live conversion needs reservations; refunds need the refund event.
- [CONTRACT] S40 needs `order.paid` fields `paidAt`, `lines[].shopId` (non-null), `lines[].lineTotalMinor`, `lines[].title`, `userId`, `currency = EUR`, and the guarantee that `order.paid` precedes `order.refunded` for one order (same key `orderId`) → exactly the S10 payload; no change requested, only that these fields stay.
- [CONTRACT] `order.refunded` carries no per-shop split; S40 attributes a full refund to each shop's recorded share (its own sales facts) and dead-letters a partial amount → S10 AS-49 says `order.refunded` is emitted for full refunds only; if S10 ever emits partial refunds it must add `shopRefunds: [{shopId, amountMinor}]`.
- [CONTRACT] Product category comes from the S05 snapshot events (`catalog.product_*`, `category`, `productVersion`), not from `order.paid` (no category there) → follows S05's own "projectors stop reading `Product`" decision; the alternative (S10 adds `category` to each line) would remove one read model but changes a finished contract.
- [CONTRACT] Shop names and slugs come from `tenancy.shop_created|updated` (R3) and erasure from `tenancy.shop_deleted`; S40 does not use `ShopQueryService.getShopsByIds` although S03 lists S40 as its consumer → lists need a join-free read model (IX.7 R3); a single lookup R1 would only add a dependency on S03 in the hot path.

## LOCAL (affects only this capability's internals)

- [LOCAL] Ranking by gross revenue; refunds ignored by boards → S10 gives no line split on refunds and lists only `order.paid` for ranking; self-purchase-and-refund gaming is a known limit (a net board is the follow-up).
- [LOCAL] Platform currency `EUR`; other currencies dead-lettered → no FX in this capability.
- [LOCAL] Weekly/monthly UTC; "today" is the UTC day → one global calendar; shop time zones are a later option.
- [LOCAL] Exact rank for every shop while live; approximate percentile for huge boards (notes §18) not built → one sorted set per board is exact and fast at showcase scale; the notes list it as an option for very large boards.
- [LOCAL] Frozen = top 100 → notes: snapshot of the top 100; ranks beyond are `not_ranked`.
- [LOCAL] Snapshot due at period end + 1 h → existing job schedule (Monday/day 1 at 01:00 UTC) and grace for late events.
- [LOCAL] Sale instants use `paidAt`, not the envelope's `occurredAt` → business time; the envelope time is outbox time.
- [LOCAL] Revenue ceiling `2^33 − 1` minor units per shop and period (exact ranking key in a double); over it the order is dead-lettered whole → documented limit, EUR 85.9M per shop per period; a wider key needs a different encoding.
- [LOCAL] Same-instant tie order is "larger shop id first" → it is what a sorted set yields for equal keys; stable and testable.
- [LOCAL] Unknown category counts on the overall board only, no retroactive attribution → product events precede sales in practice; retry or reconcile adds a pending store for little gain.
- [LOCAL] Boards keep 35 days after period end → covers the grace, catch-up after outages, and reads of last month.
- [LOCAL] Public rate limit 60/min/address, fail open → public cacheable data; fail closed would turn a limiter outage into a leaderboard outage.
- [LOCAL] Timeouts: board store 500 ms, analytics 3 s → the 20 ms p99 target of the notes is for the hot path; these bound the worst case.
- [LOCAL] Conversion = orders ÷ checkouts in the same 60 s window, may exceed 1, 3 decimals → a live indicator, not a cohort metric.
- [LOCAL] `uniqueBuyers` exact up to 1,000, within 2% above → approximate distinct count is enough for a seller panel.
- [LOCAL] Staleness: boards and counters 5 s, read models 30 s, analytics 30 s (p99) → states the R3 staleness IX.7 asks for; `plan.md` repeats it.
- [LOCAL] Shop suspension does not hide a shop from public boards → moderation policy belongs to a later capability; deletion is handled.
- [LOCAL] No cursor on the top list → bounded at 100 (III.10 is for unbounded lists).
- [LOCAL] No events published → no listed consumer needs one.
- [LOCAL] Partial refunds unsupported → follows S10 (no event emitted).
- [LOCAL] Offboarding export: none → this domain holds only data derived from orders; the orders domain exports orders.
