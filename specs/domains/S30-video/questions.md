# Questions and defaults: S30 — Product video and VOD (domain `media`)

Each line: `question → default → why`. Sorted by impact: BREAKING first (changes behaviour or a contract that exists today; the implementation updates existing tests and callers), then CONTRACT (another capability must provide or consume it), then LOCAL. Nothing here was asked of a human; each default is the most production-grade option the notes and the constitution support.

## BREAKING (changes behaviour or an API/UI contract that exists today)

- [BREAKING] Who may fetch playback of an `unlisted` video? Today `GET /videos/:id/playback` is anonymous and answers for any ID → a random share token (≥ 128 bits) is required (`?token=`), a missing or wrong one is the same `404` as an unknown ID; the token is shown only to the shop's members → "unlisted" means "anyone with the link", not "anyone who guesses or learns an ID" (IDs are time-ordered UUIDs, listed in logs and events); notes: signed access for unlisted video (10/08 #26).
- [BREAKING] What if the signing key pair is not configured? Today an unlisted video silently gets the unsigned public URL (`video.service.ts:122`) → `503` at playback, startup failure in production, never an unsigned URL → fail-open on a security control is a leak, not a convenience.
- [BREAKING] Where do the signed cookies live? Today `Domain` is the delivery host's own name, which browsers refuse when the cookie is set from the API host (`video.controller.ts:49`) → `Domain` is the configured parent domain that contains the API host and the delivery host (`video_cookie_domain`), checked at startup → the credential must actually reach the segment requests.
- [BREAKING] Where do originals and outputs live? Today everything is under `videos/<id>/` including `source`, and the public URL base falls back to the storage endpoint (`video.service.ts:52,119`) → private source path, `/p/<id>/` (public) and `/u/<id>/` (unlisted) delivery paths on a dedicated video host, no storage-endpoint fallback; visibility is fixed at creation → the CDN can require a signature per path, the original can never be served, and a signed path cannot be cached unsigned.
- [BREAKING] What does `POST /shops/:shopId/videos` return? Today `{videoId, partSize, uploadId, key, partUrls}` (leaks the private source key and the upload identifier) and a raw `400 "max 20 GB"` → `{videoId, partSize, partCount, expiresAt, visibility, shareToken, parts:[{partNumber,url,contentLength}]}` with problem+json errors, `contentType`, `productId`, quota and rate limits; every part URL signs its exact length → the client never needs the key; the store enforces each part.
- [BREAKING] How does completion work? Today it selects the row, completes the multipart upload, then starts the pipeline, answers `200` even for non-`UPLOADING` states and trusts the client's etags (`video.service.ts:58-64`); two concurrent calls both start the pipeline → conditional `UPLOADING → UPLOADED → PROCESSING`, parts verified against the storage's own list, size check, `202`/`200` matrix, one message after commit, recoverable `UPLOADED` → constitution III.7, III.3 and the notes' idempotent processing.
- [BREAKING] What states does a video have? Today `UPLOADING | PROCESSING | READY | FAILED`, no history, no version, no error vocabulary → add `UPLOADED`, `EXPIRED`, `DELETED`, `VideoStatusHistory`, `version`, `failureCode`, `retryCount`, `shareToken`, `productId`, `contentType`, `sizeBytes`, `partSize`, `sessionExpiresAt`, `objectsPurgedAt`; tasks get `lease`, `claimedAttempt`, `CANCELLED` → III.7 (history on every transition) and recoverability.
- [BREAKING] Foreign keys from `Video` to `Shop` and `User` (migration `20261002120000-videos.js:9-10`) → dropped by an expand/contract migration; the columns stay as plain IDs → IX.4 forbids FKs to another owner's table, and the check does not see them.
- [BREAKING] How is a task claimed? Today `QUEUED` or `RUNNING` can be claimed by anyone at any time and `DONE` is written without checking who claimed (`video.service.ts:83`) → claim only `QUEUED` or an expired lease; `DONE` is fenced by the claimed attempt; each attempt writes its own output location; "busy" does not consume an attempt → two workers on one rendition interleave non-identical encodes into one playlist; "deterministic keys" are not deterministic bytes.
- [BREAKING] How are retries scheduled? Today a thrown error leaves redelivery to the visibility timeout (up to 900 s, no backoff) and a lost message after the claim commit stalls the video forever → delayed re-enqueue 30 s then 120 s, permanent failures fail at once, a sweep re-sends lost messages and recovers expired leases → notes: per-task retries; IV.6 exponential backoff, transient only.
- [BREAKING] What does a shutdown do to a running task? Today the abort counts as a failed attempt (it throws into the retry path) → it re-queues without consuming an attempt → a deploy must not exhaust the 3 attempts.
- [BREAKING] Are the HLS outputs accurate? Today keyframes are 48 frames regardless of the source frame rate (`hls.ts:23`), the master playlist uses configured bitrates, a fixed codec string and frame rate, and a width rounded from the source (`hls.ts:34-35`, `video.service.ts:164`); a source below 240p is enlarged → constant output frame rate and fixed-time keyframes, a master built from measured values, the lowest rung made at the source's size → notes: "no upscaling", "seamless ABR"; players pick rungs from `BANDWIDTH` and `CODECS`.
- [BREAKING] The pipeline gains a `thumbnails` task (sprite + text track), optional (`SKIPPED` on failure) → the notes list "thumbnails/sprite" in the DAG; the existing graph has only `poster`; the existing waves test changes.
- [BREAKING] Playback response and cookies: adds `title`, `spriteUrl`, `width`, `height`, `renditions`, `expiresAt`; the cookie `maxAge` becomes `Expires`; the response is `404` for every hidden state → additive for clients except the cookie domain and unlisted token above.
- [BREAKING] No shop-status check on playback today → a suspended shop's videos stop playing (R3 copy of the shop's status, no per-view call to tenancy) → takedown must reach the player; a per-view R1 read would put the database on the hot path the notes keep off it.
- [BREAKING] `video.e2e-spec.ts` calls `VideoService` directly with the queue spied and is skipped when ffmpeg is missing (`describe.skip`) → HTTP-level supertest suites per `test-plan.md` through the real queue port; in CI a missing ffmpeg fails the run → VII.2 (HTTP through the real pipeline), VII.3, VII.6; a silently skipped deep layer is not a gate.
- [BREAKING] `VideoService` is exported through the barrel only to be wired in `apps/` → apps import `VideoModule`, `VideoWorkerModule`, `VideoProjectorModule`; the service is no longer exported (D-8) → X.4.
- [BREAKING] New rate limits on every seller mutation and on playback (`video.start.shop`, `video.write.shop`, `video.playback.ip`); none exists today → V.6-adjacent abuse control; fail closed for writes, open for reads.

## CONTRACT (decides something another capability must provide or consume)

- [CONTRACT] Which host serves public video? S27's block allowlist names `stream.marketplace.dev` → the `video_cdn_url` setting; production value `https://stream.marketplace.dev`; public master at `/p/<id>/master.m3u8` → honours S27 (FR-040); S27 stores only URLs on that host.
- [CONTRACT] Domain map: `media` "Emits: `media.ready`", "Depends on: none" → also emits `video.ready`, `video.failed`, `video.deleted`, and depends on tenancy (`ShopScoped`, `tenancy.shop_deleted`, `tenancy.shop_status_changed`) and catalog (`getProductsByIds`, `catalog.product_deleted`) → the domain map and S29's note "no dependencies" must be updated by the implementation; the video flow cannot meet III.4 and IX.7 without them.
- [CONTRACT] Events: `video.*` use a separate name space from `media.ready` (photos) on the shared `media.events` topic keyed by the video ID → S29 said S30 must not reuse photo statuses or tables; a consumer subscribing to `media.ready` is never surprised by a video payload; no event carries a URL or key.
- [CONTRACT] S05 → no `Product` access from `media`: the product check is `getProductsByIds([id], {shopId})` (R1) and `catalog.product_deleted` clears the link (R3); S05 does not read `Video` → product page videos come through `GET /products/:id/videos` composed by S48 (R2).
- [CONTRACT] S03 → `ShopScoped('products.read'|'products.write')` with its status gate; events `tenancy.shop_deleted` and `tenancy.shop_status_changed {shopId, from, to, shopVersion}` → R3 copy `VideoShopState` with a version guard; no R1 call on the playback path.
- [CONTRACT] S48 (BFF) → the product page calls `GET /products/:productId/videos` and, when the user plays, `GET /videos/:id/playback` in parallel with the other sections; the video section is optional (partial envelope) → R2; `media` builds no composed page.
- [CONTRACT] S39 (analytics ingestion) → player beacons feed view counts; `media` exposes no counter route and writes nothing per view → notes: "view counts via analytics stream, not DB updates".
- [CONTRACT] S53 → consumer framework for three events (own consumer groups, DLQ, version guard or natural idempotency), outbox `append`, queue port with receive count, delayed `enqueue` and message attributes for trace propagation → IV.5.
- [CONTRACT] S49 → jobs `media.video-expire-uploads`, `media.video-requeue-stuck`, `media.video-purge`; S50 → policies `video.start.shop`, `video.write.shop`, `video.playback.ip`; S54 → metric names of AS-57, startup validation of the settings of AS-58, redaction of `token` in access logs, graceful shutdown ordering.
- [CONTRACT] Infrastructure storage port (S29 and S07 also extend it) → S30 adds `listParts`, per-part presign with an exact length, `head` with cache-control, `put` with cache-control and a timeout, `deletePrefix`, per-call timeouts; a new delivery-edge port (sign a path-pattern credential; request path removal from the edge cache) replaces the direct `@aws-sdk/cloudfront-signer` call in `application/` → I.2 and X.3; S29's additions (`presignPost` conditions, minimum size) are separate and do not conflict.
- [CONTRACT] S29 (same domain) → distinct module names (`VideoModule`, `VideoWorkerModule`, `VideoProjectorModule` vs `MediaModule`, `MediaWorkerModule`, `MediaProjectorModule`), distinct job and policy name spaces (`media.video-*`, `video.*`), shared `media.events` topic; S29 removes `MediaProcessor` and `Sql` from the barrel (D-8) and S30 removes `VideoService` → no overlap.
- [CONTRACT] W04 / W02 → the seller screen's resumable uploader (per-part retry, resume through `GET …/upload`, status polling, `code` values) and the product page player (playback request, credentials on segment requests for unlisted, re-request before `expiresAt`) → the UI journey lives in W04/W02 (AS-61); neither screen exists in `packages/web` today.
- [CONTRACT] S23 (live → VOD) → not provided; if recorded streams are wanted later they use the same start/complete flow → the notes' SD-26 "depends on SD-15 (live → VOD)" has no consumer in S23's spec, so no speculative export now.

## LOCAL (affects only this capability's internals)

- [LOCAL] Part size, limits → 64 MiB parts, 20 GiB, 24 h session, 1 h part URLs → existing values; 20 GiB / 64 MiB = 320 parts, far below the 10,000-part limit.
- [LOCAL] Source limits → 2 h, 3,840×2,160, ≥ 1 s, ≥ 16×16, H.264/HEVC/VP9/AV1/ProRes decodable, output H.264/AAC only → bounds transcode cost; matches the 3 h task cap.
- [LOCAL] Parallelism → per rendition, no time-chunk split → chunking pays only for sources longer than the limit; a managed transcoder is the ADR alternative.
- [LOCAL] No malware scan of videos → source is private and never served; outputs are re-encoded → clamd stream limits make a 20 GiB scan impractical; see Assumptions.
- [LOCAL] Lease 5 min with heartbeat, attempts 3, backoff 30 s / 120 s, process limit 6 h → below the 900 s queue visibility with heartbeat; transient only (IV.6).
- [LOCAL] Task time limit → `max(600 s, 3 × duration)`, cap 3 h; probe 60 s, poster and sprite 120 s, package 60 s → a hung encoder dies in minutes for short clips, not after a fixed 2 h.
- [LOCAL] Optional sprite → one tile per 10 s, at most 100 tiles, 160×90 tiles in rows of 10, `SKIPPED` after failure → scrub preview is a nicety; the poster is not.
- [LOCAL] Share token → 128-bit random, stored as is (it is a capability, not a password), compared in constant time → it is shown to shop members, so it cannot be hashed.
- [LOCAL] Credential life 4 h → covers a 2 h video with pauses; the player re-requests before `expiresAt`.
- [LOCAL] Product link → optional, one product per video, at most 10 videos per product, `ARCHIVED` products not linkable → keeps the product page light and the check one batch read.
- [LOCAL] Retention → `FAILED` source 7 days, `DELETED` objects within one purge run, edge-cache removal requested for deleted public videos → fast takedown; failed videos stay retryable for a week.
- [LOCAL] Sweep and purge cadence → every minute and every 5 minutes, bounded to 200 videos per run → cheap; single-run by S49's lease.
- [LOCAL] Playback caching → `public, max-age=60` for public, `private, no-store` for unlisted; product list `max-age=15` → a takedown is visible within a minute without a purge call; signing is local crypto, so no signing cache is needed.
- [LOCAL] No `Idempotency-Key` on start → V.6 lists only orders, payments, bookings, bids and ledger movements; a replayed start creates a slot that expires unused.
- [LOCAL] Encoder runner stays in `infra/ffmpeg.ts` (domain-specific, X.7); the DAG, ladder, playlist, probe rules, delivery paths, timeouts and status table are pure in `domain/` → I.3, table-driven unit tests.
- [LOCAL] Shop status copy `VideoShopState` → a table of `{shopId, suspended, shopVersion}`; absent row means active → a shop that never changed status has no event.
- [LOCAL] Seller reads are not rate limited beyond the global limits → low volume; writes are.
