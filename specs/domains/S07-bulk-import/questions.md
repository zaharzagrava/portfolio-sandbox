# Open Decisions for S07 (answered unattended)

Format: `[TAG] question → default taken → why`. BREAKING first, then CONTRACT, then LOCAL. The human reviews BREAKING and CONTRACT lines first. Decision policy: most production-grade option the Interview-Prep notes and the constitution support; no external clients to keep compatible, so correctness, security, observability and clean boundaries win over keeping today's behaviour.

## BREAKING (changes behaviour or an API/UI contract that exists today)

- [BREAKING] Product writes (today raw `INSERT … ON CONFLICT` into the product table plus raw outbox rows `{productId}` on `products.events`, `catalog-import.service.ts:187-222`) → batches go only through S05's `ProductImportService.upsertFromExternal(shopId, items, 'import')`; this domain writes no product row and no product event → IX.4, IX.7 R1, S05 FR-032 and its AS-60–AS-63; the catalog owns validation, change detection, versions and the snapshot events (so the search projector no longer re-reads the table). Existing e2e SQL on `"Product"` moves to the catalog's read service.
- [BREAKING] Batch size 1,000 rows → 500 → S05's call accepts 1–500 items; progress events and checkpoints double (the existing test's "10 progress events for 10k rows" becomes 20).
- [BREAKING] Scanner is optional (today the scan is skipped when `CLAMAV_HOST` is unset) → mandatory in production (startup fails), explicit switch elsewhere, and fail-closed on any scanner trouble (down, stalled, size-limit reply, unknown reply) → note 10/08 #27 "virus scan before making files available"; an optional control is not a control.
- [BREAKING] Start route response (today `{jobId, partSize, uploadId, key, partUrls}` straight from the storage port, exposing the storage key and upload handle) → `{importId, status, partSize, partCount, parts: [{partNumber, url}], uploadExpiresAt}` parsed by `importStartResponseSchema`; `jobId` becomes `importId` everywhere (routes, messages, topic) → V.1 (internal IDs and handles are not for clients), V.2 (schemas in contracts).
- [BREAKING] `POST /shops/:shopId/imports` requires `Idempotency-Key` (today none; a retried request leaves an orphan job and an open multipart upload) → replay returns the stored body, in-flight `409`, different body `422` → V.6 semantics applied to the one create that otherwise leaks paid storage; design 27 "idempotent processing per upload ID".
- [BREAKING] Complete route (today `200 {status}`, no validation of the part list or the final size, check-then-act race that can enqueue twice) → `202` + `Location` + status body, part list and assembled size validated (`422 invalid_parts` / `size_mismatch`), conditional transition so one message is enqueued; replay `200` → note 04/01 §2.9 async request-reply; III.6/III.7.
- [BREAKING] Status route (today `{...job, errorReportUrl}` where `...job` includes the storage key, upload handle and lease-like fields, and a presigned URL minted on every poll) → `importJobSchema` with counters, `bytesProcessed`, `failure {code, message}`, `errorReport {available, rows}`, `history`; the URL moves to `GET …/imports/:importId/error-report` (10-minute link, minted on demand after the permission check) → V.1; a poll must not mint credentials.
- [BREAKING] Live topic `job:{id}` (shared prefix with orders' export, creator-only policy that reads the import table) → `import:{importId}`, policy = current member of the shop with `products.read` (through S03's `assertMember`), terminal events replayable, progress payload `{processed, failed, bytesProcessed, sizeBytes}` → a removed member must lose access (S03 SC-002) and two domains must not share a prefix whose policies are OR-ed.
- [BREAKING] Error report (today `row,sku,error` rewritten from scratch on every run, so after a crash it holds only post-checkpoint failures: DOUBTS Q60) → `row,sku,field,code,message`, written per batch under a stable batch key, complete across resumes, formula-injection-guarded → the report is the seller's evidence; an incomplete one is wrong. Needs batch-keyed part objects instead of one streamed object.
- [BREAKING] Checkpoint (today the row number only, rows ≤ checkpoint re-parsed and skipped; counters and checkpoint in separate statements from the product write) → row, byte offset, counters, header and format committed together; resume reads from the byte offset → design 27 "row offset + byte offset"; at 5 GiB re-parsing a prefix is minutes of wasted work.
- [BREAKING] Single-runner protection (today only a shop-level concurrency slot; two deliveries of one job can both run after a visibility timeout, and a stalled worker can keep writing) → per-job renewable lease with fencing on every checkpoint commit, plus a recovery job for lost messages → design 27 "visibility timeout > processing time or heartbeat extension", "idempotent processing per upload ID".
- [BREAKING] State machine (today 6 states, free-form `UPDATE … SET status`, no history, no cancel, no expiry) → 8 states (`CANCELLED`, `EXPIRED` added), closed transition table with conditional updates and a history row (III.7), `POST …/cancel`, expiry job, `409` on illegal moves → constitution III.7; design 27 "lifecycle rule aborting incomplete uploads" needs a visible end state.
- [BREAKING] Content sniffing (today NUL byte = binary, everything else CSV) → magic-number table (zip, gzip, PDF, images, executables, OLE), UTF-16/32 BOMs and invalid UTF-8 refused; compressed uploads refused, never expanded → note 05/01 §1 and 10/08 "content-type sniffing (don't trust the extension)", "zip-bomb protection".
- [BREAKING] File-level validation (today every row of a file with a wrong header becomes a row error, so a million-row file yields a million error lines) → header check first: missing required column fails the job `invalid_header` before any row; `stock` becomes optional (an empty cell leaves stock alone, matching S05's missing-`quantity` rule) → fail fast; avoids the 1M-line report.
- [BREAKING] Same SKU twice in one batch (today one `INSERT … ON CONFLICT DO UPDATE` over both rows raises "cannot affect row a second time" and fails the whole job) → the pending batch is sent first, so file order wins and no error → correctness bug today.
- [BREAKING] Source file kept forever (today never deleted) → deleted when the job becomes final, 7-day lifecycle backstop; error report 30 days; job record 90 days → data minimisation; the seller already owns the file.
- [BREAKING] Limits (today none beyond size and one run per shop) → 3 non-final imports per shop (`409 too_many_active_imports`, enforced by the store), 10 starts per hour per shop (`429`), 1 MiB per record, 100,000 failed rows (`too_many_errors`) → design 27 "limits"; one tenant cannot flood the queue or the report.
- [BREAKING] Message `{kind: 'import'|'export', jobId}` → `{importId}` only; order export routes, `OrderExportService` import, and the `kind: 'export'` branch leave `catalog-sync` (D-10) → S12 takes them; removes a domain edge `catalog-sync → orders` (X.5).
- [BREAKING] `ImportJob` table: foreign keys to `Shop` and `User` dropped, `status` check widened, columns added (`nextByteOffset`, `format`, `headerColumns`, counters, `lease`, `scan`, `failureCode`), history table added → IX.4 (a cross-domain reference is a plain ID column), III.11 expand/contract, III.7.
- [BREAKING] Row price `0` accepted by the file rules (today the regex allows `0.00` and writes price 0) → S07 accepts the text, S05 refuses it (`rejected`, reported) → one validation owner for product rules (S05 FR-032); the seller sees the refusal in the report.
- [BREAKING] `sku` max 100 characters → 128 (S05's `externalSku`), `description` and `brand` limits become S05's → S07 keeps only structural limits (types, decimal format, record size) so product rules live once.
- [BREAKING] Existing e2e (`catalog-import.e2e-spec.ts`) calls `imports.process(...)` and the service directly and never the HTTP routes → rewritten to drive the real routes through `supertest` with the production pipeline (VII.2, VII.3); it also stops importing `ShopModel` from tenancy (D-7).

## CONTRACT (decides something another capability must provide or consume)

- [CONTRACT] S05 error codes → S07 passes `errors[].code` through unchanged and maps `field` (`priceMinor→price`, `quantity→stock`, `externalSku→sku`); S05 must publish a closed list of codes per field (e.g. `required`, `too_long`, `out_of_range`, `invalid_format`) in its contracts package, and S07's message table covers every code with a generic fallback → the error report's stable `code` column must not change by accident.
- [CONTRACT] S05 batch limit and idempotency → S07 sends 1–500 items, repeated items are idempotent (`unchanged`), a `rejected` item never fails the call, `ShopNotActiveError` is thrown before any write → as written in S05 (AS-60–AS-63); S07 depends on `unchanged` to make crash-resume cheap and safe.
- [CONTRACT] S05 `externalSku` ceiling → 128 characters, trimmed; S07 trims, S05 enforces → S05 spec.
- [CONTRACT] S12 order export → S12 owns its routes, `ExportJob` and its own queue (`order-exports`); `catalog-imports` becomes import-only. Until S12 lands, the controller and worker keep a temporary branch → debt D-10; S07 gaps lists the removal.
- [CONTRACT] S51 topic registry → `define({prefix: 'import', policy})`; the policy is asynchronous and may call S03's `assertMember`; terminal events are published replayable, progress not; the old `job:` import registration is removed (orders keeps `job:` for exports until S12 renames it) → S51 must allow an R1 call in a policy and per-event `replay`.
- [CONTRACT] S03 membership check → `ShopAccessService.assertMember(shopId, userId, 'products.read')` is the R1 call for the live-channel policy (it throws not-found/forbidden, the policy turns it into a refusal) → replaces the policy's own query; `ImportJobTopicsModule` therefore needs `TenancyModule` loaded in `apps/sse-gateway`.
- [CONTRACT] S03 offboarding export → import history, reports and files are NOT part of the shop export (operational data derived from files the seller owns); S07 reacts to `shop_offboarding_started` by cancelling and to `shop_deleted` by purging → keeps the export small; S03's "every shop-owning domain" rule is satisfied by purge.
- [CONTRACT] S53/S54 idempotency-key store → S07 uses the shared Idempotency-Key interceptor (V.6: replay, in-flight, different body, 24 h TTL) on the one POST that needs it; it must work on a route whose body is small but whose result contains presigned URLs (replay returns the stored body; URLs may have aged, and `GET …/upload` issues fresh ones, AS-06).
- [CONTRACT] S53 events → new topic `catalog-sync.events` (key `importId`) with `catalog_sync.import_finished` v1; the topic must be registered in the outbox's topic groups. ## LOCAL (this capability's internals)

- [LOCAL] Batch checkpoint and the catalog write cannot share a transaction (IX.4) → accept the one-batch reclassification created→unchanged after a crash; processed, failed and products stay exact → documented in AS-35; a write-ahead intent row was rejected as complexity without user value.
- [LOCAL] Retry layer → none inside the job; the queue's redelivery (max 3) is the single layer (IV.6) → retries at two layers multiply.
- [LOCAL] Duplicate SKU in one file → file order wins; the pending batch is flushed before a repeated SKU → deterministic, memory bounded by one batch (no global SKU set).
- [LOCAL] `row` in the report → record ordinal after the header (quoted newlines do not shift it) → matches today's test and is stable across parsers.
- [LOCAL] Report storage → one part object per batch with problems, keyed by batch number, concatenated on read/finish → idempotent rewrite after a crash.
- [LOCAL] Report cap → 100,000 failed rows fails the job `too_many_errors` → bounds report size; configurable.
- [LOCAL] Download name → `errors-<sanitised name>.csv`, 120 characters max.
- [LOCAL] Scan deadlines → 60 s inactivity, 30 min total, 64 KiB frames → today's flat 120 s socket timeout cuts off a legitimate 5 GiB scan.
- [LOCAL] Lease → 5 min, renewed every 60 s, compared with the injected clock; recovery re-enqueues after 2 min unclaimed.
- [LOCAL] Parts → 64 MiB, URLs valid 6 h, job expiry 24 h → a 5 GiB upload on a slow link needs hours, not today's 1 h.
- [LOCAL] Record limit → 1 MiB per record; oversized JSON line = row error, oversized CSV record = job failure (cannot resynchronise).
- [LOCAL] Currency → platform currency only; comma decimals refused as ambiguous.
- [LOCAL] Duplicate tag/unknown column handling → unknown columns ignored and listed in `ignoredColumns`; tags are `|`-separated in CSV, an array in JSON lines; S05 enforces tag limits.
- [LOCAL] Signature name of detected malware → logged, not returned to the client → no value to the seller, a little to an attacker probing the scanner.
- [LOCAL] Terminal event type → one type with a `status` field instead of four types → one schema, one consumer branch.
- [LOCAL] Benchmark script (1M rows, memory and throughput) → an ops artifact outside the e2e suite, referenced by SC-001 and `test-plan.md`.
