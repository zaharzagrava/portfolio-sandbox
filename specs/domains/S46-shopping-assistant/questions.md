# Questions and decisions: S46 — Streamed shopping assistant

Decisions taken unattended under the decision policy (production-grade, notes and constitution first). BREAKING first, then CONTRACT, then LOCAL. Format: `question → default → why`. Notes: `docs/showcase/sections/SD-42-shopping-assistant-llm.md` and `interview-prep/10-system-design/10-ai-applications.md` §42 were read; `pnpm check:table-ownership` needs approval in this session and was not run, so the ownership facts in `gaps.md` come from code search. Where SD-42's test plan and the constitution differ (403 vs 404), the constitution wins and the choice is below.

## BREAKING

- [BREAKING] Another user's generation stream/cancel answers `403` (`assistant.controller.ts:100-105`, SD-42 test plan "403 stream/cancel") → `404 not_found`, same body as an unknown id; ownership is part of the lookup key, not a check after loading (`generation-buffer.ts:55`, `owner()` then compare) → V.4 (existence hidden), III.4 (no load-then-check), VII.3 IDOR.
- [BREAKING] A turn is written in pieces: the user message is stored at the start (`assistant.service.ts:153`), tool rounds as they happen (`:176`), the answer at the end (`:184`), so a refusal, cancel, crash or provider failure leaves a user message or a tool round with no answer, and the next turn then sends two user messages in a row or a dangling `tool_use` → persist the whole turn in one same-partition batch only when it ends `done`; every other outcome persists nothing → a corrupted transcript permanently breaks a conversation; SD-42 says "partial not stored" and "refusal not persisted" but the user message is.
- [BREAKING] `POST …/messages` has no idempotency (`assistant.controller.ts:70-80`) → `Idempotency-Key` required (missing → `422`), completed replay re-serves the stored events, in flight → `409` with the `messageId`, different body → `422`, 15-minute replay window, keys per user, released when the send was rejected before generating → a retried send creates paid, persisted work (V.6 spirit; the notes name idempotent replay as a required edge case); web (W05) must send a key per message.
- [BREAKING] Malformed `Last-Event-ID` is silently treated as "from the start" (`assistant.controller.ts:87`) → `400 invalid_last_event_id` → replaying from the start on a client that already shows text duplicates the answer on the screen.
- [BREAKING] Metering is a direct billing call plus a fire-and-forget Kafka produce that drops on error (`llm-meter.ts:54-55`), with `Math.max(1, tokens)` billing a unit for nothing → one durable `llm.call_completed` v1 per model call through the outbox, billing consumes it (S18); zero-token calls bill 0; `UsageService` is removed from `assistant.module.ts:10,32` and the barrel → IV.4 (no dual write), IX.7 R3, D-14; silent usage loss is silent revenue loss.
- [BREAKING] `callId` is the message id for every call of a turn (`llm-meter.ts:35-40`, `assistant.service.ts:292`), so a turn with three tool rounds yields three events with the same aggregate id, which S18's de-dup (`llm:<aggregateId>`) would collapse into one → `callId = "<messageId>:<n>"`, unique per provider call including failed attempts and the summary (`:0`) → billing must count every call.
- [BREAKING] The monthly limit falls back to a local default (`assistant-quota.service.ts:9,35`, `assistant_buyer_tokens_per_month`) and the counter is a bare Redis key that restarts at 0 if lost → limit only from S18's `EntitlementsService.get`, counter seeded from `checkQuota` when absent, billing unreadable → `503` fail closed; config key removed → a silent default plan hands out free tokens when billing is down; cost control must fail closed.
- [BREAKING] Quota charging swallows errors (`assistant.service.ts:293`) and is not idempotent per call → charge is idempotent by `callId` and its failure is retried and counted; aborted calls are charged an estimate → a disconnect-and-retry loop must not read answers for free.
- [BREAKING] The real provider is replaced by the scripted echo model whenever `ANTHROPIC_API_KEY` is missing (`llm.module.ts:14-15`), also in production → startup fails when the real provider has no key; the scripted provider is refused in production → a misconfigured deploy must not serve fake answers.
- [BREAKING] No moderation exists anywhere in the module → input moderation before any lock (422 `input_rejected` by category), sensitive-data rejection (card numbers, secrets), per-chunk output moderation with context, fail closed → the notes require moderation of input and output and no secrets in prompts; this is a new behaviour and new error codes for W05.
- [BREAKING] `done` carries `costMicros` and cache counters (`assistant.service.ts:145,189`) → client-facing `done {stopReason, truncated, usage: {inputTokens, outputTokens}, allowance: {used, limit}}` only → V.1 (internal pricing and provider details do not belong in client payloads).
- [BREAKING] `GET /assistant/usage` returns `{used, allowance}` (`assistant-quota.service.ts:38-41`) → `{used, limit, resetsAt}` → names match S18's `checkQuota` and `/me/usage`; a client needs the reset time to show "back on 1 Nov".
- [BREAKING] Circuit breaker named in the notes and showcase table is absent; only the SDK's own retries and one fallback exist → per-model breaker (5 consecutive transient failures, 30 s cooldown, one probe), both open → `503 assistant_unavailable` at admission, forced-path tests → P0617 and VII.9.
- [BREAKING] Provider `Retry-After` is read (`anthropic.provider.ts:101`) but only passed through; nothing stops the fleet hammering a limited model → fleet-wide per-model cooldown → P0417 (consume rate-limited APIs with `Retry-After`).
- [BREAKING] No timeouts besides the 120 s SDK request timeout (`anthropic.provider.ts:6`) and the 5-minute lock → first-token (30 s), whole-call (120 s), tool (5 s) and turn (4 min) deadlines; a first-token timeout is transient and uses the fallback → IV.6; a hung provider would otherwise hold a conversation for 5 minutes.
- [BREAKING] A crashed generator leaves viewers waiting forever and the conversation locked for up to 5 minutes (`generation-buffer.ts`, lock at `assistant.service.ts:118`) → generator liveness marker; viewers get one `GENERATION_LOST` and the lock is reclaimed in about 15 s → resumable streams must end.
- [BREAKING] Cancel of a finished generation answers `202` and does nothing (`assistant.controller.ts:94-98`, `assistant.service.ts:134-139`) → `409 generation_finished`; repeated cancel while cancelling stays `202` → illegal state transitions are `409` (III.7, VII.3).
- [BREAKING] `GET /assistant/conversations` returns the first 20 with no cursor (`conversation.store.ts:57`) and there is no delete → keyset cursor (`limit` ≤ 50, default 20) and `DELETE /assistant/conversations/:id` → III.10 and the notes' data-retention point (users must be able to erase chats).
- [BREAKING] Body location handling silently ignores a lone `lat` or `lng` (`assistant.controller.ts:75`) → `400` → silent partial input hides client bugs.
- [BREAKING] Product tools go through `ProductService` (catalog internals, `assistant-tools.ts:4,107,113`) and `AvailabilityIndex` (fulfilment internal, `:5,121`) → S32 `ProductSearchService.search` (surface `internal`), S05 `ProductQueryService.getProductsByIds`, S19 `PickupNearMeService.searchNear` (R1), tools filter to active, non-sandbox products and drop seller-private fields → IX.4, X.4, D-7/D-12; today `product_details` can return an archived product's data.
- [BREAKING] The LLM port, adapters, pricing and meter live in `assistant/infra/llm` and are imported by seller-onboarding and the Lambda → move to `libs/infrastructure/llm` (domain-agnostic, scripted adapter included); `assistant` index stops exporting them → D-14, X.3.
- [BREAKING] A per-user cap on concurrent replies does not exist (only one per conversation) → 3 per user, `429 too_many_active_turns` → without it N conversations multiply the soft allowance overshoot and the provider load by N.
- [BREAKING] Graceful shutdown is not defined for running generations → readiness fails, new sends `503`, drain 25 s, then abort with `SHUTTING_DOWN` → VIII.4.
- [BREAKING] Generation retention is 10 minutes (`generation-buffer.ts:21`) → 15 minutes, equal to the idempotency window → a replayed key always finds its events.

## CONTRACT

- [CONTRACT] S19 exports only `PickupAvailabilityService.checkAvailability` and says "no `AvailabilityIndex`" (S19 spec, Cross-capability contracts) → S19 must add `PickupNearMeService.searchNear({q, lat, lng, radiusKm, limit}) → {items: {productId, title, category, priceMinor, currency, nearest: {pickupPointId, name, distanceM, quantity}}[]}` (R1, no cursor) → the assistant's `pickup_near_me` tool has no other approved path (IX.7: HTTP between domains is forbidden, R3 would duplicate S19's index).
- [CONTRACT] S18 asked for `llm.call_completed` v1 extended additively with `subjectId`, `metric`, `billableTokens` → done, plus `callId`, `outcome`, `usageEstimated`; `aggregateId = callId`; the metric for chat and summary is `llm.assistant.tokens`; `eventId` deterministic per `callId`; published through the outbox → S18 keys identity on `llm:<aggregateId>`, so a unique call id is what makes retries safe.
- [CONTRACT] S18's `checkQuota` is used only to seed a missing month counter; per-send admission uses the local counter and `EntitlementsService.get` → ClickHouse usage lags events by seconds, so it cannot gate each send; both sides derive from the same per-call `billableTokens`, so they converge.
- [CONTRACT] S04 asked for a port with `complete({model, system, messages, tools, outputSchema, maxTokens, timeoutMs})`, document and image blocks, typed transient error, no internal retry, metering by `llm.call_completed` → provided by `@app/infrastructure/llm` (`maxRetries: 0` supported, `LlmUnavailableError` transient, `LlmRejectedError` not, `LlmCallRecorder.record` appends the event with caller-supplied `subjectId`, `callId = "<documentId>:<attempt>"`, `purpose: "extraction"`) → S04 can switch its import and drop `LlmMeter`, `UsageService`, Kafka and ClickHouse imports.
- [CONTRACT] `llm.call_completed` is defined and emitted by `libs/infrastructure/llm` for every caller, not by the `assistant` domain alone (the domain map says "assistant emits") → one technical metering event for all LLM users; `docs/architecture/domain-map.md` §2 `assistant` Emits line should read "`llm.call_completed` (via `infrastructure/llm`)" → X.3 allows technical libs generic over payload; S04 and S47 cannot import assistant.
- [CONTRACT] The circuit breaker is a generic primitive in `@app/common` (S54), reused by S13 and S43; S46 adds it there if absent → S13 questions already say S43 and S46 reuse the generic primitive, not payment logic; a breaker inside a domain would be copied three times.
- [CONTRACT] W05 must: send `Idempotency-Key` per message, handle the new codes (`input_rejected`, `too_many_active_turns`, `assistant_unavailable`, `idempotency_in_flight`), replace shown text on `refusal {source: "moderation"}`, resume with `Last-Event-ID`, show `usage` from `GET /assistant/usage` (`used`, `limit`, `resetsAt`) → the stream and error contracts changed (BREAKING items above).
- [CONTRACT] S05's `ProductQueryService.getProductsByIds` must return `status`, `isSandbox`, `brand`, `rating`, `inStock`, `description` (S05 DTO already lists them) and unknown ids absent → the tool filters to `ACTIVE`, non-sandbox; if S05 later restricts fields, the tool needs them.
- [CONTRACT] S32's `ProductSearchService.search` must return `brand`, `rating`, `inStock` per item and apply visibility rules → the tool shows brand and rating (S32's HTTP shape has them; the R1 shape says "same as HTTP").
- [CONTRACT] S50 keeps `llm.messages` (fail closed) and `llm.provider.tpm` (weighted cost, fail open) in its registry and adds `Retry-After` and rate-limit headers → both exist today (`rate-limit.types.ts:58,63`).
- [CONTRACT] S47 shares the provider port, recorder, moderation port and breaker, and states its own admission limits (`rag.ask`) → same domain; S47 must not add a second provider path.

## LOCAL

- [LOCAL] Per-turn model routing (cheap model for simple turns) → not done; the summary model (Haiku) is the routed cheap work, effort `low` is the cost lever → switching model mid-conversation breaks the prompt-cache prefix and the thinking-block binding (SD-42 implementation notes); the notes' routing line is met by summary routing.
- [LOCAL] Persist whole turn only on `done` means a conversation's user message is lost on failure → the client keeps its text and retries with a new key; the cost is one retyped message, the gain is a transcript that is always valid.
- [LOCAL] Breaker is per process; cooldown from the provider is fleet-wide → each instance learns in 5 failures; sharing breaker state needs a fast store round trip on every call.
- [LOCAL] Moderation port with an always-on rule-based adapter (categories, sensitive data) and an optional provider adapter; categories fixed → deployment chooses the adapter; spec stays vendor-free.
- [LOCAL] Output moderation window = chunk + 256 preceding characters → catches phrases split across the 40 ms coalesced chunks without re-scanning the whole answer.
- [LOCAL] Active-reply cap 3, tool deadline 5 s, first-token 30 s, call 120 s, turn 4 min, heartbeat 15 s, grace 10 s, replay window 15 min, drain 25 s → defaults, all configuration with startup validation.
- [LOCAL] Conversation cap 400 messages; refuse when 400 − 12 would be exceeded (a maximal turn = user + 5 rounds × 2) → keeps the Scylla partition bounded; the UI offers "new chat".
- [LOCAL] Conversation list ordered by creation time (time-UUID clustering), not last activity → a last-activity order needs a second table; creation order is stable for a keyset cursor.
- [LOCAL] Retention of conversations not specified; the user can delete → platform policy owns retention.
- [LOCAL] Compaction threshold 60,000 estimated tokens (precise count at 80%); summary ≤ 300 words; keep-tail compaction rejected → as SD-42 (thinking blocks of retained turns would fail the prefix check).
- [LOCAL] Opaque per-user hash sent as the provider's end-user id → abuse tracking at the provider without sending the user id.
- [LOCAL] Metering outbox append retries 3 times with full jitter, then counts and logs `callId`, `subjectId`, `billableTokens` → the log line lets operations re-create the record; never fail the turn for metering.
- [LOCAL] Edge cases dropped as not worth a scenario: stream trimming at the 20,000-event cap (a maximal turn emits far fewer), per-token (uncoalesced) events, attachments.
