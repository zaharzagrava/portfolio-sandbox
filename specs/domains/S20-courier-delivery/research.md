# Research: S20 — decisions that were open

No NEEDS CLARIFICATION remain; `questions.md` defaults are accepted. Decisions the design had to make:

- **R-1 Store of record for offers.** Decision: Postgres `DeliveryOffer` with a partial unique index `(courierId) WHERE status='OFFERED'`; assignment uniqueness by a partial unique index on `Delivery(courierId) WHERE status IN ('ASSIGNED','PICKED_UP')`; Redis `SET NX` stays as a cheap pre-guard. Rationale: invariants must survive a Redis flush (AS-21/22, III.6). Alternatives: Redis-only lock (current, rejected); advisory lock per courier (works, not declarative).
- **R-2 Timers.** Decision: `Delivery.nextActionAt` + SQS delayed message + `recover-deliveries` job (15 s). Rationale: a crash between commit and enqueue must not strand a delivery (SC-004). Alternative: job-only polling (coarse for 15 s offers).
- **R-3 Accept atomicity.** Decision: one transaction updates the delivery (conditional on `OFFERED` and a live offer), the offer → `ACCEPTED`, and the courier `AVAILABLE→BUSY` (conditional). Redis removal after commit, repaired by the next ping and the recovery job. Alternative: saga with compensation (more states).
- **R-4 Offer expiry clock.** Decision: the accept statement compares `expiresAt` with a `:now` bound parameter from the injected `CLOCK` (not SQL `now()`), so frozen-clock tests are deterministic; all app instances share NTP time in production.
- **R-5 Per-shop open limit.** Decision: `pg_advisory_xact_lock(hashtext(shopId))` then `COUNT(*)` in the create transaction (same pattern as S19 R-5). Alternative: counter column (drift).
- **R-6 One non-terminal delivery per (order, shop).** Decision: partial unique index `(orderId, shopId) WHERE status <> 'CANCELLED'`: `DELIVERED` blocks, `CANCELLED` frees.
- **R-7 Fee math.** Decision: surge held as integer hundredths (100–300, step 25); `fee = (499 × s + 50) / 100` integer division (round half up); `feeMinor BIGINT`; `surge NUMERIC(4,2)` kept for display. No float in the money path.
- **R-8 Ring.** Decision: ring points `sha1(instance#i)` for i < 128; city owner = first point ≥ `sha1(city)`; live instances in a Redis hash refreshed every 10 s with 30 s expiry; `ownerOf(city, instances)` is a pure function; hand-back re-enqueues with a `handBacks` counter capped at 3. Correctness never depends on it.
- **R-9 Cell isolation.** Decision: every per-city Redis key carries a `{city}` hash tag, including `trackThrottleKey` (A26); a unit test inspects key shapes.
- **R-10 Order write-back.** Decision: job `fulfilment.apply-order-lifecycle` enqueued after commit and re-driven by the recovery job from `Delivery.orderSyncedStatus` vs. status; idempotent through `InvalidOrderTransitionError` handling. Alternative: inline call (network in the request path) rejected.
- **R-11 Queue.** Confirmed at T004: `delivery-offer-timeouts` (+ `-dlq`, maxReceiveCount 5, visibility 30 s) exists in `infra/docker/elasticmq/elasticmq.conf:39-40` and `infra/stack/main.tf:31`; nothing added. `delivery-offer-timeouts` already exists (`elasticmq.conf`, `infra/stack/main.tf`); this capability adds no queue, so no queue-server reload is needed (L-020). Standard queue: no `groupId` (L-001).
- **R-12 Producer payloads (confirmed at T003 from `packages/contracts/src/orders/order-events.ts` and `libs/domains/tenancy/domain/events.ts`).** Existing violators before creating the unique assignment index are checked inside the expand migration (T026).
  - `order.paid` v1 on `orders.events` (key `orderId`): `{orderId: uuid, userId: string, orderVersion: int>0, totalMinor, currency: string, paymentRef, paidAt, lines: [{productId, shopId: string|null, ...}], shopOrders: [{shopOrderId: string, shopId: string|null, subtotalMinor}]}`. There is no `buyerId` and no `shopIds` field: buyer = `userId`; shop list = distinct non-null `shopOrders[].shopId`; single-shop = exactly one `shopOrders` entry. No `shopVersion`.
  - `order.cancelled` v1: `{orderId, userId, orderVersion, reason: out_of_stock|payment_failed|hold_expired|user_cancelled, previousStatus}`; it carries no shop ids.
  - `tenancy.shop_deleted` v1 on `tenancy`: `{shopId: string, shopVersion: int}`.
  - `OrderFulfilmentService.apply`, `InvalidOrderTransitionError` and `OrderNotFoundError` live in `libs/domains/orders` (`domain/order-errors.ts`).
  - `defineEvent` is backend-only (`@app/infrastructure/events/define-event`); `packages/contracts` cannot import it, so (as in `contracts/src/community/events.ts`) `delivery.ts` ships the payload zod schemas and `application/events/delivery-events.ts` wraps them with `defineEvent`.
