## Deviations from the plan (P1 pass)

- Request bodies are validated with the contract schemas (`productCreateRequestSchema`, `productUpdateRequestSchema`, `productTransitionRequestSchema`) inside `ProductCommandService` instead of class-validator DTO classes, so HTTP and the exported commands refuse exactly the same input (`api/product.dto.ts` holds only the transition-body parser).
- The 503 for an unreachable database uses the platform code `database_unavailable` (S54) rather than `service_unavailable` of `contracts/http.md`.
- `ProductStockService` locks the product rows (`FOR UPDATE`, ordered by id) and decides before it writes, instead of the per-item conditional update with rollback, so a rejected call writes nothing even when it joins the caller's transaction; operations on one product in one call make one version step and one event, each with its own operation record.
- `ProductImportService` locks the `(shopId, externalSku)` row and retries a lost insert as an update instead of `INSERT … ON CONFLICT DO UPDATE … RETURNING xmax`.
- `ProductChanged`/`productChanged` now use `aggregateVersion` 0 (the old value was the wall clock in milliseconds, which would outrank every snapshot).
