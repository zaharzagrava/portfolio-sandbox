# Open Decisions for S12 (answered unattended)

Format: `[TAG] question → default taken → why`. BREAKING first, then CONTRACT, then LOCAL. The human reviews BREAKING and CONTRACT lines first. Decision policy: most production-grade option the Interview-Prep notes and the constitution support; no external clients to keep compatible, so correctness, security, observability and clean boundaries beat today's behaviour.

## BREAKING (changes behaviour or an API/UI contract that exists today)

- [BREAKING] Routes `POST /shops/:shopId/exports/orders` and `GET /shops/:shopId/exports/:jobId`, served by `catalog-sync`'s controller (`catalog-import.controller.ts:49-60`) → `POST|GET /shops/:shopId/order-exports[/:exportId]` plus `/cancel` and `/download`, served by `orders`; the old paths answer `404` with no alias, redirect or `Deprecation` header → the resource noun is in the path (V.5), the debt D-10 asks for the move, and there are no external clients (V.7's announce-first rule exists for clients that do not exist here).
- [BREAKING] Create answers `{jobId, status: 'QUEUED'}` with the default status (`order-export.service.ts:42-43`) → `202` with `Location` and the full job body `{exportId, status, rowsWritten, totalRows, bytesWritten, attempt, failure, createdBy, createdAt, startedAt, finishedAt, expiresAt}`; `jobId` becomes `exportId` → async request-reply (P0407, note 02/02 §4.1 "generate asynchronously and return a link"); stable DTO with a contracts schema (V.2).
- [BREAKING] The status route returns `{status, rows, objectKey, downloadUrl}` and signs a link on every poll (`order-export.service.ts:49-57`, leaks the storage key `objectKey`) → the job read never carries a storage location or link; the link comes only from `GET …/download` (10 min, audited), `409 export_not_ready` before `DONE`, `410 export_expired` after expiry → V.1 (no internal fields), least privilege, an audit trail of who fetched the data.
- [BREAKING] Starting needs no key and any number can run at once (`order-export.service.ts:38-44`) → `Idempotency-Key` required (V.6 replay / in-flight 409 / different request 422), at most **one** `QUEUED|RUNNING` export per shop enforced by the store (409 `export_already_active`), 5 starts per shop per hour (429) → a double click or a loop must not multiply 10-million-row jobs (III.6, VII.3 concurrency case); the old "request twice, get two jobs" test changes.
- [BREAKING] The export rides the import queue `catalog-imports` as `{kind: 'export', jobId}` (`order-export.service.ts:14,40`; worker branch `catalog-import.worker.ts:29`) → queue `order-exports`, message `{exportId}` only, 3 deliveries then dead-letter; the import worker loses its `kind` branch and its `OrderExportService` import → debt D-10, removes the X.5 edge `catalog-sync → orders`; S07's own `questions.md` already records the same removal.
- [BREAKING] Streaming reads through one server-side cursor held inside one long read, with a pooled connection kept for the whole run (`order-export.service.ts:66-77`) → keyset batches of 1,000 (`ORDER BY shop-order time, shop-order ID, line ID`), each its own short read, driven as an async generator into the same `pipeline` (P0102 + P0207); the file excludes orders created after the request but each line shows its status as of its batch → note 02/02 §4.1 names the trade-off (holds a connection and a snapshot for the whole download); a cursor pins a connection, a snapshot and vacuum for minutes, and cannot resume or be fenced; keyset batches obey III.3 and III.10 and keep memory flat. Costs exactness of a point-in-time snapshot (stated in Assumptions).
- [BREAKING] File content: `order_id` currently holds the **shop-order** ID (`so.id`, `order-export.service.ts:67,85`); columns `status`, `unit_price_minor` (from `priceAtPurchase`), `sku`/`title` from a `LEFT JOIN "Product"` (`:69`); no BOM; LF; no ordering tiebreaker (`ORDER BY so."createdAt"`) → columns `order_id, shop_order_id, created_at, shop_order_status, currency, product_id, sku, title, quantity, unit_price_minor, discount_minor, line_total_minor`; title from the S10 snapshot, SKU through R1; UTF-8 BOM and CRLF; a leading apostrophe on text cells that begin with `= + - @ TAB CR`; deterministic order; byte-identical re-runs → the old column was mislabelled data; the formula guard is the OWASP CSV-injection control for seller-controlled titles (05/01 injection family); IX.4 forbids the `Product` join; a determinism guarantee makes the file testable and diff-able.
- [BREAKING] A failed run is marked `FAILED` and the error rethrown (`order-export.service.ts:93-96`), but redelivery then finds `FAILED` and does nothing (`run` only claims `QUEUED|RUNNING`), so a transient storage error is final and the raw message (first 500 characters) is stored → failures are classified (AS-35): transient ones are retried by redelivery up to 3 deliveries, permanent ones fail at once; only a stable `failure.code` and a generic message are stored and returned → IV.6 (retry transient failures only, at one layer), V.3 (no upstream text to clients).
- [BREAKING] `ExportJob` states `QUEUED|RUNNING|DONE|FAILED`, `kind` column, `rows`, `error`, foreign keys to `Shop(id)` and `User(id)` (migration `20261002100000-catalog-import.js:33-44`) → adds `CANCELLED`, `EXPIRED`, `attempt`, `totalRows`, `bytesWritten`, lease and timestamps, `failureCode`; adds `ExportJobHistory`; drops both foreign keys (IX.4: a cross-domain reference is a plain ID); a partial unique index for the one-active-export rule; `rows → rowsWritten`, `error → failureCode`, `kind` dropped by expand/contract → III.7 (conditional transitions plus history), IX.4, III.11; test seeds that insert an `ExportJob` for a non-existent user now work, tests asserting FK errors go.
- [BREAKING] Files and records are kept forever → files deleted 7 days after finishing (`EXPIRED`, `410` on download), finished records deleted after 90 days → data minimisation of a bulk copy of sales data; a stale bearer link cannot outlive its file.
- [BREAKING] Live channel: topic `job:{id}` (prefix shared with imports and OR-ed, creator-only, `SELECT 1 FROM "ExportJob"` raw query in `realtime-topics.ts:20-24`), event `done {rows}` only → topic `order-export:{exportId}`, viewer policy "current member of the job's shop with `orders.manage`" through S03's `assertMember` (R1, no table access); events `progress`, `done`, `failed`, `cancelled`; terminal events replayable, progress not; `ExportJobTopicsModule` is renamed `OrderExportTopicsModule` → a removed member loses access (S03), exports are shop resources not creator resources, two domains must not share a prefix whose policies are OR-ed (S07 makes the same change on its side).
- [BREAKING] Barrel of `@app/domains/orders` exports `OrderExportService` and `ExportJobTopicsModule` (`index.ts:20-21`) and `catalog-sync` imports the service → both removed; new exports are `OrderExportModule`, `OrderExportWorkerModule`, `OrderExportTopicsModule` → X.4, D-8, D-10; `apps/core`, `apps/worker`, `apps/sse-gateway` wire the new module names.
- [BREAKING] The only export test is one case inside `catalog-import.e2e-spec.ts:120-128` that calls the service directly and exercises an empty shop → deleted there; a new `order-export*.e2e-spec.ts` family boots the real routes (VII.2) → S07's test plan already says "its order-export test moves to S12".

## LOCAL (internal to this capability)

- [LOCAL] Batch size → 1,000 lines → the notes' example and `batchSize` today.
- [LOCAL] Read-ahead bound → ≤ 3,000 lines when storage is stopped → batch in flight plus transform and stringify buffers; a number the backpressure test can assert.
- [LOCAL] Resume after a crash → restart from the beginning (abort the old upload, rewrite) rather than checkpoint a multipart upload → a streamed upload has no resumable position; exports are bounded by the row limit.
- [LOCAL] A stale worker's upload → written to a per-attempt location and promoted only by the fenced completion → one rule for crash, cancel and fencing (AS-42, AS-45, AS-50); the exact mechanism is the plan's.
- [LOCAL] Row limit 20,000,000 and deadline 2 h → config defaults; roughly a 2.5 GB file at the limit.
- [LOCAL] Lease 5 min renewed every 60 s; unclaimed recovery 2 min; backoff 60 s ± 20 % → copies S07 so the platform has one set of numbers.
- [LOCAL] Cancel of a cancelled export → `200` unchanged, not `409` → the outcome the caller wanted already holds; replays are safe.
- [LOCAL] Graceful shutdown restores `attempt` → a deploy must not burn a retry.
- [LOCAL] Progress persisted at the publish cadence (≤ 1/s, first and last batch always) → the polled job and the live channel agree; no write per row.
- [LOCAL] `totalRows` is counted once at the start of a run, bounded by the request time → gives an honest percentage; a lost or reset count is recomputed on the next claim.
- [LOCAL] Legacy lines whose shop is null are not exported → ownership unknown; the S10 backfill is expected to fill them.
- [LOCAL] History table name `ExportJobHistory`, one row per transition with `reason` (`retry`, `lease_expired`, `retention`, `shop_offboarding`, …) → III.7.
- [LOCAL] Download audit is a structured log line, not a table → no new table for an operational record; the registry stays small (IX.3).
- [LOCAL] Active-export cap is 1, not N → simplest rule that is also fair between shops; raise by configuration if ever needed.
- [LOCAL] No filters, one format → keeps this capability small; additive later (V.7).
