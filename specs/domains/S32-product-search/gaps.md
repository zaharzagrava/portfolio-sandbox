# Gaps: S32 — current `discovery` search code versus the spec

The implementation agent's to-do list. Paths are under `packages/backend/libs/domains/discovery/` unless stated; line numbers are those read on 2026-10-05. Questions behind each row are in [`questions.md`](questions.md); scenario IDs refer to [`spec.md`](spec.md).

What exists: one controller (`api/search-admin.controller.ts`, 71 lines: shop search, click, quality report, synonyms, reindex trigger), four services (`shop-product-search.service.ts`, `search-reindex.service.ts`, `search-quality.service.ts`, plus the autocomplete, trending and recommendation services that belong to S33–S35), a query logger and two ClickHouse projectors (`infra/search-query-logger.ts`, `infra/search-queries.projector.ts`, `infra/search-clicks.projector.ts`), two modules (`search-admin.module.ts`, `search-reindex-worker.module.ts`), one e2e spec of three tests that calls services directly (`search-reindex.e2e-spec.ts`). The public search itself is **not in this domain**: it is in the catalog (`catalog/api/product.controller.ts:30-38`, `catalog/application/product.service.ts:60-76`), the product index adapter is in `libs/infrastructure/elasticsearch/elasticsearch.service.ts` (420 lines) and the index projector is in the catalog (`catalog/infra/product-search.projector.ts`). There is no `domain/` folder for search, no port, no run record, no synonym store, no contract schema in `packages/contracts`, and no consumer test.
