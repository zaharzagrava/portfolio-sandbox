# Open Decisions for S29 (answered unattended)

Format: `[TAG] question → default taken → why`. BREAKING first, then CONTRACT, then LOCAL. The human reviews BREAKING and CONTRACT lines first. Decision policy: most production-grade option the Interview-Prep notes and the constitution support.

## BREAKING (changes behaviour or an API/UI contract that exists today)

- [BREAKING] `GET /media/:id` (today anonymous, any status, returns `rejectReason` with the raw decoder message and the variants) → public only for `READY` (`mediaPublicSchema`); the uploader (and shop members) see every status with a stable `rejectCode`; everybody else gets one identical `404` → III.4, V.4 (existence hidden), V.1 (no internals); a pending or rejected private upload must not be readable by guessing a UUID.
- [BREAKING] Status machine (today `PENDING_UPLOAD → PROCESSING → READY | REJECTED`, `complete` does not change the status) → adds `UPLOADED`, `EXPIRED`, `DELETED`, a history table, `attempts`, a lease and a `version`; `complete` moves `PENDING_UPLOAD → UPLOADED` before the message is sent → III.7 (conditional transition plus history row), design 27 note (`PENDING → UPLOADED → PROCESSING → DONE/FAILED`), makes lost messages recoverable and replays harmless; the CHECK constraint, the processor claim and existing tests change.
- [BREAKING] Rejection reason (today `Media.rejectReason` = decoder message such as `not a decodable image: Input buffer contains unsupported image format`) → closed code vocabulary `rejectCode` (`not_an_image`, `format_not_allowed`, `multi_frame`, `image_too_large`, `size_invalid`, `malware_detected`, `processing_failed`); column renamed by expand/contract → V.3 (no upstream messages to clients); stable codes are testable.
- [BREAKING] Event `media.ready` (today `{mediaId, shopId, purpose, variants, possibleDuplicateOf}` written by raw SQL in the Lambda) → `{mediaId, mediaVersion, shopId, uploaderId, purpose, width, height, variants, duplicateSuspected}`; `possibleDuplicateOf` removed → `possibleDuplicateOf` names a photo of another shop: a cross-tenant leak to every consumer; IX.8 needs `mediaVersion`; the match goes only to the moderation event `media.duplicate_suspected`.
- [BREAKING] Events written by raw `INSERT INTO "Outbox"` in `media-processor.ts` → `outbox.append` from the outbox lib (a framework-free function the Lambda can call) → IX.6 and the domain-map §4 row (`Outbox`: only `outbox.append()`); new events `media.rejected`, `media.deleted`, `media.gallery_changed`, `media.duplicate_suspected`.
- [BREAKING] Upload purposes (today `review | post | product`) → `review | product`; the `post` purpose is removed → S25 specifies text-only posts and says the media promise of "discussion posts" is not kept; the purpose can be added additively when a capability needs it.
- [BREAKING] Review upload rate limit (today borrows `discussion.write`, 10/min, so uploads eat the posting budget; shop route has none; `complete` has none) → own policies `media.upload.user` 30/min, `media.upload.shop` 120/min, `media.gallery.shop` 60/min (all fail closed) and `media.read.ip` 600/min (fail open) → S25's gaps ask for exactly this; abuse of presign is a cost attack on storage.
- [BREAKING] Presigned policy content type (today prefix `image/`, which admits `image/svg+xml`, `image/gif`, `image/tiff`) → an exact list (JPEG, PNG, WebP, AVIF), minimum body size 1 → defence in depth; the pipeline still decides from the bytes (design 27: "don't trust the extension").
- [BREAKING] `complete` on a missing object (today `400`), on a terminal state (today `200 {status}` for anything) → `409 upload_incomplete` / `409 upload_expired` / `404` for deleted; `202` when work is pending, `200` when finished → V.4 (409 for state conflicts); clients can tell "retry" from "done".
- [BREAKING] Gallery write (today `PUT .../gallery {mediaIds}`: delete-all then insert-N in one transaction, last writer wins, product existence via a SQL join on `Product`, one `400` for everything, no event) → `PUT` with `expectedVersion`, `422 media_not_attachable` with per-photo `failures`, `409 version_conflict`, `409 product_archived`, a `ProductGallery` version row, a `media.gallery_changed` event, product check through S05 R1 → note 03/02 (optimistic concurrency), III.6, IX.4, IX.6; the web seller gallery editor (W04) will send `expectedVersion`.
- [BREAKING] Duplicate detection scope (today every photo of any purpose against any other shop, `LIMIT 200` with no order, first hit under distance 3 wins, outside the READY transaction) → `product` photos only, nearest match wins, near-uniform hashes never match, 500-candidate cap with a counter, scan serialised per band inside the READY transaction → fewer false positives (a buyer re-posting a seller's picture is not theft; a blank image is not a match), and two simultaneous copies can no longer both miss each other.
- [BREAKING] Processing claim (today any worker re-claims a `PROCESSING` photo at any time, `SKIPPED` only for finished ones) → a 5-minute lease and a 5-attempt cap; a held lease answers `BUSY`; the fifth claim rejects with `processing_failed` → note 27 ("idempotent processing per upload ID, visibility timeout > processing time", "DLQ for poison files"); stops two workers from processing one photo and poison files from looping.
- [BREAKING] Malware scan (today none for photos; the `clamd` config key exists and only `catalog-sync` uses it) → mandatory before any variant is written, outage is a transient failure, only a non-production switch skips it → P0509 names AV scan; S07 already built the adapter.
- [BREAKING] Media origin (today `media_cdn_url` optional, falling back to `<s3_endpoint>/<bucket>` URLs, i.e. the storage endpoint) → mandatory in production, validated at startup to be a different site from the web app and the API → P0509 ("separate domain"); a missing setting must not silently expose the bucket.
- [BREAKING] Colour handling (today the variants keep the source's colour space unconverted) → convert to sRGB before encoding → wide-gamut phone photos otherwise look washed out once the profile is stripped.
- [BREAKING] Input limits (today `heif` allowed, animated WebP accepted as its first frame) → AVIF, JPEG, PNG, WebP only; multi-frame images rejected as `multi_frame`; the size is re-checked at completion → predictable output; animated images are a different feature.
- [BREAKING] Foreign keys `Media.shopId → Shop`, `Media.uploaderId → User`, `ProductMedia.productId → Product (ON DELETE CASCADE)` → dropped by expand/contract migrations (lock timeout, one step each); the cascade becomes the `catalog.product_deleted` consumer → IX.4 (cross-domain reference is a plain ID).
- [BREAKING] `MediaProcessor`, `Sql` exported from the barrel (apps/lambdas builds a processor with raw `pg`) → replaced by `createMediaProcessor(deps)`; the Lambda passes its adapters; `MEDIA_QUEUE` stops being exported → D-8, X.4.
- [BREAKING] `media.e2e-spec.ts` calls `MediaService` and `MediaProcessor` directly with the queue mocked → replaced by the supertest suites of `test-plan.md` → VII.2 (HTTP through the real pipeline), VII.3 (401, IDOR, validation, 429, concurrency), VII.6 (contract schemas).

## LOCAL (affects only this capability's internals)

- [LOCAL] Variant set and quality → `thumb` 200, `feed` 640, `full` 1600, WebP q80 → the notes' three sizes; AVIF skipped for encode cost.
- [LOCAL] Perceptual hash → keep dHash (9×8, 64 bits) with four 16-bit bands, threshold 3 → notes and migration; pigeonhole guarantees recall.
- [LOCAL] Where the scan is serialised → advisory locks on the four band values taken in ascending order inside the READY transaction → two simultaneous near-duplicates see each other.
- [LOCAL] Lease 5 min, attempts 5, run limit 45 s, read 20 s, variant write 10 s, scanner 15 s → below the 60 s function timeout and above one image's work.
- [LOCAL] Upload slot life 60 min, purge 7 days, stuck thresholds 2 and 10 min → comfortably past the 10-minute signature life.
- [LOCAL] Delete is soft (`DELETED`) and objects are reclaimed by the purge → a request never does storage I/O; shared content-addressed variants are kept while any live photo references them.
- [LOCAL] Gallery cap 20, position 0 is primary, whole-list replace → same as today, plus a version.
- [LOCAL] Public read cache header `public, max-age=15` → short, so a takedown is visible within seconds without a CDN purge.
- [LOCAL] Pending-upload quota 50 per scope → generous for a 20-photo gallery, bounds orphan rows.
- [LOCAL] Image library calls stay in `infra/`; hash comparison, band split, matching rules and the status table move to `domain/` → I.3, and they become table-driven and property-testable.
- [LOCAL] Duplicate detection is not applied to `review` photos → see BREAKING scope line.
- [LOCAL] No `Idempotency-Key` on the upload routes → V.6 lists only orders, payments, bookings, bids and ledger movements; replays are safe by design (a repeated presign creates an unused slot that expires).
