# Research: S34 — Bought Together Recommendations

- **R-1 R1 lookups (read 2026-10-10).** `ProductQueryService.getProductsByIds(ids, options?)` returns `Map<string, ProductDto>` with `title, priceMinor, currency, status, isSandbox, inStock, shopId`; `ShopQueryService.getShopsByIds(ids)` returns `Map<string, ShopSummaryDto>` with `status`. Both are exported from the domain entry points and both modules are already loaded by `apps/core`. Decision: one `CatalogFacts` port in `domain/` with an `infra/` adapter that calls both (product call first for the pool, then shop call for the distinct `shopId`s of products found), each under its own timeout (100 ms, 50 ms) and mapping any throw/timeout to a typed `LookupUnavailableError` → `503`. Alternative rejected: injecting the services directly in `application/` (no single place for the budgets, harder to inject faults).
- **R-2 Pool and expansion trigger.** Pool = requested id + ≤ 20 direct + ≤ 5 × 20 second-hop = ≤ 121 ids, under the 500 limit. Expansion runs when the count of valid stored direct entries (after sanitising, before visibility) is below `limit`; this keeps AS-16 (8 direct, limit 8 → 1 read), AS-19 (hidden seed still bridges) and AS-10 (10 direct, limit 4 → no expansion). Seeds' lists are read in full (20), which is A7's fix. Alternative rejected: expanding after the visibility filter (needs a second R1 round trip).
- **R-3 ClickHouse basket table.** A `ReplacingMergeTree`'s version column cannot be added with `ALTER`; `questions.md` assumed new nullable columns. Decision: new table `recommendation_baskets (order_id, buyer_id, products, paid_at, order_version, inserted_at)`, `ENGINE = ReplacingMergeTree(order_version)`, `ORDER BY order_id`, 13-month TTL on `paid_at`. Projector writes only the new table; the old `order_baskets` stays untouched until the replay of `orders.events` is done and the build is switched, then `042_drop_order_baskets.sql` removes it (contract step). The build reads the new table `FINAL`. Alternative rejected: keeping `order_baskets` with nullable columns and a read-time `argMax` (no engine-level version guard, FINAL would not pick the highest version).
- **R-4 Version guard.** The engine keeps the highest `order_version` per `order_id` at read (`FINAL`), but "lower or equal changes nothing, and counters say stored/duplicate/stale" needs an explicit check: the capture service looks up the stored `max(order_version)` of the batch's order ids in one query, inserts only strictly higher versions, counts the rest as `duplicate` (equal) or `stale` (lower). Two concurrent deliveries of the same version both insert identical rows; `FINAL` collapses them (AS-30 asserts one basket after reading with `FINAL`). Idempotency mechanism declared: `versionGuard`.
- **R-5 Payload validation.** The projector declares the `order.paid` event with the `orderEventSchemas['order.paid']` shape from `packages/contracts`, extended in `domain/recommendation-events.ts` with `lines: min(1)` and UUID `productId`, so the framework dead-letters malformed payloads (AS-31) and ignores other types on the topic (AS-32). No import of `@app/domains/orders`.
- **R-6 Build query.** Kept: double `ARRAY JOIN`, `cityHash64(a) % buckets`, `LIMIT k BY a`. Changed: source `recommendation_baskets FINAL WHERE paid_at >= {since:DateTime64}` (`since` computed from the injected clock, so frozen time works); pair `HAVING co >= minCo AND uniqExact(buyer_id) >= minBuyers`; `n(p)` counts every eligible basket of `p`; order `a, score DESC, b ASC`. Score is symmetric because `ia.n * ib.n` is commutative.
- **R-7 Atomic publish and removal.** Per list: `DEL staging; ZADD staging; EXPIRE staging ttl; RENAME staging live` in one pipeline (hash tag keeps the pair in one slot), kept from today. Each bucket's published product ids are added to a temporary Redis set `rec:build:{runId}` (TTL 2 h). After the last bucket succeeds, `SCAN MATCH rec:bought:*` (skip `…:next`) and delete keys whose product is absent from the set (`SMISMEMBER` in batches); `removed` counts them. A failed build never reaches this step (AS-38, AS-40). `KEYS` is not used (III.9). The shared client is single-node ioredis, so `SCAN` sees every key.
- **R-8 Lock.** `SET rec:build:lock <token> NX PX 3_600_000`; release by compare-and-delete Lua. A holder that crashes loses the lock after the lease (AS-41). `fleetConcurrency: 1` already limits the fleet; the lock covers direct invocations (tests, operators). Alternative rejected: a Postgres advisory lock (adds a PG dependency for a non-PG capability).
- **R-9 Empty source.** The build first runs a cheap `SELECT count() … LIMIT 1` over the window; zero → `{outcome: 'skipped_empty'}`, metric `recommendations_build_skipped_total{reason="empty"}`, nothing written or removed.
- **R-10 Time budgets.** A shared `withBudget(promise, ms)` (race against a timer, timer cleared) around the Redis reads and each R1 call; on timeout the underlying call is abandoned, the request answers `503` and no retry runs. Redis `maxRetriesPerRequest: 2` and `enableOfflineQueue: false` already make a down store fail fast.
- **R-11 Headers.** As in S33's `SuggestController`: set `Cache-Control: no-store` first, replace with `public, max-age=60, s-maxage=300` only when the service returned a body, so every thrown problem keeps `no-store`. `503` adds `Retry-After: 5` (typed error → global filter). No `Vary: Cookie/Authorization`; the route is `@Firewall({ anonymous: true })` and an invalid bearer is ignored (to be verified in AS-07 against the firewall; if the firewall rejects bad tokens, the route opts out of token parsing).
- **R-12 Rate limit.** Add `discovery.recommendations` (sliding window, 600/min, key `ip`, fail open) to `discoveryRatePolicies`; the `search.query` reuse is removed.
- **R-13 Config.** New keys (defaults in `common/config/recommendations-config.ts`, joi, fail at startup naming the key): `REC_MIN_CO_ORDERS` 3 (≥ 1), `REC_MIN_BUYERS` 3 (≥ 1), `REC_TOP_N` 20 (1–20), `REC_WINDOW_DAYS` 180 (1–390), `REC_BUCKETS` 16 (1–256), `REC_TTL_SECONDS` 259200 (≥ 1), `REC_EXPAND_SEEDS` 5 (1–20), `REC_HOP_DECAY` 0.5 ((0,1)), `REC_STORE_BUDGET_MS` 100, `REC_PRODUCT_BUDGET_MS` 100, `REC_SHOP_BUDGET_MS` 50 (each ≥ 1), `REC_BASKET_MIN` 2, `REC_BASKET_MAX` 30. Job payload defaults come from the same settings.
- **R-14 Transactions.** The recommendations files hold no `sequelize.transaction` and no `// S54 T037 audit` comment (baseline `.tx.baseline` = 0); nothing to migrate or add.
- **R-15 Metrics.** `recommendations_requests_total{result}`, `_hops_total{hops}`, `_bad_entries_total`, `_basket_skipped_total{reason}`, `_baskets_total{outcome}`, `_build_duration_seconds`, `_build_products`, `_build_edges`, `_build_last_success_timestamp`, `_build_skipped_total{reason}` in `infra/recommendations-metrics.ts` through `MetricsRegistry`; labels are fixed enums. The 36-hour alert rule is an ops artifact.
- **R-16 Sibling files.** Web/BFF/GraphQL consumers, the Playwright journey and the BFF composition tests belong to W02/S48; S50's registry entry is declared here and listed under "Sibling-spec follow-ups" in `gaps.md`.
