# Questions and defaults: S44 — Embeddable storefront widget

Decisions taken unattended, sorted by impact. Review `[BREAKING]` and `[CONTRACT]` lines first. Policy: most production-grade option the notes and the constitution support.

## [BREAKING]

- [BREAKING] Permission on dashboard routes (today `shop.manage`, so every manager-level role can mint identity secrets) → new `widget.manage` (OWNER, ADMIN) on every route including reads → the routes mint and rotate a secret; III.4, V.4. Existing callers and the e2e fixture must use a member with that permission.
- [BREAKING] Origin registration (today `normalizeOrigin` silently drops path, query and fragment, accepts IP literals, `localhost`, single-label hosts, and invalid input answers `403`) → strict bare `https` origins only, closed rejection reasons, `422 origin_invalid {origin, reason}`; no wildcards, no `http`, no `localhost` → exact-origin trust is the root of the model (SD-01, 10/04 §1); `403` is for authorisation, not input.
- [BREAKING] Public `config` price shape (today `price: Number(<decimal string>)`, a float) → `price: {amountMinor, currency}` integer minor units; products come only from S05 R1 in configured order, archived and foreign products hidden (today SQL `IN (:ids)` with undefined order, archived products shown) → III.8, IX.4, D-12. The loader and any consumer of `config` must read the new shape.
- [BREAKING] How `config` gets shop and product data (today raw SQL on `Shop` and `Product` in the widget service) → product by S05 R1 `getProductsByIds(ids, {shopId})`; shop name and status by an R3 copy on the site (S03 events), seeded once by R1 `getShopsByIds` → IX.4, IX.7, D-12, D-7. The existing e2e (`widget.e2e-spec.ts`) injects the tenancy `Shop` model and seeds `Product` rows; it is rewritten through exported services and shared fixtures.
- [BREAKING] Embed document CSP (today `default-src 'self'; script-src 'self'; frame-ancestors …`, no nonce, no `base-uri`/`object-src`/`form-action`; the script URL `/widget/v1/app.js` lacks the `/api` prefix; `embed` for a switched-off site returns `410` with an empty body) → nonce + `strict-dynamic`, `default-src 'none'`, `object-src 'none'`, `base-uri 'none'`, `form-action 'self'`, `Cache-Control: no-store`; every refusal is problem+json and carries `frame-ancestors 'none'`; the bundle URL is configuration owned by W07 → P0502, 05/01 §2.1, §2.5.
- [BREAKING] Kill switch (today `PUT …/kill-switch` returns `204`, is an unconditional update with no history and no event, and the site cache keeps a per-process layer for 10 s so other instances keep serving) → `200 WidgetSiteDto`, idempotent conditional update with a history row and an outbox event on change only, no per-process site cache, effective on the next request on every instance; it now also stops `identify`, `session` and issued tokens; a non-`ACTIVE` shop disables its sites → SD-01 kill switch row, III.7, III.9, IV.4.
- [BREAKING] Widget token (today signed with the general `jwt_secret`, `typ: "widget"`, `aud: "widget"`, no `jti`/`iss`) → a dedicated signing key (startup fails without it), `typ: widget+jwt`, `aud: marketplace-widget-session`, `iss: marketplace`, `jti`; refused by every other verifier and vice versa → token confusion, VIII.7, S01 moves access tokens to ES256 and may drop `jwt_secret`.
- [BREAKING] `identify` hardening (today rate-limited with the login policy `auth.login.ip`, a store failure is a `500`, content type not enforced, `iat` required by `maxAge`, claim limits implicit, email unchecked) → own policies `widget.identify.ip` / `widget.identify.site`, `503` fail-closed without consuming the token, `415` for non-JSON, `413` over 8 KiB, closed claims policy (AS-24), identical `401 identity_token_invalid` body for every rejection → stops widget floods from consuming login budgets, P0504, 05/02 JWT validation.
- [BREAKING] CORS on widget routes (today the controller sets `Access-Control-Allow-Origin` by hand on top of the global CORS middleware, which reflects any origin when `cors_allowed_origins` is unset and sends `credentials: true`; no per-site preflight, so the JSON `identify` call only works if the global allowlist happens to include the shop) → per-site CORS with registered-origin echo, `Vary: Origin`, no credentials, exact preflight answers, global policy bypassed for these routes → 10/04 §1, 05/01 §4.
- [BREAKING] `config` caching and errors (today `public, max-age=60, s-maxage=60` for success only, `skipThrottle: true`, every error uncached by default, a site-cache negative entry of 60 s) → success as today; `410` cacheable 30 s; every other error `no-store`; unknown-key memory ≤ 30 s and malformed keys never cached; stale-on-error 600 s for the shaped response; `widget.config.ip` fail-open policy → SD-01 scale section (switched-off sites must not melt the origin).
- [BREAKING] Identity secret storage (today sealed with no context; only one secret ever; no rotation) → sealed with context `widget-site:<siteId>`, plus a previous secret with an overlap window and `rotate-secret` / `expire-previous-secret` → P0518 (S01 `SecretBox` context), same dual-secret rule as S43 (P0418). A one-off re-seal of existing rows is required.
- [BREAKING] Data model (today `WidgetSite` has a foreign key to `Shop`, no `name`, `version`, previous secret, shop copy, history table, or constraints) → drop the FK (expand/contract), add `name`, `version`, `previousIdentitySecretSealed`, `previousSecretExpiresAt`, `shopName`, `shopStatus`, `shopVersion`, `updatedAt`, check constraints (1–10 origins, key format), new owned table `WidgetSiteChange` → IX.4 (no cross-domain FK), III.7, III.11. Registry entry for the new table.
- [BREAKING] Management API surface (today only `POST sites` and `PUT kill-switch`, no list, read, update, delete, theme, rotate; `POST` returns `{id, publishableKey, identitySecret, allowedOrigins}`; theme and featured products cannot be changed after creation) → full surface of the Provides list with `WidgetSiteDto`, keyset list, optimistic `expectedVersion`, history → the notes' "site keys bound to registered origins" is unusable without editing origins; III.10, V.5.
- [BREAKING] Theme (today `Record<string,string>` stored and echoed without validation, and no way to set it) → allowlisted keys with strict value formats, validated on write and re-checked by the loader → a theme value rendered into a host page is an injection path (05/01 XSS).
- [BREAKING] Error taxonomy (today `403` for a malformed origin on create and `403`/`404` strings from `ForbiddenException`/`NotFoundException`, unknown site on the dashboard is a bare `404`) → problem+json with the codes `origin_invalid` 422, `origin_not_allowed` 403, `widget_site_not_found` 404 (dashboard and public, identical for cross-shop), `widget_disabled` 410, `identity_token_invalid` 401, `widget_token_invalid` 401, `site_limit_reached` 422, `site_version_conflict` 409, `rotation_in_progress` 409 → V.3, V.4.
- [BREAKING] Shop lifecycle (today a switched-on site keeps working for a suspended or deleted shop, and the FK blocks shop deletion) → consume `tenancy.shop_status_changed` / `tenancy.shop_updated` / `tenancy.shop_deleted`; sites of a non-`ACTIVE` shop answer `410`, deleted shops lose their sites → IV.4, IX.7 R3.
- [BREAKING] Rate limit on creation and rotation (today none) → `widget.manage.shop` 60/min fail-closed, 10 sites per shop enforced by the store → III.6.

- [CONTRACT] Shop copy: S03 events `tenancy.shop_updated {shopId, name, slug, shopVersion}`, `tenancy.shop_status_changed {shopId, from, to, shopVersion}`, `tenancy.shop_deleted {shopId}` and `ShopQueryService.getShopsByIds` returning `status` and `shopVersion` → exactly what S03 already provides (its questions line names the widget as a consumer of R1 and R3); no change requested → honoured, listed so S03 keeps `shopVersion` monotonic.

- [CONTRACT] Event `developer_platform.widget_site_changed` v1 `{siteId, shopId, change, actorId?}` → new, additive, no required consumer (audit/S28 optional) → keeps S28's catalogue (S28 spec lists no widget mail) unchanged; if S28 later mails "your widget was switched off" it consumes this.
- [CONTRACT] `WidgetSessionService.verify(token, origin?)` (R1) with `WidgetPrincipal` → offered to S10/S13 for checkout calls made by the iframe; **no consumer exists yet**, so S10's spec does not need to change now → a widget session that nobody can verify would be a dead end; reviewers decide when S10 adds widget-authenticated checkout.
- [CONTRACT] Rate-limit policy names `widget.config.ip`, `widget.identify.ip`, `widget.identify.site`, `widget.manage.shop` and their fail modes → S50 registry entries (S50's spec does not exist yet) → fail-open for the public read, fail-closed for token minting and management.
- [CONTRACT] S53 / S52 / S54 facilities asked: a single-use "set if absent with expiry" marker with fail-closed behaviour; cross-instance invalidation and stale-on-error cache; a route-group CORS exemption and per-route headers; startup validation of the widget token key and HTTPS bundle/checkout URLs → S50–S54 specs are not written yet; stated here so they provide them → no per-process site cache is allowed (FR-017).
- [CONTRACT] W07: provides the checkout bundle URL (configuration), the route behind `checkoutUrl`, and the iframe half of the `postMessage` contract (post only to the host page, accept only from it; close, need-identity, identity); keeps the web app's own pages at `frame-ancestors 'none'` → P0502 lists W07 as co-owner of the pattern; the embed document is served by the backend, not the web app.
- [CONTRACT] W04: dashboard screens for sites (create, origins, products, theme, rotate, kill switch, history; secret shown once) → API in Provides.
- [CONTRACT] Packaging: loader source stays in `packages/edge-be` (`widget-loader.ts`, route `/widget/v1/loader.js`); there is no separate edge capability, so this spec owns its behaviour (AS-47–AS-49) → the loader is part of the widget feature in SD-01.

## [LOCAL]

- [LOCAL] Composition (R2) vs domain assembly for `config` → domain assembly with R1/R3 → the runbook says the widget owns a table so it is a domain; keeps one hop on a 50k RPS route.
- [LOCAL] Key format → `pk_live_` + 24 base64url chars (unchanged) → 144 bits; no `pk_test_` keys (sandbox uses a sandbox shop).
- [LOCAL] Identity secret format → `wis_` + 43 base64url chars (256 bits, unchanged); overlap default 24 h, max 72 h, 0 allowed.
- [LOCAL] Hand-off claims → HS256 only; `exp` ≤ 300 s; `nbf` skew 30 s; `iat` skew 60 s; `sub` ≤ 128; `jti` 8–128; `email` ≤ 254 → clock-skew numbers are configuration.
- [LOCAL] Single-use marker TTL → token `exp` + 60 s (today a fixed 600 s) → shorter and exact.
- [LOCAL] Widget token lifetime → 900 s, no refresh endpoint; the iframe asks the shop's page for a new hand-off token → keeps the shop in control of who is logged in.
- [LOCAL] Limits → 10 sites/shop, 10 origins/site, 12 featured products, body 8 KiB, token 4 KiB.
- [LOCAL] Name of the site → optional, default "Storefront widget", 1–60 chars.
- [LOCAL] History kept as long as the site; removed with it → no separate retention.
- [LOCAL] CSP report-only rollout and violation reporting → not in this release.
- [LOCAL] Subresource Integrity for the checkout bundle → not required now; the bundle is same-organisation and versioned.
- [LOCAL] CHIPS partitioned cookies → not built; in-memory token only → notes call it an option; no state needs a cookie; avoids a CSRF surface.
- [LOCAL] Platform-wide widget-version kill → CDN purge / deploy now; S38 flag later.
- [LOCAL] Staleness of shop copy → ≤ 60 s p99, to be restated in `plan.md`.
- [LOCAL] Consumers deployed through `apps/projector` in `WidgetProjectorModule` → R3 rule IX.7.
- [LOCAL] Load test `scripts/load-tests/widget-config.test.js` → ops artifact for SC-007, not a test-plan row.
