# Research: S44 — Embeddable storefront widget

No `NEEDS CLARIFICATION` remained after reading spec.md and questions.md (defaults accepted). The decisions below close the implementation choices the plan relies on; each was checked against the repository on 2026-10-14.

| ID | Question | Decision | Rationale | Alternatives rejected |
|---|---|---|---|---|
| R-01 | Where does the site record live for the hot path? | S52 `CacheService` with `l1: 'never'`, key `widget:site:<publishableKey>`, invalidated on every write through the cross-instance channel; ≤ 30 s memory for unknown well-formed keys, cleared on create | FR-017 forbids per-process copies; S52 follow-up says `l1: 'never'` for site records | keep today's `l1: 'always'` 10 s (serves killed sites); no cache (database on a 50k RPS path) |
| R-02 | Permission `widget.manage` | Request it from S03 (OWNER, ADMIN) as a `[CONTRACT]`. The permission list lives in `tenancy/domain/permissions.ts`; this plan does not edit another domain's spec. If it is absent when the task runs, the task adds the single entry to the tenancy permission table with the S03 test row, and records it under `## Sibling-spec follow-ups` in gaps.md | the route cannot be guarded without it; the entry is additive | reuse `shop.manage` (lets managers mint secrets) |
| R-03 | Per-site CORS vs the global policy | One per-site CORS function in `api/widget-cors.ts`; group exempt from the global CORS through a route-group metadata read by `bootstrap-http.ts`. Existing `SecurityPolicy('public-embed')` sets `ACAO: *`, which is wrong here (registered-origin echo, `Vary: Origin`, no credentials), so a new narrow policy name is needed | FR-013; today's double CORS reflects any origin with credentials | reuse `public-embed` (wildcard, breaks origin binding) |
| R-04 | Site limit race | Per-shop `pg_advisory_xact_lock` + count + insert in one `TransactionRunner.run` | store-enforced (FR-004), no extra table, deterministic under `Promise.all` | unique partial index per slot (schema churn); Redis counter (not store-enforced) |
| R-05 | Optimistic update | `UPDATE … SET version = version + 1 … WHERE id AND "shopId" AND version = :expected RETURNING *`; zero rows → disambiguate not-found vs conflict by a shop-scoped read | FR-005, AS-07 | row lock `SELECT FOR UPDATE` (serialises, no conflict signal) |
| R-06 | Kill switch race | Conditional update on the value; history + outbox only when a row changed | FR-027, AS-40 | unconditional update then diff (double events) |
| R-07 | Hand-off single use | Redis `SET key NX EX (exp-now+60)` through a `SingleUseStore` port; any store error → `503`, nothing consumed; counter metric for fallbacks | FR-019; S53 primitive is not guaranteed to exist, the port keeps the choice swappable | DB unique insert (slower, write on a public path) |
| R-08 | Claims policy | Pure `evaluateHandoffClaims(claims, now)` returning `{ok}` or a closed reason; signature first with `algorithms: ['HS256']`, `clockTolerance` off (policy does the time checks) | G-22/G-23, testable with a frozen clock; one body for all rejections | library `maxAge` (needs `iat`, wall clock) |
| R-09 | Widget token key | Config `widget_token_key` (≥ 32 bytes), required at startup via S54 config validation; HS256 token with `typ: widget+jwt`, `aud: marketplace-widget-session`, `iss: marketplace`, `jti`; one verifier in `jwt-widget-token.ts` | FR-020, AS-33; separate from legacy `jwt_secret` | reuse `jwt_secret` |
| R-10 | Secret overlap | Columns `previousIdentitySecretSealed`, `previousSecretExpiresAt`; decision `now < previousSecretExpiresAt` at use time from the injected clock; overlap 0–72 h default 24; rotation during overlap → `409 rotation_in_progress` | FR-010 same rule as S43 | background expiry job (not needed, decided at use) |
| R-11 | Shop copy | Columns `shopName`, `shopStatus`, `shopVersion` on `WidgetSite`; update `WHERE "shopId" = :id AND "shopVersion" < :v`; status events carry `shopVersion`; seed through `getShopsByIds` before the create transaction; backfill in batches ≤ 500 | R3 rule, D-12, FR-033; `shop-copy.ts` holds the decision table | read tenancy on every request (hot-path coupling) |
| R-12 | Consumers | Three consumers in `infra/widget-consumers.ts` listed in `WidgetProjectorModule.projectors`, same shape as `PublicApiShopLifecycleConsumer` (zod match, `PermanentError` for invalid payloads, inbox by event id, DLQ); registered in `apps/projector` | VII.4, FR-035 | one consumer for three topics (different idempotency) |
| R-13 | CSP assembly | Pure `buildEmbedCsp(nonce)` and `buildFrameAncestors(origins)` in `domain/frame-policy.ts`; nonce 16 random bytes base64url from the injected random source; one script element; bundle URL from `WIDGET_APP_BUNDLE_URL` (default `/widget/v1/app.js`, absolute HTTPS accepted) | FR-025/26, W07 follow-up | host allowlist CSP |
| R-14 | Refusals | Throw domain errors mapped by the S54 problem+json filter; widget routes add `Content-Security-Policy: frame-ancestors 'none'` on every error (route-group filter/interceptor) and `Cache-Control` per FR-029 | FR-024, FR-029 | per-controller `res.status().send()` |
| R-15 | Config shaping and stale copy | Shaped response stored per (key, origin) in S52 with stale-on-error 600 s; product lookup failure serves stale else `503 service_unavailable`; failures never cached as success | FR-016, AS-21 | cache raw product rows |
| R-16 | Rate limits | Four policies in `developerPlatformRatePolicies`; `config` open, rest closed | FR-036 | reuse `auth.login.ip` |
| R-17 | Transactions | `TransactionRunner.run` everywhere; the widget service has no `sequelize.transaction`; `.tx.baseline` must not rise | rule 4 | direct sequelize transaction |
| R-18 | Contract migration (FK) | Separate later migration `ALTER TABLE … DROP CONSTRAINT` with `lock_timeout`; backfill runs before it; reversible by re-adding is not needed (IX.4) | expand/contract | single migration |
| R-19 | Loader | Keep generated-string design; add shape validation, closed message set, 5 s identify deadline, global defined first, referrerpolicy; 5 KiB budget asserted by jsdom spec | G-35…G-38 | rewrite as module bundle |
| R-20 | Living spec | New page `docs/spec/capabilities/S44-storefront-widget.md` modelled on S42 (rules with `[proof:]`, `[code:]`); no `*.reviewed.json` touched | rule 0 | none |
