# Research: S55 — Lambda workers

`questions.md` defaults close every open question. These are the decisions the plan adds after reading the code.

- **D-1 Runner engine location.** Decision: `libs/infrastructure/serverless/runner`, exporting `startRunner(options): Promise<{ stop(): Promise<void> }>` and `redrive(options)`. Rationale: removes `apps/lambda-local → apps/lambdas` (G-01) and lets e2e specs call it with an injected clock. Rejected: keep it in the app and test through a child process (slow, no clock injection).
- **D-2 Runner loads bundles.** Decision: it reads `dist/lambda-bundles/manifest.json` and requires `dist/lambda-bundles/<name>/index.js` (FR-060). Rationale: local run equals deployment. Rejected: ts imports of source (hide bundling mistakes).
- **D-3 Error classes.** `TransientError` and `PermanentError` live in `libs/infrastructure/projections/errors.ts` (S53). Decision: import them from the projections public entry if `pnpm check:boundaries` accepts it; otherwise define them in `serverless/errors.ts` and make `projections/errors.ts` re-export them (the questions.md fallback), so `instanceof` has one class identity. If the fallback is used, add a bullet under `## Sibling-spec follow-ups` for S53.
- **D-4 Dead-letter reason.** S04 is built and its handler uses `'extraction_unavailable'`; the spec's `retries_exhausted` is only a default that yields to S04's enum. Decision: keep `extraction_unavailable`; AS-34 asserts the review state, not the literal. Key: `idempotencyKey('document-extractor-dlq', documentId)` (document IDs are globally unique UUIDs; FR-026's tenant part has nothing to bind to at this layer).
- **D-5 Sibling exports that may not exist yet** (`createMediaProcessor` S29, `WebhooksLambdaModule` / `WebhookDeliveryHandler` S43, S04 error classification). Decision: check each at task time. Where one is missing, the entry file adapts the nearest existing export behind the same wiring shape and the gap is listed under `## Sibling-spec follow-ups` in gaps.md. Never edit their specs or domain code.
- **D-6 Idempotency conditions.** Claim condition: `attribute_not_exists(PK) OR (status = IN_PROGRESS AND leaseUntil < :now) OR expiresAtEpoch < :nowSec`. Completion and release: `ownerToken = :token`. Time comes from the injected clock. Rejected: transactions (single item, no gain).
- **D-7 Completion failure.** Only the work sits inside the failure-release `try`; a failed completion write emits `IdempotencyCompletionFailed`, leaves the claim and rethrows the store error (AS-23).
- **D-8 FIFO scheduling.** Group records by `MessageGroupId` (missing → one shared group); groups share one concurrency semaphore; a group runs in order; after a failure the remaining records of the group are reported failed without running.
- **D-9 Conformance readers.** Plain regex readers for `elasticmq.conf` and the `queues` map and module resources in Terraform (no HCL dependency); messages name file and field (AS-29, AS-37).
- **D-10 Metrics.** Embedded-metric-format lines through an injectable writer; units from the CloudWatch unit list; namespace `Marketplace/Lambda` for toolkit metrics.
- **D-11 Deadline.** `context.getRemainingTimeInMillis()` is checked before each record start; the runner builds a context from the function timeout.
- **D-12 Table ownership (G-07).** The command needed approval in an earlier session. A task runs the package script and records the output; if it cannot run, write that in questions.md, do not claim clean.
- **D-13 Terraform roles.** `for_each` over functions, role `marketplace-<env>-<function>`, policy limited to the function's queue (a dead-letter handler: its DLQ only), the `Idempotency` table, the app secret and KMS key; `extra_policy_json` becomes a per-function map for non-queue rights (S3 for media-processing).
- **D-14 S54 audit.** No touched file opens a transaction directly; `media-processing.ts` loses its inline transaction runner when S29's factory is adopted.
