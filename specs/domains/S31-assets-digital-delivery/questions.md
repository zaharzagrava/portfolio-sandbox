# Open Decisions for S31 (answered unattended)

Format: `[TAG] question → default taken → why`. BREAKING first, then CONTRACT, then LOCAL. The human reviews BREAKING and CONTRACT lines first. Decision policy: most production-grade option the Interview-Prep notes and the constitution support; no external clients to keep compatible, so correctness, security, observability and clean boundaries beat today's behaviour.

## BREAKING (changes behaviour or an API/UI contract that exists today)

- [BREAKING] `GET /assets/shared/:token` increments the download counter and streams the file (`assets.service.ts:185-192`, `assets.controller.ts:92-96`) → `GET` is a stateless preview; `POST /assets/shared/:token/redeem` counts and returns a 120 s download URL; `GET /downloads/:token` streams → constitution V.5 (GET never changes state) and link scanners or prefetch must not burn a capped link; note 04/03 (state-changing actions are not GET).
- [BREAKING] Buyer download token is a JWT signed with the session `jwt_secret`, no `aud`/`iss`, redeemed anonymously without re-checking the purchase (`assets.service.ts:208,212-221`) → opaque 192-bit random grant (digest stored), version-pinned, 600 s, re-checks entitlement and asset on every fetch, so a refund ends access and a leaked URL dies fast → VIII.7-style hygiene (no reuse of the session key), notes 10/08 #25 "download URLs are short-lived signed URLs", SD-25 "per-buyer, expiring".
- [BREAKING] Entitlement is a SQL join over `BisOrder` and `BisOrderItem` with a hard-coded status list (`assets.service.ts:199-206`) → own entitlement store filled from `order.paid` and emptied by `order.refunded` (R3) → IX.4 and IX.7 (domain map: "asset-library consumes order events"), D-7 and D-12; staleness stated in FR-052 (≤ 30 s).
- [BREAKING] A buyer without a purchase gets `403 Not purchased` (`assets.service.ts:207`) → uniform `404 entitlement_not_found` for not bought, revoked, someone else's and unknown → V.4 (existence hidden), anti-enumeration.
- [BREAKING] Commit has no `Idempotency-Key`; a retried commit after a lost response becomes a "conflicted copy" of itself (baseVersion no longer matches) → `Idempotency-Key` required (8–128 chars, 24 h), replay returns the stored `201`; same key different body `422`; in flight `409` → V.6 and P0414 (a replayed create must not duplicate), note 04/03 §1; callers and the old e2e spec must send the header.
- [BREAKING] Commit answers `201 {assetId, path, version, conflicted}` and `400` for chunk and size problems → `201|200 {assetId, path, version, outcome: created|updated|conflicted_copy|unchanged, conflicted, sizeBytes}`; semantic failures are `422` with codes `chunks_unknown`, `chunk_not_uploaded`, `size_mismatch`, `invalid_base_version`; `size` becomes `sizeBytes` → V.4 (422 semantic), III.8 naming (unit in the name).
- [BREAKING] Changes journal: query `cursor` defaults to `0`, any junk becomes `0`; response `{changes, cursor, hasMore}` with numeric cursor; no retention (`assets.service.ts:141-148`, `assets.controller.ts:62-64`) → required opaque `cursor`, response `{items, nextCursor, hasMore}`, listing returns `syncCursor`, `422 invalid_cursor`, `410 cursor_expired`, 90-day retention → III.10 (opaque cursor), notes 10/08 #25 (cursor = last seen change).
- [BREAKING] Manifest returns every chunk URL at once (`{chunks: string[], urls: {hash: url}}`, up to 10,000 presigns per call) and works on deleted assets → paginated `{chunks: [{index, hash, sizeBytes, url}], totalChunks, nextFrom}`, 404 for deleted assets → bounded response size at 50 GiB files, III.4.
- [BREAKING] Deleting the current version tombstones the asset yet leaves older versions, and nothing guards it (`assets.service.ts:125-138`) → current or only version cannot be deleted (`409 cannot_delete_current_version`); new `DELETE /shops/:shopId/assets/:assetId` (soft delete, 30-day undelete, purge), `POST …/undelete`, `POST …/versions/:version/restore`, asset states `ACTIVE → DELETED → PURGED` → III.7 (guarded transitions), notes "version history allows restore".
- [BREAKING] A second conflict on the same device and day silently writes a new version into the first conflicted copy (`ON CONFLICT … DO UPDATE`, `assets.service.ts:107-111`) → numbered copies `(2)`, `(3)`; a conflicted copy never writes into an existing asset → lost-update prevention (P0311).
- [BREAKING] Prepare treats a placeholder row younger than 1 hour as "already stored" without checking storage, so a never-uploaded chunk is skipped by the client and the commit then fails (`assets.service.ts:50`) → stored means confirmed in storage; reused chunks get their grace restarted so cleanup cannot race them → correctness of delta sync, notes "deleting chunks still referenced by old versions" pitfall.
- [BREAKING] Commit calls storage `HEAD` while holding row locks inside the transaction (`assets.service.ts:79-88`) → existence is checked before the transaction and re-validated inside against chunks protected from cleanup → III.3 (no network I/O inside a transaction).
- [BREAKING] Limits: prepare ≤ 10,000 chunks, commit ≤ 10,000 chunks (a 50 GiB file at 4 MiB average needs ~12,800) → prepare ≤ 5,000 (client batches), commit ≤ 15,000, file ≤ 50 GiB, version ≤ 500 per asset → notes 08 design 25 ("files up to 50 GB") and SD-25 ("3D models up to 50 GB") are unreachable at 10,000.
- [BREAKING] Share link create: expiry silently clamped, no `maxDownloads` ceiling, response `{token, url}`, no list or revoke, URL on the API host → `{id, token, url, expiresAt, maxDownloads, createdAt}`, max 10,000 downloads, list and revoke routes, URL on the separate user-content origin (`usercontent_origin`), every unavailable reason `410 link_unavailable` → note 08 design 27 (separate domain, `attachment`, `nosniff`), P0509.
- [BREAKING] `Content-Disposition: attachment; filename="<encodeURIComponent(name)>"` (`assets.controller.ts:35`) mangles non-ASCII names and allows odd characters → ASCII `filename` plus RFC 6266 `filename*`, control characters stripped, plus `Referrer-Policy: no-referrer` (the token is in the URL) → header injection and leak hygiene.
- [BREAKING] `DigitalProduct` and `Asset` have foreign keys to `Product` and `Shop` (`20261002110000-asset-library.js:14,64`) and the link check is a SQL join on `Product` (`assets.service.ts:239`) → drop both foreign keys (expand/contract), check the product by R1 `getProductsByIds([id], {shopId})` → IX.4 (no FK across owners, no cross-domain SQL), D-12.
- [BREAKING] Linking has only `PUT` and nothing stops deleting a sold file → `GET`/`DELETE` link added; unlink refused while entitlements exist (`409 digital_product_sold`); asset delete refused while linked or entitled (`409 asset_in_use`); re-link moves existing entitlements → buyers keep what they paid for.
- [BREAKING] Time comes from SQL `now()` and `new Date()` (`assets.service.ts:50,59,102,178,187,229`) → every time rule reads the platform clock (FR-049) → I.3 and VII.2 (frozen time); old tests that rewrite `unreferencedSince` through SQL change to advancing the clock.
- [BREAKING] The existing e2e spec calls services directly and seeds orders through `BisOrderModel` (`assets.e2e-spec.ts:12-13,132-133`) → rewritten through HTTP with `supertest`, delivering contract-valid events instead of creating orders → VII.2, D-7.
- [BREAKING] Cleanup deletes the row, then the object with errors swallowed (`assets.service.ts:229-232`), orphaning objects → object first, row kept on failure, retried, counted → cost control, P0509 pitfalls.
- [BREAKING] New realtime notification `assets.changed {lastSeq}` after every journaled change → notes 08 design 25 ("change notifications"), P0406 push over poll.
- [BREAKING] Per-shop storage quota (default 100 GiB) with `409 quota_exceeded` (none today) → a storage service without a quota is an unbounded cost and abuse vector.
- [BREAKING] New tables for entitlements, download grants, shop storage usage and the order revocation record; `AssetShareLink` gains `id`, `createdBy`, `createdAt`, `revokedAt`; `Asset` gains `deletedAt` → registered in `db/ownership.ts` and `domain-map.md`, expand/contract migration with `lock_timeout` (III.11).

## CONTRACT (decides something another capability must provide or consume)

- [CONTRACT] S10 lists S31 as a consumer of `OrderQueryService.getOrderLines` (S10 `spec.md` and `gaps.md`) → S31 does not call it; it consumes `order.paid` (`lines[].productId|shopId|title`, `userId`, `orderVersion`) and `order.refunded` only; S10 may drop S31 from the `getOrderLines` consumer list → R3 is what the domain map prescribes and avoids a synchronous dependency on the order service for each download.
- [CONTRACT] Does `order.refunded` mean the whole order? → yes: any `order.refunded` revokes all entitlements of that order (S10's `REFUNDED` is a terminal order state); a partial-refund concept would need a `partial` flag first → simplest safe rule, S10 should keep `order.refunded` for full refunds only.
- [CONTRACT] Late binding of a digital link → no retroactive entitlements for orders paid before the product was linked → keeps S10 and S05 unchanged; a backfill would need an order-lines-by-product read from S10.
- [CONTRACT] S05 → asks for nothing new (`getProductsByIds(ids, {shopId})`, `catalog.product_deleted`); S05 may emit `catalog.product_deleted` before S31's consumer exists: the consumer must tolerate unknown products → idempotent and tolerant by FR-047.
- [CONTRACT] S03 → no new permission: library routes use `products.read` and `products.write` (a `VIEWER` can read the library); share links need `products.write`; asset library purge on `tenancy.shop_deleted`; **no export of the library on offboarding is provided here** (the manifest and journal endpoints already let an owner sync everything out while the shop is `DELETING`) → S05 asked the same question; if tenancy wants a bundle it must say so.
- [CONTRACT] S50 → declare `assets.upload.shop` 120/min per shop (fail closed), `assets.redeem.ip` 60/min per address (fail open), `assets.grant.user` 30/min per user (fail closed) → consistent with S10's policy style.
- [CONTRACT] S51 → topic `shop:<shopId>:assets`, event `assets.changed {lastSeq}`, topic registered by this domain's own topics module (D-3), subscribers must be members with `products.read`; the hub's publish function name is S51's to define → keep S51 free of domain names.
- [CONTRACT] S53 → outbox topic `assets.events` with `assets.entitlement_granted|entitlement_revoked|digital_product_linked|digital_product_unlinked`, schemas `assetEventSchemas` in `packages/contracts`, key per event as in the spec → needed by S28 (download-ready mail) and future read models.
- [CONTRACT] S28 → may consume `assets.entitlement_granted` for "your download is ready"; the mail must not contain a download URL, the buyer opens "My purchases" → grants are short-lived and bound to a request.
- [CONTRACT] S54 → config key `usercontent_origin` (a separate origin for share and buyer downloads) shared with S29 and S30 if they serve user content; startup validation fails in production when it equals the app origin; request logs must record route templates, not path parameters, for the token routes.
- [CONTRACT] Web owners → no web capability owns the library browser, share dialog, share landing page, "My purchases" or the sync client (W03's order history and W04's dashboard do not name them) → W03 should host "My purchases → Download" and W04 the library and share dialog; until they say so the UI column of `test-plan.md` records journeys as "owner to be named".
- [CONTRACT] `docs/architecture/domain-map.md` lists owned tables and `Depends on` for asset-library → update to the new owned tables, `Depends on: orders (events), catalog (R1 + event), tenancy (events), realtime`, and drop the "replaces the BisOrder reads" wording once done.
- [CONTRACT] S18 (usage entitlements) → may later supply a per-plan quota; until then the default is a constant → no dependency on an unwritten spec.

## LOCAL (internals of this capability)

- [LOCAL] Folder ACLs (notes design 25) → not built; shop roles apply library-wide → no model, no consumer asked.
- [LOCAL] Renames and moves → delete plus create (zero bytes uploaded because chunks exist) → keeps the journal two kinds.
- [LOCAL] Buyer downloads resumable → no; streamed through the app → sync clients use the manifest per chunk.
- [LOCAL] Case sensitivity of paths → case-sensitive, NFC-normalized → predictable on all platforms.
- [LOCAL] Entitlement granularity → per (order, product), quantity ignored → a licence per purchase.
- [LOCAL] Download audit → counter and last time on the entitlement plus metrics, no per-download rows → enough for support, cheap.
- [LOCAL] Share link serves → current version at redeem, pinned in the grant → matches Dropbox "live" links; pin-at-create can be added later.
- [LOCAL] Share grant 120 s, buyer grant 600 s, manifest URLs 600 s, upload permission 900 s → short but enough for large parallel fetches.
- [LOCAL] Version cap 500, undelete window 30 days, journal 90 days, cleanup grace 24 h → constants in configuration with these defaults.
- [LOCAL] Empty files allowed (`chunks: []`) → real libraries contain `.gitkeep` and placeholders.
- [LOCAL] Conflicted-copy name uses the device ID, UTC date, and `(n)` suffix → deterministic, pure, testable.
- [LOCAL] Quota counted as unique chunk bytes held or reserved per shop → matches the cost driver.
- [LOCAL] Mechanism choice for cleanup-versus-commit safety (touch on prepare, object-before-row, chunk generations) → plan decides, behaviour fixed by AS-41..AS-43.
- [LOCAL] No antivirus scan of library files → private workspace; delivery is attachment on a separate origin.
- [LOCAL] No watermarking → hook and `X-Licensed-To` only.
- [LOCAL] The `GET /me/purchases` list shows only active entitlements → revoked ones are hidden, not shown greyed out.
