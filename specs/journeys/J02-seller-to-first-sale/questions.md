## BREAKING

- [BREAKING] How does a new shop's owner become `SELLER`? → identity consumes `tenancy.shop_created` (conditional, idempotent); tenancy no longer runs `UPDATE "User"` nor clears an identity cache key (today `shop.service.ts:46-49`, and the token still says `USER` until a refresh) → IX.4 (a domain never writes another's table), IV.3; accepted window H1 = 3 s; shop routes authorise by membership, never by the global role.
- [BREAKING] Who writes `Shop.verificationStatus` / `payoutsEnabled`? → only tenancy, from `shop.onboarding_submitted | verified | rejected` (today onboarding runs raw `UPDATE "Shop"` at `onboarding-session.service.ts:59` and `verification.service.ts:49`, and nothing consumes the events) → IX.4, S03 AS-71/72, S04; the shop's verified flag becomes eventually consistent (H2, H4).
- [BREAKING] When are paid entitlements granted? → only after the first charge succeeded (today `subscribe()` creates the subscription `ACTIVE` and invalidates the cache before commit, so the plan applies before any money moved: `billing.service.ts:57,69`) → a stale or premature "yes" gives paid features away (S18 spec); a declined first charge must leave the free tier (AS-14).
- [BREAKING] `POST /shops/:shopId/subscription` → requires `Idempotency-Key` (`422 idempotency_key_required`), returns `subscriptionSchema` without `paymentMethodRef`, no client-chosen `trialDays` (today a raw ORM row with the reference, no key, `trialDays` in the body, replay answers `409`) → S17 spec; retried subscribes must be indistinguishable from one.
- [BREAKING] Billing events → `billing.invoice_paid`, `billing.subscription_status_changed {…, from, planCode, subscriptionVersion}`, `billing.subscription_plan_changed {shopId, plan, version}` appended in the state-changing transaction (today only `setStatus` emits a thin status event as a separate statement, `invoice_paid` and `plan_changed` do not exist, and no consumer reads them: `billing.jobs.ts:138-161`) → S17, S18, S03; entitlement invalidation and `Shop.plan` move to consumers.
- [BREAKING] Entitlement invalidation → a consumer of `billing.events` with inbox and version guard (group `entitlements-invalidation`) replaces the direct `invalidate` calls scattered in `billing.service.ts:69,95,111` and `billing.jobs.ts:159` → events are the repair path when a direct call is lost; S18.
- [BREAKING] Product-count limit → enforced at product create through `EntitlementsService.checkLimit` (R1), `409 plan_limit_reached {key, limit}`, fails closed with `503 entitlements_unavailable` (today `maxProducts` is read nowhere: `plan.model.ts:7`, `entitlements.service.ts:9`) → the plan must mean something; S05 spec only said "not enforced here", this journey requires it, so S05 and S18 take the R1 call (S18 already lists S05 as consumer).
- [BREAKING] Product create route and shape → `POST /shops/:shopId/products` returning `productMemberSchema` with `priceMinor`, no `embedding`, `searchVector`, `sellerId` (today `POST /products/shops/:shopId` and `POST /products`, raw model, `price`: `product.controller.ts:61-71`) → S05 spec; one route, one shape.
- [BREAKING] Product events → `catalog.product_created|updated|archived|restored|deleted` with the full snapshot and `productVersion`, through `outbox.append` (today `{productId}` only, no `eventName`, legacy `{payload, extra, error}` Kafka value, `occurredAt` stamped at consume time: `outbox.service.ts:108-124`, `envelope-parser.ts:27-48`) → R3: projectors must not re-read the owner's table (IX.4), version guard needs `productVersion`.
- [BREAKING] Stock changes → every reservation, release and sale goes through `ProductStockService.applyStockDelta`, which appends `catalog.product_updated` in the same transaction (today seven code paths run `UPDATE "Product"` with no event: `checkout.service.ts:148-152`, `order.service.ts:97`, `order.jobs.ts:50,106`, `payment.service.ts:190`, `auction.service.ts:55`, `integration-sync.service.ts:186`) → search `inStock`, cache and low-stock webhooks otherwise never see a sale (AS-25).
- [BREAKING] Search → `GET /products/search` in S32's shape (`searchId`, `items[].shopId`, `total {value, exact}`, `nextCursor`); the projector builds the index from events (today `{total, hits[{id, score, source}], suggestions}`, no `shopId`, projector re-reads `Product` and `Shop`: `product-search.projector.ts:36-40`) → R3, D-12, D-16; the journey asserts `shopId` on a hit.
- [BREAKING] Products of suspended shops → hidden from search by consuming `tenancy.shop_status_changed` (today nothing filters archived or suspended: S32 gap) → AS-22; compensation across tenancy and discovery.
- [BREAKING] Webhook dashboard API → permission `webhooks.manage` (OWNER, ADMIN) instead of `shop.manage`; routes `enable`, `disable`, `GET :id`, `GET :id/events/:eventId`, `POST :id/ping`; `attempts` with `eventId`, `ok`, cursor; cross-shop `404` not `[]`; event types add `product.created` etc.; receiver headers `Marketplace-Delivery-Id`, `-Event-Type`, `-Attempt`, `-Replay` and body `resource_version` (today `webhooks.controller.ts:34-71`, `webhook-events.ts:2`, `signature.ts`) → S43 spec; the journey needs `eventId`-filtered attempts to observe one delivery.

- [BREAKING] Local webhook receiver → `allowedReceiverHosts` (host and port) local-profile setting, validated at startup and refused in production; endpoint URLs must be HTTPS in every profile (today `WEBHOOKS_ALLOW_PRIVATE_HOSTS` env, `@IsUrl({require_tld:false})` accepts `http`, mocked in e2e: `webhook-endpoints.service.ts:36-41`, `webhooks.controller.ts:14`) → black-box journeys cannot mock config; S43, S54 `safeRequest`.
- [BREAKING] Leaderboard routes and shapes → `GET /leaderboards` without revenue and with `slug`/`name` from tenancy events; `GET /shops/:shopId/rank` behind `ShopScoped('shop.read')` with `404 not_ranked` (today `GET /leaderboards/shops/:shopId` anonymous, exposes `revenue`, placeholder name "Unknown shop", unranked shop is `404 No sales`: `leaderboards.controller.ts:23-35`) → S40 spec; a competitor's revenue is not public.
