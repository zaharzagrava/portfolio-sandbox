# Gaps: J03 — Launch day

Every missing or broken hand-off between the domains of this journey, found by reading the code (static reading only; nothing was run) against [`spec.md`](spec.md). This is the implementation agent's to-do list; each row names the domain (capability) that must fix it. Paths are under `packages/backend/` unless marked `ROOT/`. Rows marked **blocker** stop the journey from running at all.

**Inherited, not repeated.** J01's gaps apply unchanged: the relay envelope (J01 G-01: the poller wraps the envelope and `parseEnvelope` turns events into `<aggregate>.legacy`, so every typed consumer skips them), the missing control surface for jobs, consumers and clock (G-30 to G-32), topics created only by auto-create (G-27), the local monolith's composition (G-03), the missing payment-initiation route (G-02) and the `order.paid` payload (G-11), consumers without idempotency proof (G-25), and J01's notification gaps (G-21, G-22: no `shop.order_received`, hard-coded currency). J02's G-11/G-17 (extractor, provider doubles) apply to the `sellerFixture`. The rows below are what J03 adds.

Existing journey tests: none. `test/journeys/` holds only `README.md`; `jest-journeys.json` and `pnpm test:journeys` exist. Existing e2e specs of these domains (`launch-events.e2e-spec.ts`, `auctions.e2e-spec.ts`, `checkout.e2e-spec.ts`, `notifications.e2e-spec.ts`) boot Nest testing modules and call services directly, so none of them sees the relay's real message shape or the SQS/Kafka hand-offs.

Also true in all five domains: **no code uses the injectable `Clock`** (`libs/common/core/clock.ts`; only `catalog-sync` does): time is `Date.now()`, so advancing the stack clock cannot make anything due (row G-01).

## 3. Debt-register rows touching this journey

- **D-7 / D-12** (cross-domain models and SQL): launch-events, live, auctions, flash sales and notifications all appear (G-18, G-24, G-26, G-31). `pnpm check:table-ownership --strict` for the five domains is the gate (AS-40).
- **D-8** (barrels export infrastructure internals): `launch-events`, `auctions`, `orders` barrels export models, services and projectors (G-31).
- **D-11** (orders ↔ payments cycle): the settlement order of an auction and a drop order both rely on payments' order copy, fed by `order.reserved` (G-21); payments must not read orders' tables.
