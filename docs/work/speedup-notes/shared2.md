## Not done, and why

- **c (second half), skip index recreation when the test did not change the index.** I could not prove "unchanged" from the code: tests change the index through the projector, Kafka, reindex jobs, admin endpoints, direct `es` calls, and also through the settings, aliases and synonym set. A wrong guess leaves one test's data in the next test. A safe version would compare several things (only the initial index exists, zero documents, default aliases, synonym set equal to default) and that costs about as many round trips as the recreation itself. Left alone.
- **d, create the Elasticsearch index once per process.** Same reason, plus: `resetSearch` is called by 14 spec files (`catalog/product-boundary`, `search-reindex`, `search-admin`, `search-synonyms`, `search-projection`, autocomplete and others). `search-reindex`, `search-admin` and `search-synonyms` clearly test the index life cycle (alias swap, mapping, synonym push), and for the others I cannot show from the fixture alone that no test changes mappings or aliases. Needs a file-by-file decision by whoever owns those specs.
- **f, other things in shared fixtures.** Looked at the sleeps and waits in `test/utils`, `test/seeds`, `test/fakes` and the `testing` folders: the only fixed waits are short poll steps (10 to 100 ms) or scripted fake delays that tests depend on. The BFF app factory waits for Redis only if it is not ready yet. Nothing safe to change.
