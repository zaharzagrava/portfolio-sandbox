Discussions (discussions, discussions-votes, discussions-comments): the 100 votes (or 50 comments) land on one row group in Scylla at the same instant, and each one is a "check and set" write. Scylla makes them queue behind each other and gives up after its own limit "cas_contention_timeout_in_ms" (1000 ms here, I read it from the running container). Those that give up come back as a server timeout and the app answers 503. It is not the app's own timeout (raising it to 15 s changed nothing) and not a driver limit. The test container runs with one core, so the queue is slow. Needed change OUTSIDE the repo files: in docker-compose.test.yaml add `--cas-contention-timeout-in-ms 10000` (maybe also `--write-request-timeout-in-ms 10000`) to the test_scylla command and restart that container.
