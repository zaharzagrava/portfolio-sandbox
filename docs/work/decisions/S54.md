- **S54.D-02** Should the idempotency-key rules change for the callers that use them today?
  - default: the header is renamed `Idempotency-Replayed`. A key is required on routes marked required (`422` if missing). Storage moves from Redis to the database.   - alternatives: keep `Idempotent-Replayed` and emit both header names for a while; fail open when the store is down, or make keys optional everywhere.
  - if wrong: duplicate charges or orders if retries slip through. A store outage turns every payment-like request into a `503`. Clients that expect the old header or status codes break.
  - source: "Idempotency: header `Idempotent-Replayed` → `Idempotency-Replayed`;" [BREAKING]
  - status: open

- **S54.D-03** Should a Postgres outage take the service out of the load balancer, or should the service stay up and report it?

  - alternatives: keep the database as critical so instances leave rotation when it is down; or promote it with a failure threshold.
  - if wrong: customers see errors from instances that cannot reach data, or every instance is pulled at once and the whole product shows an outage.
  - source: "Readiness fails when Postgres fails: `health.module.ts:31-37`" [BREAKING]

- **S54.D-04** How much should the service shed or delay traffic under overload, and which routes get protected first?

  - if wrong: normal customer requests wait longer under load, or critical flows like payments are shed during a spike.

- **S54.D-05** Should production refuse to start when the CORS allowlist or the trusted-proxy setting is missing?

  - alternatives: start with a loud warning and deny cross-origin requests; or default to no trusted proxies.
  - if wrong: a bad deploy config blocks a release or an outage. The opposite choice leaves a credential-leaking CORS hole and spoofable client IPs.
  - source: "CORS: with no allowlist the app reflects any origin" [BREAKING]

- **S54.D-06** Should the outbound-call safety rules block integrations that work today?

  - if wrong: merchants whose webhooks use port 8443 or large responses stop working. Transactional code that calls out fails immediately.
  - source: "SSRF guard: `https` plus ports `443` and `8443` allowed" [BREAKING]
  - status: open
