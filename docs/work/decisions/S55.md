- **S55.D-02** Should a malformed or invalid message body be dropped as a permanent failure, with nothing logged about its content?
  - default: Invalid bodies never reach business code, are reported failed as permanent, and the body is not written to logs (failures are logged without body).
  - alternatives: Log a redacted or truncated body to help debugging; or park invalid messages in a separate quarantine queue for inspection.
  - if wrong: Too little detail makes support cases about lost webhooks or media hard to diagnose; logging bodies risks putting personal data into logs.
  - source: "Handler signature → handlers receive a task message" [BREAKING]
  - status: open

- **S55.D-03** Should each function get its own access role and should operations get alerts on dead-letter depth and queue age?
  - default: One execution role per function (today one shared role over all queues), plus alarms for dead-letter queue depth and queue age in addition to the existing `Errors` alarm.
  - alternatives: Keep the shared role for now and add only the alarms; or add the alarms with a defined notification target and thresholds you set.
  - if wrong: A shared role means one compromised function can reach every queue; extra alarms can create alert noise or monthly monitoring cost, and without thresholds agreed no one may be paged.
  - source: "Terraform `lambda_sqs_worker` → one execution role per function" [BREAKING]
  - status: open

- **S55.D-04** What should happen when a webhook delivery fails and retries run out, given that ordering within a customer's webhook group is held back?
  - default: A failed message blocks only its own group until the receive limit; later messages in that group are reported failed without running, and `FifoGroupOrderBroken` is emitted on the last attempt.
  - alternatives: Skip the failed message and let later ones in the group go through (out of order); or hold the group until someone intervenes.
  - if wrong: Customers' endpoints receive events late or out of order, or one broken endpoint keeps delaying that customer's other events.
  - source: "FIFO batch processing → groups run concurrently, each group" [BREAKING]
  - status: open
