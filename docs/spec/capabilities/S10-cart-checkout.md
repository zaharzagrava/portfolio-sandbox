# S10 - Cart, checkout, stock reservation and order lifecycle
## Purpose
A buyer fills a cart while signed out or signed in, signs in, and checks out. Checkout turns the cart into one order that holds the stock for 15 minutes and splits into one shop order per seller. The payment provider's signed webhook, never the browser's redirect, marks the order paid. Unpaid holds expire and return the stock. Other capabilities react to the order's events.

## Entry points
- `GET /cart` returns the caller's cart (user cart if signed in, otherwise the guest cart from the signed cookie). It never issues a cookie. [code: packages/backend/libs/domains/orders/api/cart.controller.ts#CartController]
- `PUT /cart/items/:productId` sets a line quantity. The first guest write issues the cart cookie. [code: packages/backend/libs/domains/orders/api/cart.controller.ts#CartController]
- `POST /cart/merge` moves the guest cart into the signed-in user's cart after login and clears the cookie. [code: packages/backend/libs/domains/orders/api/cart.controller.ts#CartController]
- `POST /checkout` creates the order from the cart. It answers `202` with `Location`. Needs a session and an `Idempotency-Key` header. [code: packages/backend/libs/domains/orders/api/checkout.controller.ts#CheckoutController]
- `GET /orders` lists the buyer's orders with keyset pagination. [code: packages/backend/libs/domains/orders/api/orders.controller.ts#OrdersController]
- `GET /orders/:orderId` returns one of the buyer's own orders. [code: packages/backend/libs/domains/orders/api/orders.controller.ts#OrdersController]
- `POST /orders/:orderId/cancel` lets the buyer cancel a `RESERVED` order. [code: packages/backend/libs/domains/orders/api/orders.controller.ts#OrdersController]
- `POST /webhooks/stripe` receives signed payment events. No session. It stores and queues the event, then answers `200`. [code: packages/backend/libs/domains/orders/api/stripe-webhook.controller.ts#StripeWebhookController]
- `GET /shops/:shopId/orders` lists one shop's slice of orders for members with `orders.read`, with keyset pagination and an optional `status`. [code: packages/backend/libs/domains/orders/api/shop-orders.controller.ts#ShopOrdersController]
- Flash sales (scheduling, drop checkout, load, end, reconcile) belong to {{cap:S11}}. Checkout meets them at one seam: the drop lines of a cart are claimed before the order is written, and the claim is committed after it. [code: packages/backend/libs/domains/orders/application/checkout.service.ts#CheckoutService]
- `OrderCommandService.createFixedPriceOrder` is the one command other capabilities send to create an order whose stock they already hold (the auction winner's order, {{cap:S21}}). It is exported with `OrderCommandModule` and `OrderCommandRejectedError`. [code: packages/backend/libs/domains/orders/application/order-command.service.ts#OrderCommandService]
- Topic `payments.events` (`payments.payment_succeeded`, `payments.payment_failed`, `payments.payment_refunded`) is consumed and converges with the webhook. [code: packages/backend/libs/domains/orders/infra/payments-events.consumer.ts#PaymentsEventsConsumer]
- Queue `orders-refund-requested` carries refund commands. [code: packages/backend/libs/domains/orders/infra/refund-command.adapter.ts#REFUND_REQUESTED_QUEUE]
- Events published: `order.reserved`, `order.paid`, `order.cancelled`, `order.refunded`, `order.fulfilment_changed`. [code: packages/backend/libs/domains/orders/application/events/order-events.ts#OrderPaid]
- Jobs: per-order hold expiry, expiry sweeper (every 60 s), `PENDING` recovery (every 30 s), release retry (every 30 s), cart cleanup per order, webhook processing per event, daily purge of stored webhook events (`orders.purge-webhook-inbox`), and the item title backfill (`orders.backfill-item-titles`, every 10 minutes until nothing is left). [code: packages/backend/libs/domains/orders/infra/order.jobs.ts#OrderJobs]

## Rules
- **S10.R-01** A cart belongs to one [identity](../terms/identity-domain.md): a signed-in user or a [guest](../terms/guest-cart.md) with a [signed cookie](../terms/guest-cart-token.md). No route takes a cart ID. [proof: S10 AS-01, S10 AS-02] [code: packages/backend/libs/domains/orders/api/cart.controller.ts#CartController]
- **S10.R-02** A signed-in caller MUST always use the user's cart. [The guest cookie stays unchanged except on merge.](../terms/guest-cart-token.md) [proof: S10 AS-02] [code: packages/backend/libs/domains/orders/api/cart.controller.ts#CartController]
- **S10.R-03** A cookie with a changed signature, no dot, a `user:` prefix, a [foreign secret](../terms/guest-cart-token.md), an empty value or 4096 characters MUST count as "no cart". Only a [freshly issued token](../terms/guest-cart-token.md) verifies. [proof: S10 AS-04, S10 AS-11] [code: packages/backend/libs/domains/orders/domain/guest-cart-token.ts#verifyGuestToken]
- **S10.R-04** `PUT /cart/items/:productId` MUST set the quantity (0 to 20), not add it. Quantity `0` removes the [line](../terms/cart-line.md). A cart holds at most [50 lines](../terms/cart-line-limit.md). [proof: S10 AS-03] [code: packages/contracts/src/orders/cart.ts#CART_LIMITS]
- **S10.R-05** A cart line [expires 30 days after it was last set](../terms/cart-line.md), and an expired line MUST NOT be returned. [proof: S10 AS-09]
- **S10.R-06** [Merge](../terms/cart-merge.md) MUST give each product one line with quantity `min(20, user + guest)` and at most 50 lines. User lines always survive; guest-only lines follow in [`addedAt`](../terms/added-at.md), `productId` order. [`droppedLines`](../terms/dropped-lines.md) counts the guest lines left out. [proof: S10 AS-05, S10 AS-07, S10 AS-12] [code: packages/backend/libs/domains/orders/domain/cart-merge.ts#mergeCarts]
- **S10.R-07** Merge MUST add the guest quantities [exactly once ↗](../sw-external-terms.md#idempotency), however many merges run at the same time. [proof: S10 AS-06]
- **S10.R-08** [`POST /cart/merge`](../terms/cart-merge.md) MUST answer `401` without a [session](../terms/session-lifetime.md) and leave the guest cart unchanged. [proof: S10 AS-08]
- **S10.R-09** Cart writes (`PUT`, merge) are [limited to 120 per minute per identity](../terms/rate-limit.md). The 121st answers [`429 rate_limited`](../terms/rate-limited.md) with [`Retry-After` ↗](../sw-external-terms.md#retry-after). Reads are not limited. {{concept:rate-limit-policy}} [proof: S10 AS-10]
- **S10.R-10** [`POST /checkout`](../terms/post-checkout.md) MUST require a session and an [`Idempotency-Key`](../terms/idempotency-key.md) of 8 to 128 characters. A missing key answers [`422 idempotency_key_required`](../terms/idempotency-key-required.md). {{concept:idempotency-key}} [proof: S10 AS-18, S10 AS-21] [code: packages/backend/libs/domains/orders/api/checkout.controller.ts#CheckoutController]
- **S10.R-11** Checkout MUST read prices, currency and shop from the catalog. A client [`expectedTotalMinor`](../terms/expected-total-minor.md) that differs from the server total answers [`409 price_changed`](../terms/price-changed.md). [proof: S10 AS-14]
- **S10.R-12** [The same key with the same body replays the stored answer](../terms/idempotency-stored-answer.md) with [`Idempotency-Replayed: true`](../terms/idempotency-replayed.md). A duplicate in flight answers [`409 idempotency_in_flight`](../terms/idempotency-in-flight.md) with [`Retry-After: 1` ↗](../sw-external-terms.md#retry-after). The same [key](../terms/idempotency-key.md) with another body answers [`422 idempotency_key_reuse`](../terms/idempotency-key-reuse.md). Keys are per buyer. [proof: S10 AS-15, S10 AS-16, S10 AS-17, S10 AS-18, S10 AS-19]
- **S10.R-13** A failure before an order exists [releases the key](../terms/idempotency-key.md). Once an order exists, the outcome is final for that key. [proof: S10 AS-20]
- **S10.R-14** One order MUST split into one [shop order](../terms/shop-order.md) per distinct shop. Each [subtotal](../terms/shop-subtotal.md) equals the sum of its lines, and the order total equals the sum of the subtotals. [proof: S10 AS-22, S10 AS-25] [code: packages/backend/libs/domains/orders/domain/money-allocation.ts#priceCart]
- **S10.R-15** All money MUST be [integer minor units](../terms/minor-units.md). Line total = unit price × quantity − discount, and MUST be at least 0. Discounts are allocated by the [largest-remainder method ↗](../sw-external-terms.md#largest-remainder-method), [ties by line position](../terms/discount-tie-break.md). [proof: S10 AS-23, S10 AS-25] [code: packages/backend/libs/domains/orders/domain/money-allocation.ts#allocateLargestRemainder]
- **S10.R-16** Checkout is limited to 10 requests per minute per buyer and [fails closed ↗](../sw-external-terms.md#fail-open-fail-closed) when the [limiter store](../terms/rate-limit-counter-store.md) is down. [proof: S10 AS-26]
- **S10.R-17** At most one checkout per buyer runs at a time. A concurrent one with another key answers [`409 checkout_in_progress`](../terms/checkout-in-progress.md). [proof: S10 AS-27]
- **S10.R-18** After checkout, a [cart line](../terms/cart-line.md) is removed only if its quantity still equals the quantity the order took. A failed cleanup does not fail the checkout; [a job retries it](../terms/job-retries.md) up to 5 times. [proof: S10 AS-28, S10 AS-29]
- **S10.R-19** The catalog read has a 1 s timeout and the stock call 2 s. A timeout answers [`503 checkout_unavailable`](../terms/checkout-unavailable.md) with [`Retry-After: 2` ↗](../sw-external-terms.md#retry-after). [proof: S10 AS-30]
- **S10.R-20** Stock MUST change only through the [catalog stock command](../terms/catalog-stock-command.md). [Operations are sorted by ascending product ID](../terms/stock-operation-ordering.md), one per product, with [IDs `orders:<orderId>:reserve:<productId>`](../terms/stock-operation-id.md). {{concept:order-reservation}} [proof: S10 AS-31, S10 AS-35] [code: packages/backend/libs/domains/orders/domain/stock-operations.ts#buildReserveOperations]
- **S10.R-21** [A reservation is all or nothing](../terms/all-or-nothing-reservation.md). If any line is short, no stock is held, the order is [`CANCELLED(out_of_stock)`](../terms/out-of-stock-error.md), and the buyer gets `422 out_of_stock` with [`productIds`](../terms/product-id.md). Stock never goes below 0. [proof: S10 AS-32, S10 AS-33, S10 AS-34]
- **S10.R-22** An unpaid [`RESERVED`](../terms/order-status.md) order MUST be cancelled with reason [`hold_expired`](../terms/hold-expired.md) at [`reservedUntil`](../terms/reserved-until.md) (15 minutes after reservation), by [the expiry job](../terms/hold-expired.md) or by [the sweeper](../terms/pending-order-recovery.md) (at most 200 orders per run). Stock returns once. [proof: S10 AS-36, S10 AS-37]
- **S10.R-23** Cancelling moves [`HELD`](../terms/reservation-status.md) reservations to [`RELEASE_PENDING`](../terms/reservation-status.md) [in the same transaction ↗](../sw-external-terms.md#database-transaction). [A retry job](../terms/job-retries.md) releases failures. [proof: S10 AS-38, S10 AS-40]
- **S10.R-24** An order stuck in [`PENDING`](../terms/order-status.md) for more than 60 s MUST be recovered by [repeating the same stock operations](../terms/stock-operation.md). [proof: S10 AS-39]
- **S10.R-25** The webhook MUST verify [the signature over the raw body ↗](../sw-external-terms.md#webhook-signature) in [constant time ↗](../sw-external-terms.md#constant-time-comparison), accept timestamps within ±300 s, and accept the current and, [during rotation](../terms/signing-key.md), [the previous secret](../terms/webhook-secret.md). [proof: S10 AS-42, S10 AS-52, S10 AS-53] [code: packages/backend/libs/domains/orders/domain/webhook-signature.ts#verifyStripeSignature]
- **S10.R-26** The webhook MUST answer [`200 {received: true}`](../terms/post-webhooks-stripe.md) after [storing and queueing the event ↗](../sw-external-terms.md#transactional-outbox), never after processing. [A duplicate event ID](../terms/event-id.md) answers `200 {received: true, duplicate: true}`. {{concept:outbox-task-queue}} [proof: S10 AS-41, S10 AS-43]
- **S10.R-27** Only a [verified event](../terms/verified-webhook-event.md) whose payment status, amount and currency match the order marks it [`PAID`](../terms/order-status.md). A mismatch stores the event as [`REJECTED`](../terms/rejected-payment-event.md). [proof: S10 AS-41, S10 AS-45]
- **S10.R-28** A processing failure retries with [exponential backoff ↗](../sw-external-terms.md#exponential-backoff) and [jitter](../terms/jitter.md), up to 8 attempts. The event is never lost. [proof: S10 AS-44]
- **S10.R-29** An event without `orderId` or with an unknown one is stored as [`UNMATCHED`](../terms/unmatched-payment-event.md). An unhandled type is stored as [`IGNORED`](../terms/ignored-payment-event.md). [proof: S10 AS-46]
- **S10.R-30** A late failure after `PAID` MUST be ignored. [`payment_failed`](../terms/payment-failed-event.md) cancels a `RESERVED` order. A full [`charge.refunded`](../terms/refund.md) refunds a `PAID` or [`FULFILLING`](../terms/order-status.md) order. {{concept:payment-lifecycle}} [proof: S10 AS-47, S10 AS-48, S10 AS-49]
- **S10.R-31** [The payments consumer](../terms/payments-events-consumer.md) MUST [handle a repeated message once](../terms/consumer-deduplication-mode.md). It converges with the webhook on the same [guarded transitions](../terms/guarded-update.md). [proof: S10 AS-50, S10 AS-51]
- **S10.R-32** The webhook body is capped at 64 KiB (`413`). A [signed body ↗](../sw-external-terms.md#webhook-signature) that is not JSON or lacks `id` and `type` answers [`400 invalid_payload`](../terms/invalid-payload.md). [proof: S10 AS-52] [code: packages/contracts/src/orders/webhook.ts#WEBHOOK_BODY_LIMIT_BYTES]
- **S10.R-33** The order has [8 statuses](../terms/order-status.md) and moves only by the commands [`reserve`](../terms/order-command.md), `markPaid`, `cancel`, `startFulfilment`, `ship`, `deliver`, `refund`. Each move is a [conditional change](../terms/guarded-update.md) with one [history row](../terms/order-status-history.md) and [`version`](../terms/order-version.md) raised by 1. [proof: S10 AS-54, S10 AS-56] [code: packages/backend/libs/domains/orders/domain/order-state.ts#decide]
- **S10.R-34** Fulfilment moves only through [`OrderFulfilmentService.apply`](../terms/order-fulfilment-service.md); each emits [`order.fulfilment_changed`](../terms/order-fulfilment-changed-event.md). [proof: S10 AS-57] [code: packages/backend/libs/domains/orders/application/order-fulfilment.service.ts#OrderFulfilmentService]
- **S10.R-35** The buyer's cancel answers [`409 order_not_cancellable`](../terms/order-not-cancellable.md) with [`currentStatus`](../terms/order-status.md) for `PAID`, `FULFILLING`, `SHIPPED`, `DELIVERED` and `REFUNDED`, and changes nothing. A `CANCELLED` order answers `200` unchanged with [no second event](../terms/order-cancelled-event.md). An unknown or [foreign order](../terms/identical-not-found.md) answers the same [`404 order_not_found`](../terms/order-not-found.md); a malformed id answers `400`; no session answers `401`. [proof: S10 AS-55] [code: packages/backend/libs/domains/orders/application/order-cancellation.service.ts#OrderCancellationService]
- **S10.R-36** `GET /orders/:orderId` returns the buyer's own order with items, [shop orders](../terms/shop-order.md) and [timeline](../terms/order-status-history.md). A shop member or an [admin](../terms/platform-admin.md) who is not the buyer gets the same `404 order_not_found` as for a missing order. No internal field (key, [request hash](../terms/idempotency-key.md), user ID, version, [payment reference](../terms/provider-idempotency-reference.md)) is returned. [proof: S10 AS-58] [code: packages/backend/libs/domains/orders/application/order-query.service.ts#OrderQueryService]
- **S10.R-37** `GET /orders` [pages by keyset on `(createdAt, id)`](../terms/pagination-cursor.md) newest first: default 20, maximum 100. It never lists another buyer's orders or [`CANCELLED(out_of_stock)`](../terms/out-of-stock-error.md) ones. A limit outside 1 to 100, a malformed cursor or another buyer's cursor answers `400`. [proof: S10 AS-59] [code: packages/backend/libs/domains/orders/domain/order-cursor.ts#encodeOrderCursor]
- **S10.R-38** The history query reads only columns of the [covering index ↗](../sw-external-terms.md#covering-index) and [repeats its predicate ↗](../sw-external-terms.md#partial-index-predicate), so over 10,000 orders the plan is an index-only scan without a sort. [proof: S10 AS-60] [code: packages/backend/libs/domains/orders/infra/order.repository.ts#USER_HISTORY_PAGE_SQL]
- **S10.R-39** `GET /shops/:shopId/orders` returns for [every role of the shop](../terms/shop-role.md) only that shop's lines and [subtotal](../terms/shop-subtotal.md). A member of another shop only, or a non-member, gets [`404 shop_not_found`](../terms/shop-not-found.md); no session gets `401`; a shop that is not [`ACTIVE`](../terms/shop-status.md) follows the [S03 status gate](../terms/shop-status-gate.md) (`403` for a suspended shop). A `status` outside `PENDING`, `PAID`, `CANCELLED`, `REFUNDED` or a bad cursor answers `400`. [proof: S10 AS-61] [code: packages/backend/libs/domains/orders/api/shop-orders.controller.ts#ShopOrdersController]
- **S10.R-40** `getOrdersForShop` returns the same page as the route. `getOrderLines` takes at most 500 order IDs, reads them in one statement, leaves unknown IDs out and throws [`TooManyIdsError`](../terms/products-ids-limit.md) for 501. [Neither returns a model](../terms/read-model.md). [proof: S10 AS-62] [code: packages/backend/libs/domains/orders/application/order-query.service.ts#OrderQueryService]
- **S10.R-41** `getPayableOrder(orderId, userId)` returns the amount, currency, [hold end](../terms/reserved-until.md) and [per-shop allocation](../terms/shop-subtotal.md) of the buyer's own [`RESERVED`](../terms/order-status.md) order whose hold has not ended. Otherwise it throws `OrderNotPayableError` ([`order_not_reserved`](../terms/order-not-payable.md) or [`hold_expired`](../terms/hold-expired.md)); a foreign or missing order throws [`OrderNotFoundError`](../terms/order-not-found.md). [proof: S10 AS-63] [code: packages/backend/libs/domains/orders/application/order-query.service.ts#OrderQueryService]
- **S10.R-42** Each applied [transition](../terms/order-command.md) appends exactly one event in the [same transaction ↗](../sw-external-terms.md#database-transaction), with a strictly rising [`orderVersion`](../terms/order-version.md) that matches the [envelope's aggregate version](../terms/aggregate-version.md). If the append fails, the status, history, reservations and events stay unchanged and the buyer's cancel answers [`503 order_unavailable`](../terms/order-unavailable.md) with [`Retry-After` ↗](../sw-external-terms.md#retry-after). [proof: S10 AS-64] [code: packages/backend/libs/domains/orders/application/order-lifecycle.service.ts#OrderLifecycleService]
- **S10.R-43** The realtime push after a commit is [best effort](../terms/best-effort-push.md). When the [hub](../terms/realtime-hub.md) is down the transition and its events still commit, the failure is counted in [`orders_realtime_failed_total`](../terms/orders-realtime-failed-total.md), and `GET /orders/:orderId` shows the new status. [proof: S10 AS-65] [code: packages/backend/libs/domains/orders/infra/realtime.adapter.ts#RealtimeAdapter]
- **S10.R-44** Logs MUST carry the order ID for checkout and webhook results and MUST NOT contain the [webhook body](../terms/post-webhooks-stripe.md), the signature, a secret, a cookie, an authorization header or an [idempotency key](../terms/idempotency-key.md). The metrics [`orders_checkout_total`](../terms/orders-metrics.md), `orders_reservation_expired_total`, `orders_webhook_events_total`, `orders_discount_fallback_total` and `orders_paid_after_cancel_total` have [bounded labels ↗](../sw-external-terms.md#metric-labels). [proof: S10 AS-66]
- **S10.R-45** Every job is [safe to run twice or on two instances at once with one effect ↗](../sw-external-terms.md#idempotency). The [purge](../terms/order-webhook-events-purge.md) removes stored [`stripe` webhook events](../terms/job-source.md) older than 35 days (35 days plus 1 s is removed, exactly 35 days is kept) and no other source. The [backfill](../terms/order-items-backfill.md) gives items without a title the product's title, or `(removed product)` when the product is gone, and sets [`lineTotalMinor`](../terms/minor-units.md) to unit price × quantity in batches of 200. [proof: S10 AS-67] [code: packages/backend/libs/domains/orders/infra/order.jobs.ts#OrderJobs]
- **S10.R-46** The domain exports no model outside its marked [TRANSITIONAL block](../terms/transitional-block.md), holds no association or import into another domain, has no direct [`sequelize.transaction`](../terms/transaction-runner.md), and leaves one [table-ownership finding](../terms/table-ownership.md) (the [S12 export join](../terms/table-ownership.md) on `Product`). [proof: S10 AS-68]
- **S10.R-48** `createFixedPriceOrder` writes one `RESERVED` order at the caller's price (no discount, one line, one shop order) for stock the caller already holds, with an `EXTERNAL` reservation row and an `order.reserved` event, in one transaction. It is idempotent on `(buyer, idempotencyKey)`: a second call answers the stored order with `replayed: true`. An unknown buyer, a shop that is not active and a price that is not a positive integer throw `OrderCommandRejectedError` (permanent); any other failure is transient. Cancelling or expiring such an order emits `order.cancelled` and makes no stock operation. [proof: S21 AS-27, S21 AS-39] [code: packages/backend/libs/domains/orders/application/order-command.service.ts#OrderCommandService]
- **S10.R-47** [`POST /checkout`](../terms/post-checkout.md) accepts an optional [`refCode`](../terms/referral-code.md) of 3 to 64 characters of `[A-Za-z0-9_-]`. A valid code is stored on the order; an absent code leaves it empty, and a malformed one answers [`400 validation_failed`](../terms/validation-failed-error.md) with no order. The code is part of the [request fingerprint](../terms/request-fingerprint.md), so the same key with another code answers [`422 idempotency_key_reuse`](../terms/idempotency-key-reuse.md). [proof: S10 AS-69]

## Behaviors
- **S10.B-01** Given a [guest with no cookie](../terms/guest-cart.md), when [`GET /cart`](../terms/get-cart.md), then `200 {lines: [], droppedLines: 0}` and no [`Set-Cookie` ↗](../sw-external-terms.md#set-cookie); the first `PUT` issues the cookie. [proof: S10 AS-01]
- **S10.B-02** Given a user with a [guest cookie](../terms/guest-cart-token.md), when the user [sets a line](../terms/cart-line.md), then it lands in the user's cart and the guest cart and cookie are untouched. [proof: S10 AS-02]
- **S10.B-03** Given a user cart `{A: 1, B: 19}` and a guest cart `{A: 3, B: 5, C: 2}`, when [merged](../terms/cart-merge.md), then the cart is `{A: 4, B: 20, C: 2}` and the cookie is cleared. [proof: S10 AS-05]
- **S10.B-04** Given a user cart with 40 lines and a [guest cart](../terms/guest-cart.md) with 20 other products, when [merged](../terms/cart-merge.md), then the cart holds 50 lines and [`droppedLines`](../terms/dropped-lines.md) is 10. [proof: S10 AS-07]
- **S10.B-05** Given a cart with A × 2 (shop S1, 1000) and B × 1 (shop S2, 500), when the buyer checks out, then [`202`](../terms/post-checkout.md) returns an order in [`RESERVED`](../terms/order-status.md) with two [shop orders](../terms/shop-order.md) and a [15-minute hold](../terms/all-or-nothing-reservation.md). [proof: S10 AS-13, S10 AS-22]
- **S10.B-06** Given A costs 1200 now and the client sent [`expectedTotalMinor`](../terms/expected-total-minor.md) 2000 for A × 2, when checking out, then [`409 price_changed`](../terms/price-changed.md) returns the current total. [proof: S10 AS-14]
- **S10.B-07** Given a completed checkout, when the [same key](../terms/idempotency-key.md) and body are sent again, then the [stored `202`](../terms/idempotency-stored-answer.md) returns with [`Idempotency-Replayed: true`](../terms/idempotency-replayed.md), even after the order is [`PAID`](../terms/order-status.md). [proof: S10 AS-15]
- **S10.B-08** Given [five identical concurrent requests ↗](../sw-external-terms.md#idempotency), when they run, then one order exists and [stock is deducted once](../terms/stock-delta.md). [proof: S10 AS-17]

## Lifecycles
Statuses: `PENDING`, `RESERVED`, `PAID`, `FULFILLING`, `SHIPPED`, `DELIVERED`, `CANCELLED`, `REFUNDED`. Checkout writes `PENDING` and then moves to `RESERVED`. The webhook or the payments consumer moves to `PAID` or cancels. The expiry job, the sweeper and the buyer cancel. The fulfilment service moves `PAID` onwards. A refund moves `PAID` or `FULFILLING` to `REFUNDED`. Shop orders follow the order (`PENDING`, `PAID`, `CANCELLED`, `REFUNDED`). Reservations pass `REQUESTED`, `HELD`, `CONVERTED`, `RELEASE_PENDING`, `RELEASED`. See [order-status](../models/order-status.md).

## Owns
- Tables: `BisOrder`, `BisOrderItem`, `ShopOrder`, `StockReservation`, and the webhook inbox rows through the S53 inbox service.
- Queue: `orders-refund-requested`.
- Events: `order.reserved`, `order.paid`, `order.cancelled`, `order.refunded`, `order.fulfilment_changed`.
- Rate-limit policies: `orders.cart-write.identity` (120 per minute), `checkout.create` (10 per minute), `orders.webhook.ip` (300 per minute).
- Configuration: cart cookie secret, current and previous webhook secrets, hold length, timeouts, limits and retry counts (validated at startup). [code: packages/backend/libs/common/config/orders-config.ts#OrdersConfig]
- The cart lives only in the cart store (DynamoDB). It never touches the relational database.

## Decisions
- The cart never touches the relational database, so add-to-cart bursts do not load Postgres.
- Prices are read on the server, because client prices are never trusted.
- The order is written and committed first, then stock is reserved, then the order moves to `RESERVED`; no transaction spans the stock call. Recovery repeats the same operation IDs.
- Only the signed webhook marks an order paid; the route acknowledges first and applies later, so a slow check never causes a provider retry.
- Stock operations are sorted by product ID to avoid deadlocks.
- Seller discounts fail safe: a timeout of 250 ms, an error or an invalid answer falls back (no discount).
- Reservations have a source: `CATALOG` (stock held through the catalog) or `FLASH` (units claimed in a flash sale's fast store, see {{cap:S11}}). A drop line's row starts `HELD`; it is released, converted and swept by S11's rules.
- Each transition is a guarded conditional update, so racing triggers apply a move once.

## Known gaps
- The discount fallback (250 ms timeout) appears in the specification; the facts show no test with a fallback scenario, so it is not a rule.
- The rate-limit store failing open for cart writes and the webhook has no test in the list.
- AS-24 is proven for the discount path only. The fail-safe branch is not tied to a test.
- The statement that the transition table allows exactly the listed moves (AS-54) is tested only at unit level.
- The `requestId` and `traceId` on every log line come from the platform logger and are not re-proven in the orders specs (R-44 covers the order ID and the absence of secrets).
- The platform's own inbox purge (`inbox.purge`, 30 days, all sources) still removes `stripe` events at 30 days, five days before the 35 days of R-45. S53 must exclude that source from it.
- `OrderService` (compat for `asset-library` and `payments` specs) still moves orders by its own guarded SQL; auctions no longer use it ({{cap:S21}} creates its orders through `createFixedPriceOrder`), so it leaves the barrel when those two specs convert.
