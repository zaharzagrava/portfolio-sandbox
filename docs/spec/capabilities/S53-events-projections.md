# S53 - Domain events, outbox/CDC → Kafka, idempotent versioned projections, replay, read-your-writes

## Purpose
Domains need to say "this happened" and let other domains react without sharing a table. This capability is the shared event backbone: a typed event contract, a {{concept:outbox-task-queue}} written in the same transaction as the state change, a relay to Kafka, consumers that apply each event once in effect, replay, and read-your-writes. It owns no business data, and every read model it feeds can be rebuilt from the log.

## Entry points
- `append`, `appendStandalone` and `appendTask` on the outbox service: write event or task rows in the caller's transaction (`appendStandalone` needs none). See {{concept:transaction-runner}}.
- Framework-free append: lets non-Nest writers (the Lambda of S29, the Rust gateway of S24) write rows over a plain database connection.
- Outbox relay (poller on every replica, or Debezium CDC): publishes pending rows to `<aggregateType>.events`, and task rows to their queue. [code: infra/debezium/outbox-connector.json]
- Plain event producer: sends one validated envelope to Kafka with no database.
- Projection consumers: one consumer group per consumer, with a dead-letter topic `<consumer>.dlq`.
- Inbox: `claim(source, eventId)` for webhook-style handling, and `recordOnce(consumer, eventId)` inside a transaction.
- Read-your-writes helper: a read route accepts `minVersion` and answers `200`, `202` or `400`.
- Purge jobs for published outbox rows and for terminal inbox rows (single-run jobs, see {{cap:S49}}).
- Operator commands: `pnpm projections:rebuild` [code: packages/backend/scripts/projections/rebuild.ts], `pnpm projections:promote`, `pnpm projections:redrive` [code: packages/backend/scripts/projections/redrive.ts#parseRedriveArgs], `pnpm check:table-ownership --technical-only` [code: packages/backend/scripts/check-table-ownership.ts].
- Event tap (journey control surface, local profile): `GET /api/admin/topics/:topic/messages?type=&key=&limit=` (admin role, `limit` at most 200, default 50) returns `{items: [{eventId, type, key, version, occurredAt, payload}]}` for the newest matching envelopes of a topic, oldest first (`version` is the aggregate version). It is read-only, answers `404` unless `EVENT_TAP=enabled` (refused at startup in production), and skips messages that are not envelopes. [code: packages/backend/libs/domains/identity/api/topics-admin.controller.ts#TopicsAdminController] [code: packages/backend/libs/infrastructure/kafka/topic-tap.service.ts#TopicTapService]
- A queue consumer can be a consumer group of the admin routes: `orders-booking-voucher` is paused by the same Redis flag the Kafka groups use (the SQS consumer checks it before every receive, so messages wait in the queue) and its `lag` is the queue's visible message count. [code: packages/backend/libs/infrastructure/sqs/sqs-task-queue.ts#SqsTaskQueue]
- Consumer admin routes (platform `admin` role and a sensitive session): `GET /api/admin/consumers/:group`, `POST /api/admin/consumers/:group/pause`, `/resume`, `/replay {since}` and `/dlq/redrive {limit?}`. The service lives in `libs/infrastructure/projections`; the HTTP controller is mounted by the identity operator module, because infrastructure may not import the auth guards. [code: packages/backend/libs/infrastructure/projections/consumer-admin.service.ts#ConsumerAdminService] [code: packages/backend/libs/domains/identity/api/consumers-admin.controller.ts#ConsumersAdminController]
- Task queue `enqueue`, `enqueueBatch` and `consume`; transactional consume-transform-produce pipeline; `ConsumerLag.read(group)`.

## Rules
- **S53.R-01** Every event MUST be created from a [typed definition](../terms/event-definition.md) whose payload passes its schema; a failing payload throws `InvalidEventPayloadError` naming the first failing path, never the value, and [appends nothing](../terms/outbox-append.md). [proof: S53 AS-04] [code: packages/contracts/src/events/envelope.ts#eventEnvelopeSchema]
- **S53.R-02** An event type MUST be lowercase dotted (`a.b_c`), `(type, version)` MUST be unique, and [`aggregateVersion`](../terms/aggregate-version.md) MUST be an integer from 0 to 2^53−1; otherwise a typed error is thrown and no event is created. [proof: S53 AS-10] [code: packages/contracts/src/events/envelope.ts#EVENT_TYPE_PATTERN]
- **S53.R-03** A [serialized envelope](../terms/event-envelope.md) above 256 KiB MUST be rejected with [`EventTooLargeError`](../terms/event-too-large-error.md), and nothing is appended. [proof: S53 AS-07]
- **S53.R-04** [`append`](../terms/outbox-append.md) MUST write in the caller's transaction and reject with [`NoActiveTransactionError`](../terms/no-active-transaction-error.md) when none is active; a [rollback](../terms/outbox-rollback.md) leaves no [outbox row](../terms/event-row.md). [proof: S53 AS-02, S53 AS-03]
- **S53.R-05** Events appended in one call MUST be written in one statement and [keep their order per aggregate](../terms/per-aggregate-ordering.md) in the log. [proof: S53 AS-05]
- **S53.R-06** An event for an [unregistered aggregate type](../terms/topic-registry.md) MUST throw `UnregisteredAggregateTypeError`; a registered type publishes to [`<aggregateType>.events`](../terms/topic-registry.md). [proof: S53 AS-11]
- **S53.R-07** A [`latest-per-key`](../terms/latest-per-key-topic.md) topic MUST be refused at startup with [`TopicPolicyError`](../terms/topic-policy-error.md) if any of its event definitions does not carry [full aggregate state](../terms/aggregate-id.md). [proof: S53 AS-12]
- **S53.R-08** No domain code MAY access the [outbox or inbox tables](../terms/inbox-table.md) except through this capability's exported services; a CI check enforces this. [proof: S53 AS-09] [code: packages/backend/scripts/check-table-ownership.ts]
- **S53.R-09** [The relay](../terms/outbox-relay.md) MUST publish the envelope JSON unwrapped, keyed by [`aggregateId`](../terms/aggregate-id.md), with headers [`eventId`](../terms/event-id.md), `type`, `version`, [`traceparent` ↗](../sw-external-terms.md#traceparent); the poller and [CDC ↗](../sw-external-terms.md#change-data-capture) MUST produce identical messages. [proof: S53 AS-13, S53 AS-21]
- **S53.R-10** The relay MUST [claim rows with a 30 s lease](../terms/job-lease.md), so that two relays never publish the same row while the lease holds. [proof: S53 AS-16, S53 AS-20]
- **S53.R-11** [Publication MUST be at least once](../terms/at-least-once-delivery.md): a crash between send and mark yields a duplicate with the same [`eventId`](../terms/event-id.md), never a loss. [proof: S53 AS-15]
- **S53.R-12** [A failed row](../terms/event-row.md) MUST be retried with [full-jitter backoff ↗](../sw-external-terms.md#exponential-backoff) (base 1 s, cap 60 s) and MUST [hold back later rows of the same aggregate](../terms/per-aggregate-ordering.md). [proof: S53 AS-14, S53 AS-17]
- **S53.R-13** A row MUST be [parked](../terms/parked-row.md) after 10 failed attempts, or at once for a [non-retryable broker error](../terms/non-retryable-broker-error.md); a parked row no longer blocks its aggregate. [proof: S53 AS-18, S53 AS-19]
- **S53.R-14** An invalid [relay mode](../terms/outbox-relay.md) MUST fail startup, and in [`poller` mode](../terms/relay-poller-mode.md) exactly one poller MUST run per process. [proof: S53 AS-23]
- **S53.R-15** The [purge job](../terms/outbox-purge-job.md) MUST delete only [published rows](../terms/event-row.md) older than 7 days, in batches of at most 1,000. [proof: S53 AS-24]
- **S53.R-16** The [shipped connector configuration](../terms/outbox-connector-configuration.md) MUST include only the [outbox table](../terms/inbox-table.md), route by the row's topic and key by [aggregate ID](../terms/aggregate-id.md). [proof: S53 AS-22] [code: infra/debezium/outbox-connector.json]
- **S53.R-17** A consumer MUST declare [`inbox`](../terms/consumer-deduplication-mode.md), [`versionGuard`](../terms/version-guard.md) or [`natural`](../terms/natural-idempotency.md), and [group names](../terms/consumer-group.md) MUST be unique; otherwise startup fails with [`ConsumerDeclarationError`](../terms/consumer-declaration-error.md). [proof: S53 AS-43]
- **S53.R-18** A `versionGuard` consumer MUST apply an event only when its [`aggregateVersion`](../terms/aggregate-version.md) is higher than the stored one; equal counts [`duplicate`](../terms/consumer-outcomes.md), lower counts [`stale`](../terms/consumer-outcomes.md). [proof: S53 AS-29, S53 AS-33, S53 AS-34, S53 AS-71]
- **S53.R-19** [The inbox](../terms/inbox-table.md) MUST record `(consumer, eventId)` in [the effect's transaction](../terms/consumer-effects.md), so [concurrent duplicates](../terms/consumer-outcomes.md) yield one effect. [proof: S53 AS-28, S53 AS-31, S53 AS-32, S53 AS-49]
- **S53.R-20** [Offsets MUST be committed ↗](../sw-external-terms.md#kafka-offset-commit) only after the effects, so a disconnect causes [redelivery](../terms/at-least-once-delivery.md) and never loss. [proof: S53 AS-36, S53 AS-37]
- **S53.R-21** A consumer group MUST be addressable by its canonical name (`payments-order-copy`, `orders-payment-results`, `ledger-settlement`, `ledger-balances`, `statements-facts`, `notification-router`, and for the seller journey `identity-seller-promotion`, `tenancy-shop-lifecycle`, `entitlements-invalidation`, `search-product-index`, `webhook-router`, `leaderboards`, `product-cache-invalidator`, and for the catalog-sync journey `integrations-stock-push`, `offline-sync-feed`, `pickup-availability`, and for the engagement loop `community-feed-products`, `community-feed-discussions`, `community-feed-fanout`, `marketing-link-clicks`, `marketing-affiliate-conversions`, `discovery-order-baskets`, `discovery-trending-topk`, `experimentation-purchases`) or by the name it declared; `integrations-stock-push` stands for the product-event and shop-lifecycle groups of catalog-sync, `offline-sync-feed` for its change-feed group and `pickup-availability` for the four `pickup-index-*` groups of fulfilment; the canonical `statements-facts` stands for the three `statements-*` groups, `notification-router` for the `notifications-*` groups, `tenancy-shop-lifecycle` for the verification and shop-plan groups of tenancy, `search-product-index` for the product-index and shop-state groups of discovery and `leaderboards` for the three seller-insights groups, `community-feed-products`, `community-feed-discussions` and `community-feed-fanout` for the real groups `feed-products`, `feed-posts` and `feed-fanout`, `marketing-link-clicks` for `link-clicks` and `experimentation-purchases` for `analytics-purchases`, and an unknown name answers `404 consumer_not_found`. [proof: J01 G-31, S53 G-36, J04 G-11, J05 AS-35] [code: packages/backend/libs/infrastructure/projections/consumer-groups.ts#CANONICAL_CONSUMER_GROUPS]
- **S53.R-22** A pause MUST be one Redis flag `consumer:pause:<group>` that every process running the group reads; each runner MUST stop fetching within 2 s of the flag appearing and resume within 2 s of its removal; pausing a paused group, or resuming a running one, changes nothing and answers `200`. [proof: J01 G-31] [code: packages/backend/libs/infrastructure/projections/consumer-pause.ts#ConsumerPauseFlags]
- **S53.R-23** A replay MUST answer `202`, refuse a `since` that is malformed or in the future with `422`, pause the group, move each partition to the offset of the first message at or after `since`, and then resume it. [proof: J01 G-31]
- **S53.R-24** A consumer view MUST report `state`, `lag` (the sum over partitions of end offset minus committed offset), `lastProcessedAt` and `dlqDepth` (dead letters not yet redriven); the gauge `consumer_dlq_depth{group}` carries the depth and the alert `ConsumerDlqNotEmpty` fires on it. `POST .../dlq/redrive` re-queues dead letters to their source topic and answers `202 {requeued}`. [proof: J01 G-26] [code: infra/observability/prometheus/rules/causes.yml]

## Behaviors
- **S53.B-01** Given [aggregate A](../terms/aggregate-id.md) at [version 3](../terms/aggregate-version.md), when a transaction updates it to version 4 and [appends](../terms/outbox-append.md) [`fixtures.item_changed`](../terms/event-definition.md) and commits, then exactly one [pending outbox row](../terms/event-row.md) exists. [proof: S53 AS-01]
- **S53.B-02** Given two [concurrent transactions ↗](../sw-external-terms.md#database-transaction) both updating A from 3 to 4, when both commit, then one fails with the aggregate's [conflict error](../terms/conflict-error.md) and only one [outbox row](../terms/event-row.md) remains. [proof: S53 AS-06]
- **S53.B-03** Given a writer with only a database connection, when it appends through the [framework-free append](../terms/append-standalone.md), then the [relay](../terms/outbox-relay.md) publishes the row like any other. [proof: S53 AS-08]
- **S53.B-04** Given the [broker](../terms/event-backbone.md) is unreachable, when the relay [drains](../terms/outbox-relay.md), then rows stay unpublished with [`attempts`](../terms/job-attempt.md) 1 and a future [`nextAttemptAt`](../terms/job-retry-delay.md); they publish after the broker returns. [proof: S53 AS-14]
- **S53.B-05** Given A1 fails to publish, when the relay drains, then [A2 and A3 wait while B1 publishes](../terms/per-aggregate-ordering.md); [the log ↗](../sw-external-terms.md#kafka-topic) later shows A1, A2, A3 in order. [proof: S53 AS-17]
- **S53.B-06** Given [two relays](../terms/outbox-relay.md) and 100 pending rows, when both [drain at once](../terms/skipped-locked.md), then the log holds exactly 100 messages. [proof: S53 AS-16]
- **S53.B-07** Given events with versions 3, 1, 2, when the [consumer](../terms/event-consumer.md) processes them, then the [read model ↗](../sw-external-terms.md#projection) holds version 3 and the [checkpoint](../terms/checkpoint-lookup.md) is 3. [proof: S53 AS-33]
- **S53.B-08** Given a deleted document at version 5, when an [upsert ↗](../sw-external-terms.md#upsert) at version 4 arrives, then the document [stays deleted](../terms/soft-delete.md). [proof: S53 AS-42]
- **S53.B-09** Given a [batch](../terms/consumer-batch.md) of 5 events whose third fails its schema, when processed, then the third is [dead-lettered ↗](../sw-external-terms.md#dead-letter-queue) with [`SCHEMA_INVALID`](../terms/schema-invalid.md) and the others apply. [proof: S53 AS-51]
- **S53.B-10** Given an event type the consumer does not handle, when it arrives, then it is counted [`ignored`](../terms/consumer-outcomes.md), its [offset is committed ↗](../sw-external-terms.md#kafka-offset-commit) and it is not [dead-lettered ↗](../sw-external-terms.md#dead-letter-queue). [proof: S53 AS-52]
- **S53.B-11** Given an event with a version above the [consumer's highest](../terms/consumer-highest-version.md), when it arrives, then it is [dead-lettered ↗](../sw-external-terms.md#dead-letter-queue) with [`UNSUPPORTED_VERSION`](../terms/unsupported-version.md). [proof: S53 AS-53]
- **S53.B-12** Given a handler that always throws a [permanent error](../terms/permanent-error.md), when [the batch runs](../terms/consumer-batch.md), then the event is attempted 3 times and [dead-lettered ↗](../sw-external-terms.md#dead-letter-queue) with [`HANDLER_FAILED`](../terms/handler-failed.md), and [the offset passes it ↗](../sw-external-terms.md#kafka-offset-commit). [proof: S53 AS-57]
- **S53.B-13** Given [the sink](../terms/event-sink.md) is unreachable for 30 s, when events arrive, then [the partition pauses](../terms/partition-pause.md), nothing is dead-lettered, and all events apply in order afterwards. [proof: S53 AS-59]
- **S53.B-14** Given 4 [dead letters ↗](../sw-external-terms.md#dead-letter-queue), when an [operator](../terms/operator.md) [redrives](../terms/dead-letter-redrive.md), then each returns to its [source topic ↗](../sw-external-terms.md#kafka-topic) with its [original key](../terms/event-key.md). [proof: S53 AS-63]
- **S53.B-15** Given the [read model](../terms/read-model.md) at version 7, when the read route is called with [`minVersion=7`](../terms/min-version.md), then it answers `200` with [`X-Read-Source: read-model`](../terms/x-read-source-header.md). [proof: S53 AS-73]
- **S53.B-16** Given a [projection ↗](../sw-external-terms.md#projection) stopped at version 6, when `minVersion=7` is requested, then [after 500 ms](../terms/read-wait-timeout.md) the route answers `200` from the [write model](../terms/write-model.md) with `X-Read-Source: write-model`. [proof: S53 AS-75]
- **S53.B-17** Given a route [configured for "pending"](../terms/pending-read-mode.md), when the projection is behind, then it answers [`202` ↗](../sw-external-terms.md#http-202-accepted) with [`Retry-After: 1` ↗](../sw-external-terms.md#retry-after). [proof: S53 AS-76]
- **S53.B-18** Given an invalid [`minVersion`](../terms/min-version.md) (`-1`, `1.5`, `abc`), when the route is called, then it answers `400` [problem+json ↗](../sw-external-terms.md#problem-json) without waiting. See {{concept:problem-json-errors}}. [proof: S53 AS-77]
- **S53.B-19** Given [tenant B](../terms/tenant.md) reads an [aggregate](../terms/aggregate-id.md) of tenant A with `minVersion=1`, when the route runs, then it answers `404` [like a missing ID](../terms/identical-not-found.md) and does not consult the [checkpoint](../terms/checkpoint-lookup.md). See {{concept:tenant-shop-rbac}}. [proof: S53 AS-78]
- **S53.B-20** Given an [active span ↗](../sw-external-terms.md#distributed-trace) at [`append`](../terms/outbox-append.md), when the event is [relayed](../terms/outbox-relay.md) and consumed, then the consumer's span has the same [trace ID](../terms/trace-id.md). See {{concept:request-context}}. [proof: S53 AS-27]

## Lifecycles
- Outbox row: pending → published (relay marks it), or pending → parked after 10 failed attempts or one non-retryable error. An operator requeues parked rows.
- Inbox claim: `RECEIVED` → `PROCESSED`, `IGNORED`, `UNMATCHED`, `REJECTED` or `FAILED`. A `FAILED` claim, or a `RECEIVED` claim older than the 5-minute lease, can be claimed again with attempts incremented. [proof: S53 AS-44, S53 AS-45, S53 AS-46, S53 AS-47]

## Owns
- Tables: the outbox table (events and tasks) and the inbox tables (`recordOnce` records and `claim` rows).
- Topics: `<aggregateType>.events` per registered aggregate type (`orders|payments|ledger|payouts|statements.events` are created by `scripts/init-kafka-topics.sh`; the stack doctor fails while one is missing); `<consumer>.dlq` per consumer; the `<consumer>.redrive` group.
- Metrics: `outbox_pending`, `outbox_parked`, `dlq_total`, `dlq_write_failures_total`, `consumer_events_total`, `consumer_dlq_depth{group}`, `read_your_writes_total`.
- Redis keys: `projection:registry` (hash, group to declaration); `consumer:pause:<group>` (string `{pausedAt, by}`, no expiry, deleted by resume); `consumer:replay:<group>` (hash `topic|partition` to target offset, 10 minute expiry, emptied by the runner that owns the partition); `consumer:last-processed:<group>` (ISO time of the last finished batch, 90 day expiry).
- Configuration: relay mode (`poller` or `cdc`), lease (30 s), backoff, retention (7 days outbox, 30 days inbox), read budget (500 ms default, 2,000 ms max), checkpoint expiry (24 h), consumer attempt budget (3), handler timeout (30 s), concurrency cap (500). It validates all of them at startup.
- Code: `infra/debezium/outbox-connector.json`, `packages/contracts/src/events/`.

## Decisions
- The outbox is written in the state change's transaction, so an event exists if and only if the change committed.
- Delivery is at least once, and consumers de-duplicate, so a crash never loses an event.
- Only the outbox table is captured by CDC, and the poller and CDC send identical messages, so the mode is a configuration choice.
- Topics are per aggregate and keyed by `aggregateId`, so events of one aggregate keep their order.
- Read models can be rebuilt from the log; state-carrying events (`carries: state`) allow compaction and coalescing.
- The poller runs on every replica on a local ticker, not as a scheduled job (S49 FR-060).
- No domain touches another's tables; a CI check enforces this.
