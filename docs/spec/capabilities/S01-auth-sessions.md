# S01 - Registration, password login, sessions, refresh-token rotation, JWKS, service-to-service tokens
## Purpose
Buyers, sellers and other backend capabilities need a way to prove who a caller is. S01 registers accounts, checks passwords, and issues short-lived {{concept:access-token-session}} credentials with rotating refresh tokens. It also publishes the public keys that let any service verify those tokens, and it offers user-directory and session-revocation facilities to other domains. It resists account enumeration, brute force and token theft.

## Entry points
- `POST /auth/register` — creates an account; always answers `202 {"status":"accepted"}`. [code: packages/backend/libs/domains/identity/api/auth.controller.ts#AuthController]
- `POST /auth/login` — password login; returns tokens in the body, sets cookies for `delivery: "cookie"`, or returns `{mfaRequired, mfaToken}` when a second factor is enrolled ({{cap:S02}} completes that flow). [code: packages/backend/libs/domains/identity/api/auth.controller.ts#AuthController]
- `POST /auth/refresh` — exchanges a refresh token for a new access token and a new refresh token. [code: packages/backend/libs/domains/identity/application/refresh.service.ts#RefreshService]
- `POST /auth/logout` and `POST /auth/logout-all` — revoke the current session or all sessions of the caller; `logout-all` answers `200 {revokedSessions}` and is a sensitive route. [code: packages/backend/libs/domains/identity/api/auth.controller.ts#AuthController]
- `GET /auth/sessions` and `DELETE /auth/sessions/:sessionId` — list the caller's active sessions; revoke one of them (sensitive). [code: packages/backend/libs/domains/identity/api/sessions.controller.ts#SessionsController]
- `GET /auth/me` — returns the signed-in user.
- `POST /auth/password-reset/request` and `POST /auth/password-reset/confirm` — password reset by single-use token.
- `GET /.well-known/jwks.json` — public key set, served outside the `/api` prefix without credential, with `ETag` and `304`. [code: packages/backend/libs/domains/identity/api/well-known.controller.ts#WellKnownController]
- Scheduled jobs: `auth.rotate-signing-keys` (daily, no run at boot) and `auth.purge-reset-tokens` (daily). [code: packages/backend/libs/domains/identity/infra/keys/key-rotation.jobs.ts#KeyRotationJobs] [code: packages/backend/libs/domains/identity/infra/jobs/reset-token.jobs.ts#ResetTokenJobs]
- Operator routes, ADMIN only, hosted by `core`: `GET /admin/jobs`, `GET /admin/jobs/stats`, `POST /admin/jobs/:id/retry`, `POST /admin/jobs/:id/cancel`, `GET /admin/job-schedules`, `POST /admin/job-schedules/:name/enable` and `POST /admin/job-schedules/:name/disable`. [code: packages/backend/libs/domains/identity/api/jobs-admin.controller.ts#JobsAdminController]
- Administrator job requests, ADMIN only, sensitive session for the write: `POST /admin/jobs` (header `Idempotency-Key`; body `{type, payload?}`; `type` is one of `payouts.run-weekly`, `statements.close-month`, `payments.reconcile-daily`; answers `202 {jobId}`) and `GET /admin/jobs/:jobId` (`{id, type, status, attempts, finishedAt}`). [code: packages/backend/libs/domains/identity/api/jobs-admin.controller.ts#JobsAdminController]
- Exported services for other domains: `UserDirectoryService`, `SessionRevocationService`, `ServiceTokenService`, `SecretBox`; the guard `ServiceAuthGuard` with `@AllowedCallers(...)` protects internal endpoints. [code: packages/backend/libs/domains/identity/application/user-directory.service.ts#UserDirectoryService] [code: packages/backend/libs/domains/identity/api/guards/service-auth.guard.ts#ServiceAuthGuard]
- Events: `identity.user_registered`, `identity.registration_duplicate_attempted`, `identity.password_changed`.

## Rules
- **S01.R-01** Registration MUST answer `[202 ↗](../sw-external-terms.md#http-202-accepted) {"status":"accepted"}` for a new and for an existing address, and MUST create no [session](../terms/session-lifetime.md). [proof: S01 AS-01, S01 AS-02] [code: packages/backend/libs/domains/identity/application/registration.service.ts#RegistrationService]
- **S01.R-02** The system MUST trim and lower-case an address before use; [two simultaneous registrations for one address MUST create exactly one account](../terms/optimistic-concurrency.md). [proof: S01 AS-03] [code: packages/backend/libs/domains/identity/domain/password-policy.ts#normalizeEmail]
- **S01.R-03** Self-selected roles MUST be `USER` (default) or `SELLER`; `ADMIN`, `MODERATOR` and [unknown body fields](../terms/unknown-body-field.md) MUST give [`400 validation_failed`](../terms/validation-failed-error.md). [proof: S01 AS-04] [code: packages/backend/libs/domains/identity/api/auth.dto.ts#RegisterDto]
- **S01.R-04** A password MUST have 12 to 128 characters and MUST NOT equal the address; a [breached password](../terms/breached-password.md) MUST give [`422 weak_password`](../terms/weak-password.md) for new and existing addresses alike. [proof: S01 AS-05, S01 AS-06] [code: packages/backend/libs/domains/identity/domain/password-policy.ts#passwordProblem]
- **S01.R-05** When the [breached-password check](../terms/breached-password-check.md) times out (800 ms) or fails, registration MUST proceed and increase [`auth_breach_check_skipped_total`](../terms/auth-breach-check-skipped-total.md). [proof: S01 AS-07]
- **S01.R-06** Registration MUST compute exactly one [password hash](../terms/password-hash.md) per request, for new and existing addresses. [proof: S01 AS-08]
- **S01.R-07** The 11th registration from one IP within an hour MUST give [`429 rate_limited`](../terms/rate-limited.md) with [`Retry-After` ↗](../sw-external-terms.md#retry-after) and create nothing. [proof: S01 AS-09] [code: packages/backend/libs/domains/identity/domain/auth-rate-policies.ts#identityRatePolicies]
- **S01.R-08** Login with an unknown address or a wrong password MUST give the same [`401 invalid_credentials`](../terms/invalid-credentials.md) with [one password verification](../terms/password-hash.md). [proof: S01 AS-11] [code: packages/backend/libs/domains/identity/domain/errors.ts#Domain_InvalidCredentialsError]
- **S01.R-09** The 6th login for one address within 15 minutes MUST give `429`, even with the right password and for unregistered addresses alike; a successful login resets [the counter](../terms/login-throttle.md). [proof: S01 AS-12, S01 AS-13]
- **S01.R-10** The 21st login request from one IP within a minute MUST give `429`; [forwarding headers](../terms/forwarding-headers.md) MUST NOT change the IP unless the peer is a [trusted proxy](../terms/trusted-proxy.md). [proof: S01 AS-14, S01 AS-15]
- **S01.R-11** A stored [bcrypt ↗](../sw-external-terms.md#bcrypt) or outdated [Argon2id ↗](../sw-external-terms.md#argon2id) hash MUST verify and MUST be replaced by a current Argon2id hash on the next successful login. [proof: S01 AS-16, S01 AS-17] [code: packages/backend/libs/domains/identity/infra/crypto/password-hasher.ts#PasswordHasher]
- **S01.R-12** Hash operations MUST be bounded by a [concurrency limit](../terms/concurrency-limit.md) and a [queue limit](../terms/hash-queue-limit.md); excess requests MUST be rejected with `503` and [`Retry-After: 1` ↗](../sw-external-terms.md#retry-after). [proof: S01 AS-18] [code: packages/backend/libs/domains/identity/domain/bounded-concurrency.ts#BoundedConcurrency]
- **S01.R-13** Every login MUST create a new [session ID](../terms/session-lifetime.md), and a password of more than 128 characters MUST give `400` before any hash computation. [proof: S01 AS-20, S01 AS-21]
- **S01.R-14** A user with an [enrolled second factor](../terms/mfa-enrolment.md) MUST receive a [challenge](../terms/mfa-challenge.md) instead of a session. [proof: S01 AS-19]
- **S01.R-15** The system MUST reject tokens with [`alg: none` ↗](../sw-external-terms.md#jwt-alg), a forged algorithm, an unknown [`kid` ↗](../sw-external-terms.md#jwt-kid), a bad [`typ` ↗](../sw-external-terms.md#jwt-typ), or a time outside the [5 s tolerance](../terms/clock-skew-tolerance.md), with one identical [`401 invalid_token`](../terms/invalid-token-error.md) body. [proof: S01 AS-23, S01 AS-24] [code: packages/backend/libs/domains/identity/domain/token-verifier.ts#verifyAccessToken]
- **S01.R-16** The [principal](../terms/principal.md) MUST come from the token alone; [identity headers](../terms/identity-headers.md) such as `X-User-Id` MUST NOT be trusted, and only [`Authorization: Bearer` ↗](../sw-external-terms.md#authorization-bearer) and the [`__Host-access` cookie](../terms/host-access-cookie.md) MUST carry credentials. [proof: S01 AS-25, S01 AS-26] [code: packages/backend/libs/domains/identity/api/guards/extract-auth-token.ts#extractAuthToken]
- **S01.R-17** A [sensitive route](../terms/sensitive-route.md) MUST reject the token of a [revoked session](../terms/session-revocation.md) at once; an ordinary route MUST accept it until [`exp` ↗](../sw-external-terms.md#jwt-exp) (300 s). [proof: S01 AS-27] [code: packages/backend/libs/domains/identity/api/guards/sensitive-session.guard.ts#SensitiveSessionGuard]
- **S01.R-18** A role change MUST take effect only at the next [refresh](../terms/token-refresh.md). [proof: S01 AS-28]
- **S01.R-19** A [protected route](../terms/protected-route.md) without credential MUST give `401`, and authentication and [throttling](../terms/request-throttle.md) MUST run before body validation. [proof: S01 AS-29, S01 AS-30]
- **S01.R-20** A refresh MUST return a new token for the same session and [spend the old one](../terms/refresh-token-rotation.md); presenting a [spent token](../terms/refresh-token-rotation.md) MUST revoke the session; exactly one of [two simultaneous exchanges ↗](../sw-external-terms.md#race-condition) MUST succeed. [proof: S01 AS-31, S01 AS-32, S01 AS-33] [code: packages/backend/libs/domains/identity/application/refresh.service.ts#RefreshService]
- **S01.R-21** Unknown, expired, revoked and deleted-user [refresh failures](../terms/token-refresh.md) MUST give the same [`401 invalid_refresh_token`](../terms/invalid-refresh-token-error.md); an overlong value (above 256 characters) MUST give `400`. [proof: S01 AS-34, S01 AS-35, S01 AS-37]
- **S01.R-22** A [refresh token](../terms/token-refresh.md) MUST expire 30 days after issue, and a [session](../terms/session-lifetime.md) MUST end 90 days after creation. [proof: S01 AS-35, S01 AS-36] [code: packages/backend/libs/domains/identity/domain/session-policy.ts#refreshExpiry]
- **S01.R-23** The 61st refresh request from one IP within a minute MUST give [`429`](../terms/rate-limited.md) and [MUST NOT consume the token](../terms/refresh-token-rotation.md). [proof: S01 AS-38]
- **S01.R-24** Responses that carry credentials MUST send [`Cache-Control: no-store` ↗](../sw-external-terms.md#cache-control-no-store). [proof: S01 AS-57]
- **S01.R-25** [`GET /auth/sessions`](../terms/get-auth-sessions.md) MUST list only the caller's [active sessions](../terms/session-lifetime.md), newest first, as `{sessionId, device, ip, createdAt, lastUsedAt, current}` and nothing else; another user's session ID MUST answer exactly like an unknown one ([`404 session_not_found`](../terms/session-not-found.md)). [proof: S01 AS-39, S01 AS-40] [code: packages/backend/libs/domains/identity/api/sessions.controller.ts#SessionsController]
- **S01.R-26** [Revoking a session](../terms/session-revocation.md), logging out and [logging out everywhere](../terms/logout-all.md) MUST be [durable](../terms/durable-conditional-write.md) and [idempotent ↗](../sw-external-terms.md#idempotency): logout twice gives `204` twice and keeps the first revocation time and reason; `logout-all` answers `{revokedSessions}` and only touches the caller's sessions. [proof: S01 AS-41, S01 AS-42, S01 AS-43] [code: packages/backend/libs/domains/identity/application/session-revocation.service.ts#SessionRevocationService]
- **S01.R-27** A user MUST have at most 20 [active sessions](../terms/session-lifetime.md); the 21st login revokes the oldest with reason [`session_limit`](../terms/session-limit.md). [`SessionRevocationService.revokeAllForUser`](../terms/session-revocation-service.md) MUST return the number revoked, record the reason and [end the refresh tokens](../terms/token-refresh.md). [proof: S01 AS-44, S01 AS-45] [code: packages/backend/libs/domains/identity/application/session-issuer.service.ts#SessionIssuer]
- **S01.R-28** Login with [`delivery: "cookie"`](../terms/cookie-delivery.md) MUST put no token in the body and set [`__Host-access`](../terms/host-access-cookie.md), [`__Host-refresh`](../terms/host-refresh-cookie.md) ([HttpOnly ↗](../sw-external-terms.md#httponly)) and [`__Host-csrf` ↗](../sw-external-terms.md#csrf-token) (readable), all [`Secure; SameSite=Lax; Path=/` ↗](../sw-external-terms.md#set-cookie) without `Domain`. [proof: S01 AS-46] [code: packages/backend/libs/domains/identity/api/credential-cookies.ts#CredentialCookies]
- **S01.R-29** A [state-changing request](../terms/mutating-route.md) authenticated by the access cookie MUST carry an [`X-CSRF-Token` ↗](../sw-external-terms.md#csrf-token) equal to the `__Host-csrf` cookie and issued for its own session, else [`403 csrf_invalid` ↗](../sw-external-terms.md#csrf-token); a [`Bearer` ↗](../sw-external-terms.md#authorization-bearer) request is exempt. [The token](../terms/csrf-token.md) is a random part plus a [keyed MAC ↗](../sw-external-terms.md#message-authentication-code) over the session ID, [compared in constant time ↗](../sw-external-terms.md#constant-time-comparison). [proof: S01 AS-47, S01 AS-48, S01 AS-49, S01 AS-53] [code: packages/backend/libs/domains/identity/domain/csrf-token.ts#verifyCsrfToken]
- **S01.R-30** Cookie-authenticated state changes and cookie-delivery logins MUST come from an allowed [`Origin` ↗](../sw-external-terms.md#origin-header) (or, without `Origin`, not from [`Sec-Fetch-Site: cross-site` ↗](../sw-external-terms.md#sec-fetch-site)), else [`403 origin_not_allowed`](../terms/origin-not-allowed.md) before anything is created. [Credential endpoints](../terms/credential.md) MUST accept only `application/json` bodies ([`415 unsupported_media_type`](../terms/unsupported-media-type.md)) and `GET` MUST NOT change state. [proof: S01 AS-50, S01 AS-51, S01 AS-52, S01 AS-56] [code: packages/backend/libs/domains/identity/api/guards/cookie-request.ts#assertCookieRequestAllowed]
- **S01.R-31** [Cookie-mode refresh](../terms/token-refresh.md) MUST need no body token, rotate [all three cookies](../terms/host-bff-cookies.md) and return no token; a request refused by the [CSRF check ↗](../sw-external-terms.md#csrf-token) MUST NOT consume the [refresh token](../terms/token-refresh.md). [Cookie-mode logout](../terms/post-bff-session-logout.md) MUST clear all three cookies. [proof: S01 AS-54, S01 AS-55] [code: packages/backend/libs/domains/identity/api/guards/csrf.guard.ts#CsrfGuard]
- **S01.R-32** The [JWKS ↗](../sw-external-terms.md#jwks) MUST list the public parts of every [NEXT, ACTIVE and RETIRED key](../terms/signing-key-states.md) ([ES256 ↗](../sw-external-terms.md#jwt-alg) only, no private member) with [`Cache-Control: public, max-age=300, stale-while-revalidate=3600` ↗](../sw-external-terms.md#cache-control) and an [`ETag` ↗](../sw-external-terms.md#etag) that answers `304`; a [stock verifier](../terms/stock-jwt-verifier.md) configured only from it MUST verify [access tokens](../terms/access-token.md). [proof: S01 AS-58, S01 AS-59] [code: packages/backend/libs/domains/identity/api/well-known.controller.ts#WellKnownController]
- **S01.R-33** Exactly one [ACTIVE signing key](../terms/signing-key-states.md) MUST exist, also when ten first uses [race on an empty store ↗](../sw-external-terms.md#race-condition). [proof: S01 AS-60] [code: packages/backend/libs/domains/identity/infra/keys/key-store.service.ts#KeyStore]
- **S01.R-34** The [rotation job](../terms/key-rotation-job.md) MUST [promote a NEXT key](../terms/signing-key-states.md) once it has been published 24 h and the ACTIVE key is 7 days old, keep a NEXT key available, and [purge a RETIRED key](../terms/signing-key-states.md) 24 h after retirement; tokens of a retired key verify until then. Concurrent and repeated runs MUST leave one ACTIVE and one NEXT key and change nothing on the last run. [proof: S01 AS-61, S01 AS-62, S01 AS-63, S01 AS-64] [code: packages/backend/libs/domains/identity/domain/key-rotation-policy.ts#decideRotation]
- **S01.R-35** An unknown [`kid` ↗](../sw-external-terms.md#jwt-kid) MUST cause at most one [forced reload of the key set](../terms/key-set-forced-reload.md) per 30 s. [proof: S01 AS-65] [code: packages/backend/libs/domains/identity/domain/key-cache-policy.ts#KeyCachePolicy]
- **S01.R-36** A signing key's private part MUST be [stored sealed](../terms/secret-box.md) and bound to its `kid`; [`SecretBox`](../terms/secret-box.md) MUST detect tampering, a [wrong context](../terms/secret-box-context.md) and a wrong [master key](../terms/master-key.md), open values sealed with the previous master key, and refuse to start [in production](../terms/production-configuration.md) without a master key. [proof: S01 AS-66, S01 AS-67] [code: packages/backend/libs/domains/identity/infra/crypto/secret-box.ts#SecretBox]
- **S01.R-37** [`ServiceTokenService.mint`](../terms/service-to-service-token.md) MUST issue [`svc+jwt`](../terms/service-to-service-token.md) ES256 tokens of 60 s (maximum 300 s) with [`sub: svc:<caller>` ↗](../sw-external-terms.md#jwt-sub) and no role, session or address, only for a [configured audience ↗](../sw-external-terms.md#jwt-aud); a minted token MUST be reused until 80 % of its lifetime. [proof: S01 AS-68, S01 AS-71, S01 AS-72] [code: packages/backend/libs/domains/identity/application/service-token.service.ts#ServiceTokenService]
- **S01.R-38** An [internal endpoint](../terms/internal-endpoint.md) guarded by [`ServiceAuthGuard`](../terms/service-auth-guard.md) MUST give `401` for a missing, expired, wrong-audience or user token and [`403 service_caller_not_allowed`](../terms/service-caller-not-allowed.md) for a valid token of a caller outside its [`@AllowedCallers`](../terms/allowed-callers-decorator.md); [`exchange`](../terms/token-refresh.md) MUST turn a live user token into a token that names the user and the caller, and refuse a [revoked session](../terms/session-revocation.md). [proof: S01 AS-69, S01 AS-70] [code: packages/backend/libs/domains/identity/api/guards/service-auth.guard.ts#ServiceAuthGuard]
- **S01.R-39** A [password-reset request](../terms/password-reset.md) MUST answer [`202` ↗](../sw-external-terms.md#http-202-accepted) alike for an existing, a [passwordless](../terms/passwordless-account.md) and an unknown address, send one message only for an existing address with a password, [invalidate older links](../terms/password-reset-link-invalidation.md), and keep the [raw token](../terms/raw-token.md) out of every table, [outbox row](../terms/event-row.md) and log. [proof: S01 AS-73, S01 AS-74] [code: packages/backend/libs/domains/identity/application/password-reset.service.ts#PasswordResetService]
- **S01.R-40** [Confirming a reset](../terms/password-reset.md) MUST replace the password, [revoke every session](../terms/session-revocation.md) with reason [`password_reset`](../terms/session-revocation.md) and record [`identity.password_changed`](../terms/password-changed-event.md); an unknown, spent or expired token MUST give the same [`400 invalid_reset_token`](../terms/invalid-reset-token.md), a weak password `422` that keeps the token, and [two simultaneous confirms MUST have one winner](../terms/optimistic-concurrency.md). [proof: S01 AS-75, S01 AS-76, S01 AS-77] [code: packages/backend/libs/domains/identity/application/password-reset.service.ts#PasswordResetService]
- **S01.R-41** Reset requests MUST be limited to 5 per hour [per IP](../terms/rate-limit-subject.md) and 3 per hour per address (known or not), and confirmations to 10 per hour per IP, with `429` and [`Retry-After` ↗](../sw-external-terms.md#retry-after). [proof: S01 AS-78] [code: packages/backend/libs/domains/identity/domain/auth-rate-policies.ts#identityRatePolicies]
- **S01.R-42** Security events (login failure, session creation, revocation, [refresh reuse](../terms/refresh-token-rotation.md), key rotation, reset request and completion, duplicate registration) MUST each write one [audit line](../terms/audit-log.md) with the [request ID](../terms/request-id.md) and known IDs and never an address, password, token or hash, and MUST be counted in [`auth_events_total`](../terms/auth-events-total.md) with the [bounded labels ↗](../sw-external-terms.md#metric-labels) `endpoint`, `result`, `reason`. [proof: S01 AS-82, S01 AS-83] [code: packages/backend/libs/domains/identity/application/audit.service.ts#AuditService]
- **S01.R-43** Every S01 error MUST be [`application/problem+json` ↗](../sw-external-terms.md#problem-json) with its [stable `code`](../terms/error-code.md) and a [`requestId`](../terms/request-id.md) equal to the response header; an unreadable [signing key](../terms/signing-key.md) MUST give a generic `500` and leave no usable session. [proof: S01 AS-84, S01 AS-85] [code: packages/backend/libs/domains/identity/domain/problem-catalog.ts#identityProblems]
- **S01.R-44** The [operator job routes](../terms/operator.md) MUST answer `401` without a token and `403` for any role but `ADMIN`; they MUST return [job DTOs](../terms/job.md) without payload, map a [tampered cursor](../terms/pagination-cursor.md) to [`400 validation_failed`](../terms/validation-failed-error.md), and [mark mutations sensitive](../terms/sensitive-route.md). [proof: none] [code: packages/backend/libs/domains/identity/api/jobs-admin.controller.ts#JobsAdminController]

- **S01.R-45** `POST /admin/jobs` MUST enqueue only the three allow-listed [job types](../terms/job-type.md) (any other type `422 job_type_not_allowed`), check the payload against the type's [payload contract](../terms/job-payload-contract.md) (`422 invalid_payload`, nothing enqueued), require an [`Idempotency-Key`](../terms/idempotency-key.md) scoped to the calling administrator, and answer `202 {jobId}` for a [job](../terms/job.md) due now. The same key and body MUST return the same `jobId`, a request still [in flight](../terms/idempotency-in-flight.md) `409 idempotency_in_flight`, the same key with another body `422 idempotency_key_reuse`; five concurrent requests with one key MUST leave one job. `GET /admin/jobs/:jobId` MUST answer `404 job_not_found` for an unknown id. Both routes answer `401` without a token and `403` for any role but `ADMIN`. [proof: none] [code: packages/backend/libs/domains/identity/api/jobs-admin.controller.ts#JobsAdminController]

## Behaviors
- **S01.B-01** Given no account, when `" New@Example.COM "` registers with a valid password, then the response is `202` with [no tokens](../terms/access-token.md) and one `USER` account exists as `new@example.com`. [proof: S01 AS-01]
- **S01.B-02** Given an existing account, when a registration repeats the address in another case, then the response is [byte-identical](../terms/identical-registration-response.md) to a new registration and the account is unchanged. [proof: S01 AS-02]
- **S01.B-03** Given two simultaneous registrations of one address, then both get `202` and one account and [one event of each type](../terms/event-row.md) exist. [proof: S01 AS-03]
- **S01.B-04** Given a registration with `role: ADMIN` or `isAdmin: true`, then the response is [`400 validation_failed`](../terms/validation-failed-error.md) naming the field. [proof: S01 AS-04]
- **S01.B-05** Given a [breached password](../terms/breached-password.md), when anyone registers, then the response is [`422 weak_password`](../terms/weak-password.md) and nothing is stored. [proof: S01 AS-06]
- **S01.B-06** Given right credentials and [no cookie delivery](../terms/cookie-delivery.md), when a user logs in, then the response is `200` with [`accessToken.expiresIn`](../terms/access-token.md) 300, [a refresh token](../terms/token-refresh.md), [a session ID](../terms/session-lifetime.md) and the user. [proof: S01 AS-10]
- **S01.B-07** Given 5 failed logins for an address from different IPs, when the 6th arrives with the right password, then the response is [`429`](../terms/rate-limited.md) with [`Retry-After` ↗](../sw-external-terms.md#retry-after). [proof: S01 AS-12]
- **S01.B-08** Given a user with a [bcrypt ↗](../sw-external-terms.md#bcrypt) hash, when they log in with the right password, then login succeeds and the hash becomes [Argon2id ↗](../sw-external-terms.md#argon2id). [proof: S01 AS-16]
- **S01.B-09** Given an enrolled [second factor](../terms/mfa-state.md), when the right password arrives, then the response is [`200 {mfaRequired:true, mfaToken}`](../terms/mfa-challenge-token.md) and [no session exists](../terms/session-lifetime.md). [proof: S01 AS-19]
- **S01.B-10** Given a role changed from `USER` to `ADMIN`, when the user uses [the old token](../terms/access-token.md), then the role is still `USER`; after [a refresh](../terms/token-refresh.md) it is `ADMIN`. [proof: S01 AS-28]

## Lifecycles
No model is listed for this capability. Statuses are not stored in a documented model.
- Session: active, then revoked with a reason (`logout`, `logout_all`, `revoked`, `refresh_token_reuse`, `session_limit`, `password_reset`, `admin_ban`). Users, the refresh service, the session cap and other domains move it.
- Signing key: NEXT, then ACTIVE, then RETIRED, then purged; the rotation job moves it (S01.R-34).

## Decisions
- Registration answers alike for new and existing addresses, and does equal hashing work, so neither the response nor the latency reveals membership.
- Access tokens live 300 s and carry no personal data; revocation is instant only on sensitive routes, which bounds staleness at 300 s.
- Refresh tokens are one-use with no grace period, so a stolen and replayed token revokes the session; clients that refresh in parallel must serialize.
- The breached-password check fails open with a counter, so an outage of the corpus does not block registration.
- Throttle policies are fail-closed, and the per-address counter uses the submitted address whether or not it exists.
- Other domains reach users only through DTO services; identity owns `User`, `FederatedIdentity` and `SigningKey`.
- Errors use {{concept:problem-json-errors}} with stable codes.
- Cookie sessions are opt-in and protected twice: a CSRF token bound to the session, and an origin check; bearer clients carry no ambient credential and need neither.
- Password-reset mail goes straight to the mail channel after commit (a port that notifications binds), not through the outbox, because the raw token must be in no table; a lost mail is recovered by requesting again.
- Key rotation is a pure decision (`decideRotation`) applied until it has nothing left to do, so every run is idempotent and a fresh environment ends with one ACTIVE and one NEXT key.
