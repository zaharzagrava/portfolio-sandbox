Seller dashboard, developer area under /dashboard/seller/{shopId}/developers: api-keys, webhooks (and one endpoint page), api-version, logs and usage. API keys: list shows sk_test_{prefix}… or sk_live_{prefix}… with scopes, status, expiry and last use and NEVER the secret (B-16). "Create key" with a name and default scope shows "Save your API key" once with "Copy" and "Done" (B-17): the secret must live only in that open dialog (R-15), so check it is not in the page source after closing, the address, local or session storage, the console or the query cache; Escape and a click outside must not close it; "Done" before copying asks once; "Copy" turns to "Copied" for 2 seconds; with the clipboard denied the secret is selected with the Ctrl+C hint (R-17). Names: empty, 1, 100 and 300 characters, HTML text, duplicates. A live key without two-step verification: 403 mfa_required, the message "Live keys need two-step verification." with a link, and the form values kept (B-18). Rotate with an overlap (B-19: the old key keeps working until the shown time; test with curl against the public API using both keys), revoke (confirmation dialog, focus on "Cancel" first, a double press sends ONE request, row reads "Revoked", toast "Key revoked", the revoked key now gets 401 from the public API, B-20). Use a key for real: GET the public API with it, check last use updates, scopes are enforced (a read-only key cannot write), the logs page shows the request with filters in the address, a date range limited to the last 30 days, a copyable request id (B-26), and the usage page rows add up to the totals row, labelled UTC (B-27). Webhooks: add an endpoint with a good HTTPS URL, with http, with localhost, a private address 10.0.0.1 or 169.254.169.254, a very long URL, a URL with credentials, javascript:, an unreachable host (the refusal shows under "Endpoint URL", and only endpoint_url_rejected shows the server detail, R-13); the event choices come in the API order; the endpoint card shows the full URL, up to 3 events, version, status badge, breaker state (B-21). Run a small local receiver with node on a free port if the URL rules allow it, send a test event (toast "Test event queued", deliveries refetch for 30 seconds, B-23), check the signature header against the secret, make the receiver fail with 500 and slow, and watch retries and the breaker open; deliveries page newest first, "Failed only" is ok=false in the address, "View event" shows the body as text (B-24); replay a delivery twice quickly: one replay thanks to the Idempotency-Key (R-30); rotate and disable an endpoint. API version page: pin a version, confirm, toast "API version pinned", a deprecated pin warns (B-25). Rate limits: 429 shows a countdown from Retry-After and disables the cause (R-14). As a role without the permission each page shows the forbidden panel and the API says 403 (R-02). Out of scope: the buyer-side API, billing plans.

You may: use the seller screens in the browser (Playwright as a library), call the API with curl as the signed-in seller (read the cookie or token the browser got), register extra accounts, open extra shops, read the database (SELECT only), read the API log, the queue server and the outbox. You may not: edit repository files, change the database by hand, delete other people's data, or report anything the page lists under "Known gaps". Record each finding in the report (REPORT_PATH) in the usual DEFECT block; it is copied to scripts/qa/findings.tsv and, for a seller run, to specs/.checkpoints/qa-seller/findings.tsv by the runner.
