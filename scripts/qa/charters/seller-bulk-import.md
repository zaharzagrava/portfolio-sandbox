Seller dashboard, bulk import of products at /dashboard/seller/{shopId}/imports. Prepare files with node: a good CSV of 30 rows (columns sku, title, price, stock, with a header in mixed case and extra spaces), the same as JSON lines, a CSV with a byte-order mark, a file with semicolons, a CSV with Windows line endings, a 5,000 row file (batches of 500), a file with 3 bad rows among 30 (bad price 1.999, negative stock, empty sku, duplicate sku inside the file, a formula-looking value such as =HYPERLINK(...) in a title), an empty file, a header-only file, a binary or zip renamed .csv, a very large single field (over 1 MiB), and a file over the size limit. Do: choose the file, start (needs products.write and an Idempotency-Key), watch the progress move through the states without the page freezing, see exact counters (created, updated, skipped, failed), download the error report (one line per problem: row, sku, field, code, message; formula guards present so it is safe in a spreadsheet; it is available only for the owner, via a short-lived link). Then check the products really exist: row count in the database equals the counter, prices in minor units are right (12.5 means 1250), the inventory page shows them, a second import of the same file updates instead of duplicating (by sku), an empty stock cell leaves existing stock alone. Odd things: press Start twice; start a 4th import while 3 are running (refused, a clear message); more than 10 starts in an hour (429 with a countdown from Retry-After, R-14); cancel a running import (stops at a batch edge, earlier rows kept); close the tab in the middle and come back (progress is still shown, the job went on); reload on a finished job; resume an interrupted upload (GET …/upload lists stored parts); a stale link to another shop's import id answers the same 404; a VIEWER cannot start. A file name with quotes, slashes, 300 characters or script text is shown as plain text (R-28, S07 R-02). Check the status never shows a storage key, upload handle or scanner name (S07 R-18) and the API log has no row data. Look for stuck states: SCANNING or PROCESSING forever (is the import worker running?), a parked outbox row. Also check the page on 390 px and the import history list. Out of scope: integrations with outside systems, exports.

You may: use the seller screens in the browser (Playwright as a library), call the API with curl as the signed-in seller (read the cookie or token the browser got), register extra accounts, open extra shops, read the database (SELECT only), read the API log, the queue server and the outbox. You may not: edit repository files, change the database by hand, delete other people's data, or report anything the page lists under "Known gaps". Record each finding in the report (REPORT_PATH) in the usual DEFECT block; it is copied to scripts/qa/findings.tsv and, for a seller run, to specs/.checkpoints/qa-seller/findings.tsv by the runner. Write each Playwright script you used into SCRIPTS_DIR with a name like shop-01-double-submit.js so a fixing agent can turn it into a test.
