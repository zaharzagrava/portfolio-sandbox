Seller dashboard, product video at /dashboard/seller/{shopId}/products/{productId}/media/video. Start an upload with a title, a small valid mp4 (make a 3 second clip with ffmpeg if it is installed, else a tiny file from the repo test fixtures), the visibility choice (public or unlisted) and watch: parts upload with progress, "complete" answers 202, the page polls the video until READY, and the video appears in the list with its poster. Check at each step the API (POST start, PUT parts, complete, GET list), the database row status and history, and the media worker log (the video workers must be running; if not, say so first). Try: title empty, 1 and 201 characters; a file under 1 KiB; a .txt renamed .mp4; a type outside mp4, quicktime and webm; a file that is not a decodable video (must end FAILED with a readable reason, and the page must not spin forever); a clip longer than the limit; start 11 uploads without finishing (the 11th is refused, 409 pending_uploads_limit, with a message a person understands); interrupt an upload (go offline or close the tab at part 2), come back, press "Resume upload": only missing parts are sent (B-02); reload during processing and see the state resume; delete a video (soft delete, gone from the list and from the buyer product page at once); retry a FAILED video (at most 3 times); edit the title with a stale version (409 version_conflict). Buyer side: the public player page shows only READY, public videos; an unlisted one needs its share token and answers the same 404 as an unknown id without it (B-04); the original file or storage address never appears in any response (R-17, grep the API answers). As a VIEWER the upload is disabled; another shop's video id answers the same 404. Check the page at 390 px and with the keyboard only. Look for stuck states: UPLOADING forever, PROCESSING forever, a queue message with no worker, a non-empty dead-letter queue. Out of scope: photo uploads, live streams.

You may: use the seller screens in the browser (Playwright as a library), call the API with curl as the signed-in seller (read the cookie or token the browser got), register extra accounts, open extra shops, read the database (SELECT only), read the API log, the queue server and the outbox. You may not: edit repository files, change the database by hand, delete other people's data, or report anything the page lists under "Known gaps". Record each finding in the report (REPORT_PATH) in the usual DEFECT block; it is copied to scripts/qa/findings.tsv and, for a seller run, to specs/.checkpoints/qa-seller/findings.tsv by the runner. Write each Playwright script you used into SCRIPTS_DIR with a name like shop-01-double-submit.js so a fixing agent can turn it into a test.
