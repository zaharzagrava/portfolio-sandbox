Open the event stream as an API client with curl -N on GET /api/streams?topics=<topic>, first anonymous on a public topic, and check the status 200, the text/event-stream and no-cache headers, the retry: value, and the baseline frame with no historical data event. Trigger a real change in the web app that publishes to that topic (or watch a signed-in page that uses the EventSource wrapper) and see each event arrive in order with an id: cursor and one-line JSON in data:. Then connect as a signed-in user to two topics and check that the cursor names both. Reconnect with Last-Event-ID set to an earlier cursor and check that you get only the later events, in order, with no duplicate; reconnect with the latest cursor and expect no replay and no resync. Try to break it: no topics, 11 topics, duplicate topics, an empty or malformed topic, an extra query parameter (expect 400 invalid_topics or invalid_query as problem+json); a garbage Last-Event-ID, one over 2,048 characters, and a very old cursor (expect it ignored or a resync frame with reason replay-gap); another user's user:<id> topic, a made-up topic, and a topic with no credential (expect 401 anonymous, 403 signed in, and the same 403 body for "not yours" and "missing"); an invalid, expired or wrong-audience token on a public topic (expect 401). Open many connections as one user (expect 429 too_many_connections with Retry-After: 5 past 20) and more than 60 in a minute (expect 429 rate_limited). Send odd characters, newlines and long text through a payload that a user can set, such as a chat message, and check that the stream gets no injected field or frame. Reload the browser page and kill and restart curl in the middle of a burst of events, and check that nothing is lost or repeated. Check behind the screen that the rt: replay buffer in the shared store and the number of backplane subscribers per topic match the viewers (one per topic however many viewers), and that a closed connection leaves no subscription. Out of scope: the internal subscribe, define and topicsWithSubscribers calls, and the domain rules for what each event means.
