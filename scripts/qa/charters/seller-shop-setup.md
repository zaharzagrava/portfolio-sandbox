Seller dashboard, shop entry and profile, as a member. Start signed in as seller@marketplace.local (password Demo-Seed-Pw-7491!) and also with a freshly registered buyer who has no shop. Open /dashboard/seller: a member without a shop must see "Open your shop" with "Shop name" and "Handle", and the handle must follow the name until you edit it (W04 B-01). Open the shop with a good name, with an empty name, with 1 and with 200+ characters, with emoji, with a name that is HTML ("<b>x</b>": it must show as text, R-28), with a handle that is taken (409 slug_taken, message under "Handle"), a reserved one (422 slug_reserved, for example admin or api), upper case, spaces, a trailing dash. Press "Open shop" twice fast: exactly one request and one shop row (B-02). Reach the shop limit (409 shop_limit_reached shows an alert above the button). After opening, check that the browser lands on the new overview and that the session shows the seller entries in the menu without a sign-out (the role refresh runs up to 3 times in the background). With two shops, /dashboard/seller must show the picker with name, handle, role and status badge; with exactly one, a redirect (B-04). Use the shop switcher: the current section must stay (R-32); the list holds the first 50 shops. Odd paths: a shop id that is not a UUID, an unknown UUID and another member's shop must give the SAME not-found page and the non-UUID one must not reach the API (R-04; check the API log). Signed out, open any /dashboard/seller URL: redirect to /login?returnTo= with the path and query kept (B-33); after login you must land back there. Suspended and closing shops: ask the database for a shop in SUSPENDED or DELETING (or set one through the admin account) and check the banner text, that every write control is disabled with the banner as its reason and every read still works (R-03). On a 390x844 phone and a 1280 wide desktop: the sidebar becomes a drawer opened by "Open menu", the current page has aria-current="page", nothing scrolls sideways (B-37). Go offline in the browser: the banner "You're offline. Changes can't be saved." shows and clears on reconnect (B-35). Behind the screen: one Shop row and one membership row with role OWNER per opening, an outbox row for the shop event, no 5xx in the API log. Also check the profile data the shop shows to buyers (the public shop page by handle) matches what the seller typed, including after an edit and a reload. Out of scope: KYC document upload, payouts, team.
