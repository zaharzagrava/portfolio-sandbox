# Security track (track 11): real findings

Run 2026-10-25 on the four areas. Tools: Semgrep, gitleaks, pnpm audit, Schemathesis, OWASP ZAP baseline. Per-tool pages with every flag and its verdict: `security-semgrep.md`, `security-gitleaks.md`, `security-audit.md`, `security-schemathesis.md`, `security-zap.md`. How to run again: `scripts/aiqa/tracks/security/run.sh`.

In one sentence: the code itself came out clean (no unguarded seller route, no secret, no script injection, no crash from API fuzzing), but the app ships with outdated packages that have known critical holes, and one already-known privacy leak was found again by our own rule.

## Checked and clean

- Semgrep: 119 ready-made rules found nothing in the four areas' web and backend code. Our four custom rules (`semgrep-rules.yml`) found no seller route under `/shops/:shopId` without the shop guard, no shop id read from a request body, no raw HTML injection. The rules are tested on a bad sample (`security/selftest/`) so a zero means something.
- gitleaks: 19 flags in history and 21 in the working copy (some repeated), all test fixtures, example env values and docs (`security-gitleaks.md`). No real secret.
- Schemathesis: about 10,000 generated requests on the public integration API (products, stock, orders, batch): no 5xx, no missing-auth success, no leak of internals.
- ZAP baseline on the production build: 0 failures, 60 checks passed (no CSP missing, no clickjacking, no cookie flag issues, no server banner); 8 warnings, all false alarms or hardening (XSS probe on the search box was tried by hand and is encoded).

## Not covered (be honest)

- The seller dashboard behind the login was not scanned by ZAP (baseline is anonymous and passive). An authenticated active scan was not run.
- The dashboard routes of the four areas have no API description, so Schemathesis could not fuzz them; the in-house fuzzer (`scripts/qa/fuzz-seller-api.mjs`) and the isolation tests cover them.
- Cross-seller access (seller A reading seller B) is not a scanner job; it is covered by the isolation tests (track 4, `*-isolation.e2e-spec.ts`).
